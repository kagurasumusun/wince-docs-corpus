Hoechst Marion Roussel

Industry:
Pharmaceutical manufacturer

Architecture:
A database application running on Windows® CE-based Handheld PCs that collects information from the field and synchronizes it with laptop or PC computers, which in turn synchronize with the Microsoft SQL ServerTM database at headquarters.

Products Used:
Microsoft Windows CE-based Handheld PC
Microsoft Windows NT® Workstation
Microsoft Visual C++® for Windows CE

Taking advantage of existing Win32® expertise, developers from Solution Provider Empower Trainers and Consultants, Inc., and Microsoft Consulting Services (MCS) were able to quickly customize an application for the Microsoft® Windows CE-based Handheld PC, providing sales representatives for international pharmaceutical manufacturer Hoechst Marion Roussel (HMR) with more efficient sales tools. The resulting application meets the company's need for speed and flexibility in gathering physicians' signatures for sample distribution, provides representatives with instant access to up-to-date customer information, and is projected to save approximately U.S.$5 million annually for the company.

Hoechst Marion Roussel (HMR), an international pharmaceutical manufacturer with North American headquarters in Kansas City, Missouri, has more than 1, 500 sales representatives who call on an average of 8 to 10 physicians every day. Because physicians have very little time to spare, HMR representatives estimate that they have anywhere from 45 seconds to 10 minutes with a physician to present their products and leave samples.

Since the late 1980s the Food and Drug Administration has required every prescription drug sample distributed to be accounted for with a physician's signature. To streamline this process HMR, which ships several semitrailers full of samples quarterly, developed an automated system for managing the distribution of prescription drug samples. That system evolved into a software application -- called Technology Information Management (TIM) -- that until recently had run on a pen-based laptop computer used to capture the required signatures. This application also collected data on the medications physicians are prescribing and provided reps with up-to-date physician profile information. While this system worked with HMR's Microsoft Windows environment, the laptop computer was still awkward to carry, came on slowly, and offered limited battery life.

In searching for ways to speed up the process, the HMR IS staff decided that Windows CE-based Handheld PCs offer several advantages. The H/PC's pocket size lightens the representative's load. Also, the H/PC boots up instantly, making it easy to quickly get physicians' signatures for distributed samples. What's more, its synchronization functionality enables representatives to upload those signatures and key market information to a laptop or PC and to download market share and physician profile information in about 10 minutes with the touch of a button.

Because the H/PC runs up to two weeks on two AA batteries, there is little danger of it running out of power in the middle of the day. HMR expects this combination of benefits to save up to U.S.$5 million annually by improving efficiency and thus increasing volume.

The Windows CE operating system offers a number of benefits from a developer' s perspective as well. Because it is based on the familiar Win32 API and its development tools are extensions to the standard Win32 tools, it presents a very short learning curve. And its enormous flexibility allowed the developers to meet some very specific requirements for speed, screen customization, and functionality.

A team effort
Using the existing TIM application as a guide, HMR established a basic design for a nearly identical application for the H/PC. To help refine the design and code the new application -- dubbed TIM Jr.-- HMR contacted Microsoft Consulting Services (MCS) and Empower Trainers and Consultants of Overland Park, Kansas. With more than 200 Microsoft certifications, Empower is the largest Microsoft Solution Provider Partner in the Midwest. In addition to technical and end-user training, it offers consulting services in custom application/Internet development, systems architecture and integration, and supplemental technical staffing.

Using the Microsoft Visual C++ development system for Windows CE, two developers, one from Empower and one from MCS, worked side by side for about four weeks, developing both the TIM Jr. application for the H/PC and the DLL that synchronizes the data with the laptop or PC.

"Windows CE is very close to the normal Win32 development platform, so it was a pretty small learning curve," observes Empower developer Jamie Hohman.

As each piece of the application was coded, developers would e-mail the executable files to Kevin Greenlee, HMR's Manager of Applications. He and a team of five testers would review the files and send back comments on bugs they found or improvements they'd like to see. The entire process took approximately three months to reach the pilot stage.

Creating a truly usable user interface
One of the key requirements of the TIM Jr. application was easy, quick operation. The unpredictability of a physician's day makes it critical for HMR salespeople to present their facts quickly.

The Handheld PC lets representatives download customer-specific information quickly and easily from headquarters, so they can target their sales presentations to directly meet the physicians' needs.

In addition, HMR had some very specific requirements for the purpose of maximizing the reps' efficiency while ensuring that all the i's were dotted and t's crossed. First, the user interface needed to be sequential so that it would show and hide functions conditionally based on where the user was in the data-gathering process. This was easily achieved by using standard Microsoft Windows tabbed dialog boxes. Individual tabs were enabled or disabled depending on what the user was doing and what information had been entered.

Second, the developers needed to be able to customize the screen with added graphical elements such as horizontal lines and functionality such as modified edit boxes to make it easier for users to enter information. Because Windows CE supports a subset of the Win32 API, developers were able to write these features into the application.

"That's one of the unique features of this HMR application," explains MCS developer Dave Anderson. "In just about every screen, the user interface default drawing and display behavior has been overridden." Another -- and perhaps the most challenging -- requirement requested by HMR was to turn the signature screen upside down.

"The rep records the samples on the sample request screen, fills out the quantities for the sample product, and then hits the button to bring up the signature screen," explains Greenlee. "We wanted to invert that screen to make it right side up when the H/PC is handed over to the physician. That way, the physician doesn't have to rest his or her hand on the keyboard and hit keys."

Developers had to improvise to achieve the inverted screen. They made bitmaps of the text on the signature screen and then inverted the bitmap. "This shows how well Windows CE lends itself to customization," notes Hohman.

Reducing synchronization time by 75 percent
The other critical piece of the solution, beyond the application itself, is the synchronization DLL that enables users to sync up data on their H/PCs with their laptops or PCs and ultimately with the database at headquarters.

The Windows CE-based H/PC already includes a synchronization DLL to automatically synchronize e-mail, contact lists, and schedules between the H/ PC and the laptop or desktop PC. However, because the TIM Jr. application required some special DLL functions for downloading several thousand rows of data on physician profiles, market share data, and sample information, developers decided to write their own DLL. The flexibility of the Windows CE platform made it easy to meet HMR's specific needs.

The developers first added a piece of communications to the synchronization DLL that moves the information as a text file to the H/PC in just a few seconds. Then another small application can be started remotely that reads the text file, parses the records, and assembles them into a database. HMR reps can download approximately 15,000 rows of data to the H/PC, send approximately 20 to 50 records back to the laptop computer, and connect the laptop and load data to the host database at the HMR office, all in just 10 minutes.

In fact the TIM Jr. application, written in C, runs faster than the original application running on Pentium laptop computers.

High-speed emulation
Another tool that helped speed development process was the desktop emulation software that supports developing Windows CE-based applications using the existing Win32 compiler on any x86 computer running the Windows NT Workstation operating system.

The emulator creates in the upper-left portion of the computer screen a little window that is exactly the size of the Windows CE display. "It supports the Windows CE database, file system, and all interface components," explains Anderson. "You can do 90 to 95 percent of all your development there."

"Running emulation on Windows NT makes development a lot faster, and when you put the application back on the H/PC, it's extremely accurate," adds Hohman.

A pilot of the application was rolled out to approximately 60 HMR representatives in the middle of August 1997. The full rollout is scheduled for late 1997 or early 1998.
