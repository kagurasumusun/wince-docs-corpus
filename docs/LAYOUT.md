# Layout rules

The tree is organised by **role first, then source, then product**. A path tells you what a file *is*.

```
corpus/                 harvested / vendored content (never hand-edited)
  learn/<product>/<id>.html
  wayback/<host>-<yyyy>-<mm>/<id>.html
  chm-extracted/<product>/<name>.html
  archives/<product>/<original media> + PROVENANCE.md
meta/                   descriptive + derived data
  catalogs/  rows/  manifests/  gaps/  index/  harvest/
queues/
  sources/              URL lists that define scope (committed)
  pending/              generated by `discover.py pending`, git-ignored
sources/                sources.json (scope definition), reference-links.txt
tools/                  all code, flat modules sharing common.py
docs/                   documentation
.github/workflows/      harvest, discover, index, ci
```

Rules (checked by `tools/verify_layout.py`):

1. Only the top-level entries above exist.
2. `corpus/<kind>/` with `kind ∈ {learn, wayback, chm-extracted, archives}`; one extra level = product or capture month.
3. Product directory names are lowercase, `-` separated, version with `.` or `x` (`windows-ce-5.0`, `windows-ce-net-4x`). Mapping rules live in `tools/common.py` (`PRODUCT_RULES`).
4. File names are portable: no spaces and none of `< > : " | ? * \`. (The old tree had `:`/space names that cannot be checked out on Windows.)
5. Page id = Learn/MSDN id (`aa450192`); a version suffix `(v=tag)` is kept only when it was in the original file name.
6. Generated artefacts (SQLite, `.part`, pending queues) are never tracked.
7. Anything that can be regenerated from `corpus/` lives in `meta/index/` or a Release asset.

Old → new paths: `meta/path-map.tsv` (prefix rules) and `meta/path-renames.tsv` (file-level exceptions).
