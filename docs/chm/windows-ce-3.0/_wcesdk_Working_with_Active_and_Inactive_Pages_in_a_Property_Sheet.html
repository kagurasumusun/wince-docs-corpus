Working with Active and Inactive Pages in a Property Sheet

Important:
This is retired content. This content is outdated and is no longer being maintained. It is provided as a courtesy for individuals who are still using these technologies. This content may contain URLs that were valid when originally published, but now link to sites or pages that no longer exist.

A property sheet can have only one active page at a time. The active page is at the top of the overlapping stack of pages. A user activates a page by selecting its tab; an application activates a page by using the PSM_SETCURSEL message. Before the subsequent active page is visible, the property sheet sends it the PSN_SETACTIVE notification message. The page should respond by initializing its control windows.

The property sheet determines whether to enable or disable the Help button for an active page by checking for the PSP_HASHELP style. If the active page has this style, the property sheet enables the Help button. If PSP_HASHELP is not present, the property sheet disables the button. When a user taps the Help button, the active page receives the PSN_HELP notification message. The page should respond by displaying Help information.

When a user taps the OK button, the property sheet sends the PSN_KILLACTIVE notification message to the active page, giving it an opportunity to validate the changes that a user made. If the active page determines that the changes are valid, it should call the SetWindowLong function to set the DWL_MSGRESULT value for the active page to FALSE. In this case, the property sheet sends the PSN_APPLY notification message to each page, directing it to apply the new properties to the corresponding item. If the active page determines that the changes that a user made are not valid, it should set DWL_MSGRESULT to TRUE and display a dialog box that informs a user of the problem. The page that is currently active remains active until it sets DWL_MSGRESULT to FALSE in response to PSN_KILLACTIVE.

The property sheet sends the PSN_RESET notification message to all pages when a user taps the Cancel button, which indicates that it is about to destroy the property sheet.

Note   To set the position of a window that contains a property sheet in an application, use the SetWindowPos function, instead of the MoveWindow function. Call SetWindowPos in the dialog box procedure of the property page that will open first when a user activates a property sheet.
