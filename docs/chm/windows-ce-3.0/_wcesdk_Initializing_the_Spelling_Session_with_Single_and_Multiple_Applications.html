Initializing the Spelling Session with Single and Multiple Applications

Important:

Initialization of a spelling session requires the Windows CE-based device to load a set of data into active memory. Furthermore, the initialization process might reserve a large amount of resources. Monopolization of resources might not be a problem to a user who is running only one application on the device. However, you must take into account the possibility that other applications might need to use the spelling checker at the same time as your application.

In situations in which you can be certain that only one application uses the spelling checker, you should initialize the spelling session when the application starts. Initialization of the spelling checker at the beginning of an application means that you can avoid unnecessary processing in the middle of your application. Similarly, you should keep the spelling session active until the application ends.

Initialization of a spelling session is different when you program in a multiple-application environment. A spelling session has exclusive access to external user dictionaries until the calling application closes the spelling session, which means that a second application cannot load external user dictionaries that already are in use. Therefore, if your application runs in an environment in which other applications use the spelling checker, you might want to initialize the spelling checker when the application requests it. Initialization of the spelling checker only when an application needs it reduces the number of external user dictionaries that are tied up in any given application. When the application is finished with the spelling checker, you should call the SplQuit function to release the dictionaries, so that other applications can use them.

The main dictionary is available for multiple spelling sessions, because it is read-only. The internal user dictionaries are created for each spelling session and removed at the end of each spelling session.
