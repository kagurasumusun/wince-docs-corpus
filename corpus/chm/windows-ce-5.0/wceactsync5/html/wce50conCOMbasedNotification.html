COM-based Notification

In COM-based notification, two COM interfaces are used to register an application in the desktop registry.

  • IDccMan is part of the ActiveSync connection manager.
  • IDccManSink is part of the application and must be implemented by the developer. Each application can have its own IDccManSink interface. This interface will enable an application to detect whether a connection or disconnection with a Windows CE-based device has occurred.

Although COM-based notification is more complex than registry-based notification, it gives some control of the connection manager and the ability to register and deregister for connection notification. The application can also perform actions that would not be possible by simply executing a standard command line.

COM-based Notification Procedures

The notification process follows the basic steps for connection and disconnection of the Windows CE–based device.

To register an application

  1. Initialize the COM library and register the application for the appropriate event.
  2. Connect or disconnect the Windows CE-based device.
  3. Perform the application processing.

To receive notification upon connection of the Windows CE–based device to a desktop computer

  1. Initialize the COM library and register with the connection manager.
    • Call CoInitialize to initialize the Component Object library.
    • Call CoCreateInstance with the DccMan class identifier (CLSID_DccMan) and IDccMan interface identifier (IID_IDccMan), and receive a pointer to the IDccMan interface.
    • Call IDccMan::Advise, which supplies the connection manager with a pointer to the IDccManSink interface you implemented and registers the application with the connection manager.

      The connection manager calls IDccManSink::OnLogInactive, notifying the application that there is no connection between the desktop computer and the Windows CE-based device.

  2. Establish the connection between the desktop computer and the Windows CE-based device.
    • The connection manager calls IDccManSink::OnLogListen.
    • The connection manager waits for the remote connection services for both the desktop computer and the Windows CE-based device to respond. The connection manager will not proceed until they are both running.

      For Windows 95 systems, the connection manager calls IDccManSink::OnLogAnswered when the connection manager has detected the communications interface.

    • The connection manager calls IDccManSink::OnLogActive when the connection is established between the Windows CE-based device and connection manager.
    • The connection manager calls IDccManSink::OnLogIpAddr, providing the Internet Protocol (IP) address that it obtained for the communications socket.
      Note   When IDccManSink::OnLogIpAddr notification occurs, the connection is completely established.
  3. Perform your processing in the application.

    This can include processing on the desktop computer, remote processing on the Windows CE-based device by using the remote application programming interface (RAPI), or calling IDccMan methods. However, the application should wait to use CeRapiInit to initialize RAPI until the IDccManSink::OnLogActive notification is received. This ensures that a connection is established between the desktop computer and the Windows CE-based device.

To receive notification upon disconnection of the Windows CE–based device from the desktop computer

  1. Initialize the COM library and register the application.
  2. Disconnect the Windows CE-based device from the desktop computer.
  3. ActiveSync notifies the application when the desktop computer and Windows CE-based device are disconnected by calling IDccManSink::OnLogDisconnection.
  4. Perform your processing in the application.

    Because there is no connection to the Windows CE-based device, this processing can take place only on the desktop computer.

To receive notification when reestablishing a remote connection

The Connection Notification Client source code uses the IDccMan interface and implements the IDccManSink interface.

If a connection was established, but was then disconnected by the desktop computer or the Windows CE-based device, the IDccManSink::OnLogActive notification occurs when the connection is reestablished.

When an application calls the IDccMan::ShowCommSettings function and the OK button is clicked in the Communications Properties dialog box, the following notification sequence occurs.

  1. IDccManSink::OnLogListen
  2. IDccManSink::OnLogDisconnection
  3. IDccManSink::OnLogInactive
  4. IDccManSink::OnLogListen

If the Cancel button is clicked instead, no notification is sent and a Listen state is maintained.

To unregister an application from connection notification

COM-based notification allows an application to unregister itself. This is useful when an application needs to run only once.

  1. Call IDccMan::Unadvise, which releases the memory associated with the IDccManSink interface.
  2. Call IDccMan::Release, which releases the IDccMan object.
  3. Call CoUninitialize to perform OLE cleanup.

Note that a call to CoUninitialize is required for each successful call to CoInitialize.
