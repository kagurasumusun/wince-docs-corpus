TFAT Programming Considerations

The interfaces exposed by TFAT are equivalent to those associated with FATFS. To ensure transaction safety, you should understand the FAT file system and take note of the enhancements provided by TFAT.

When the file attribute FILE_FLAG_WRITE_THROUGH is set to true for any file, each WriteFile function call is committed to the disk in an individual transaction. The committing of data implies that all data written has been written to both the volume and the FAT tables. If this attribute is not set, the data written by the WriteFile function is committed until a CloseHandle or FlushFileBuffers function is called.

Other operations such as rename, createdir, and RemoveDirectory are all transaction-safe and committed when a CloseHandle, FlushFileBuffers, or WriteFile function is called.

Memory mapped files are automatically created with the CreateFile function setting the FILE_FLAG_WRITE_THROUGH value to true. As with any form of FAT, all databases and memory mapped files must commit every WriteFile operation to the FAT atomically and must have the FILE_FLAG_WRITE_THROUGH value set to true.

Any write operations performed in the root directory of a FAT12 or FAT16 volume are not transaction-safe. The operations on the sub-directories of FAT12 and FAT16 volumes and all FAT32 volumes are transaction-safe.

TFAT requires that a FAT volume have exactly two FAT tables. TFAT can still read and write FAT volumes that do not meet this requirement, but the operations are no longer transaction-safe.

The action of committing requires that the FAT table is copied. Write operations are slower if the FILE_FLAG_WRITE_THROUGH attribute opens the file streams. This operation adds the time necessary to copy the FAT to the operation that is used to commit the data. All file streams are opened by default with this flag. If you use TFAT to improve performance, Microsoft recommends that you disable this operation by clearing the 0x20 bit in the FATFS Flags registry setting.
