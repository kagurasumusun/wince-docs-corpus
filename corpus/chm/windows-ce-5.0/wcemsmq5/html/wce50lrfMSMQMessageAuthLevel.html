MSMQMessage.AuthLevel

This property specifies if the message needs authentication. 

HRESULT get_AuthLevel( 
  long* plAuthLevel 
);
HRESULT put_AuthLevel( 
  long lAuthLevel 
);

Parameters

plAuthLevel or lAuthLevel
Value that specifies if the message needs authentication.

The following list describes the AuthLevel property values.

MQMSG_AUTH_LEVEL_NONE
The default. The message is not signed. Message Queuing does not need to authenticate the message when it reaches the queue.
MQMSG_AUTH_LEVEL_ALWAYS
Message Queuing run-time signs the message using one or more types of digital signatures.

Non-HTTP messages are signed based on the value of the sending authentication registry key. If the registry key is not set, an MQMSG_AUTH_LEVEL_SIG10 signature is used.

HTTP messages are signed with an XML digital signature.

MQMSG_AUTH_LEVEL_MSMQ10
Obsolete. This value is superseded by MQMSG_AUTH_LEVEL_SIG10.
MQMSG_AUTH_LEVEL_MSMQ20
Obsolete. This value is superseded by MQMSG_AUTH_LEVEL_SIG20.
MQMSG_AUTH_LEVEL_SIG10
Introduced in MSMQ 3.0. For non-HTTP messages, the Message Queuing run-time ignores the sending authentication registry key and signs the message using only an MQMSG_AUTH_LEVEL_SIG10 signature.

For HTTP messages, the message is signed using an XML digital signature.

MQMSG_AUTH_LEVEL_SIG20
Introduced in MSMQ 3.0. For non-HTTP messages, the Message Queuing run-time ignores the sending authentication registry key and signs the message using an MQMSG_AUTH_LEVEL_SIG20 signature.

(This setting cannot be used when sending messages to multiple destinations using distribution lists, multicast addresses, or multiple-element format names.)

For HTTP messages, the message is signed using an XML digital signature.

MQMSG_AUTH_LEVEL_SIG30
Introduced in MSMQ 3.0. For non-HTTP messages, the Message Queuing run-time ignores the sending authentication registry key and signs the message using an MQMSG_AUTH_LEVEL_SIG30 or MQMSG_AUTH_LEVEL_SIG20 signature.

MQMSG_AUTH_LEVEL_SIG30 signatures are used if the message is sent to using distribution lists, multicast addresses, or multiple-element format names.

MQMSG_AUTH_LEVEL_SIG20 signatures are used if the message is sent without using distribution lists, multicast addresses or multiple-element format names.

For HTTP messages, the message is signed using an XML digital signature.

Return Values

The following table describes the common return values.

Value Description
S-OK Success
E_INVALIDARG One or more arguments are invalid
E_NOTIMPL The function contains no implementation
E_OUTOFMEMORY Out of memory

Remarks

The AuthLevel property is only used by the sending application to request authentication.

When authentication is requested, Message Queuing creates an XML signature for HTTP message and one or more of three non-XML signatures for non-HTTP messages.

The created digital signature is used to digitally sign the message when it is sent and authenticate the message when it reaches the target computer where the destination queue resides.

Authentication can be enforced at the queue level by setting the MSMQQueueInfo.Authenticate property of the queue.

When sending messages to queues that only accept authenticated messages, the message is rejected when it reaches the queue if the authentication level of a message is set to MQMSG_AUTH_LEVEL_NONE.

Message Queuing provides different signatures for HTTP and non-HTTP messages.

Non-HTTP signatures include the following:

  • MQMSG_AUTH_LEVEL_SIG10
  • MQMSG_AUTH_LEVEL_SIG20 (introduced in MSMQ 2.0)
  • MQMSG_AUTH_LEVEL_SIG30 (introduced in MSMQ 3.0)

XML signatures, introduced in MSMQ 3.0, are used whenever an HTTP message requests authentication.

The following authentication registry keys can be used to specify what type of signature is used for non-HTTP messages. When MQMSG_AUTH_LEVEL_ALWAYS is specified, the Message Queuing run-time creates digital signatures based on the value of the sending authentication registry key.

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\MSMQ\Parameters\Security\SendMsgAuthn

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\MSMQ\Parameters\Security\RcvOnlyEnhMsgAuthn

The receiving application can check to see if authentication was requested by retrieving MSMQMessage.IsAuthenticated.

Equivalent Function property

When using functions, authentication can requested using the PROPID_M_AUTH_LEVEL property.
