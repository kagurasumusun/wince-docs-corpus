Handling Button Messages

When a user selects a button, its state changes, and the button sends notification messages to its parent window about the changed state. For example, a push button sends the BN_CLICKED notification code when a user selects the button. In all cases, the low-order word of the wParam parameter contains the control identifier, the high-order word of wParam contains the notification code, and the lParam parameter contains the control window handle. Both the message and the response of the parent window to the message depend on the type and style of the button, as well as the current state of the button.

For automatic buttons, the OS handles all state changes, and the application processes only the BN_CLICKED notification code. For buttons that are not automatic, the application usually responds to the notification message by sending a message to change the state of the button. When a user selects an owner-drawn button, the button sends its parent window a WM_DRAWITEM message that contains the identifier of the control to be drawn, as well as data about its dimensions and state.

A button also can receive messages. A parent window can send messages to a button in an overlapped or child window by using the SendMessage function; a parent window can send messages to a button in a dialog box by using the SendDlgItemMessage and CheckRadioButton functions.

Windows also provides default color values for buttons. The system sends a WM_CTLCOLORBTN message to parent window of a button before the button is drawn. This message contains a handle to the device context of the button and a handle to the child window. The parent window can use these handles to change the text and background colors of the button. An application can retrieve the values for these colors by calling the GetSysColor function, or it can set the values by calling the SetSysColors function.

The window procedure for the predefined button control window class processes defaults for all of the messages that the procedure for the button control does not process. When the procedure for the button control returns FALSE for any message, the predefined window procedure checks the message.
