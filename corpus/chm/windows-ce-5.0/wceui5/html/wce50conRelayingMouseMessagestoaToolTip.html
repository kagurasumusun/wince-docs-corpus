Relaying Mouse Messages to a ToolTip

A ToolTip control must receive mouse messages to determine when to display the ToolTip window. Because Windows CE sends mouse messages only to the window that contains the cursor, you must use the TTM_RELAYEVENT message to relay mouse messages to the ToolTip control.

If you implement a tool as a rectangular area in an application-defined window, the window procedure receives mouse messages and can relay them to the ToolTip control. However, if you implement a tool as a system-defined window, the mouse messages are sent to the window and are not readily available to the application. In this case, you must either subclass the window or use a message hook to access and relay the mouse messages. You must then explicitly relay mouse messages to the ToolTip control by using TTM_RELAYEVENT.

When a ToolTip control receives a relayed WM_MOUSEMOVE message, the ToolTip control determines whether the cursor is inside the bounding rectangle of a tool. If the cursor is inside the bounding rectangle of a tool, the ToolTip control sets a timer. At the end of the time-out period, the ToolTip control checks the position of the cursor to see if the cursor moved. If the cursor did not move, the ToolTip control retrieves the text for the tool, copies the text into the ToolTip window, and shows the window. The ToolTip control continues to show the window until the ToolTip control receives a relayed button-up or button-down message or until a relayed WM_MOUSEMOVE message indicates that the cursor moved outside the bounding rectangle of the tool.

A ToolTip control actually uses three time-out durations. The initial duration is the length of time that the cursor must remain stationary within the bounding rectangle of a tool before the control displays the ToolTip window. The reshow duration is the length of the delay before the control displays subsequent ToolTip windows when the cursor moves from one tool to another. The pop-up duration is the length of time that the ToolTip window remains displayed before it is hidden. That is, if the cursor remains stationary within the bounding rectangle after the control displays the ToolTip window, the ToolTip window is hidden automatically at the end of the pop-up duration. You can adjust all of the time-out durations by using the TTM_SETDELAYTIME message.

If an application includes a tool that is implemented as a rectangular area and the size or position of the control changes, the application can use the TTM_NEWTOOLRECT message to report the change to the ToolTip control. An application does not need to report size and position changes for a tool that is implemented as a window. The application does not have to report these changes because the ToolTip control uses the window handle of a tool, instead of the bounding rectangle of the tool, to determine if the cursor is on the tool.

Before a ToolTip control actually displays, the control sends the TTN_SHOW notification code to the owner window. The control sends the TTN_POP notification code when the control is about to be hidden. The control sends each notification code in the context of a WM_NOTIFY message.

The TTM_HITTEST message enables you to retrieve information about the tool that occupies a particular point. The message includes a TTHITTESTINFO structure that contains a window handle, the coordinates of a point, and a TOOLINFO structure. The ToolTip control determines whether a tool occupies the point and fills the TOOLINFO structure with information about the tool that occupies the point.
