Adding Callback Items and Callback Masks

For each of its items, a list view control typically stores the label text, the image-list index of the icons of the item, and a set of bit flags for the item state. A callback item in a list view control is an item for which the application stores the text, the icon index, or both. You can define callback items or change the callback mask of the control to indicate that the application, and not the control, stores some or all of this data. You might want to use callbacks if your application already stores some of this data. You can define callback items when you send the LVM_INSERTITEM message to add an item to the list view control.

The callback mask of a list view control is a set of bit flags that specify the item states for which the application, and not the control, stores the current data. The callback mask applies to all of the control items, unlike the callback item designation, which applies to a specific item. The callback mask is set to zero by default, which means that the list view control stores all of the data on the state of the item. After you create a list view control and initialize its items, you can send the LVM_SETCALLBACKMASK message to change the callback mask. To retrieve the current callback mask, send the LVM_GETCALLBACKMASK message.

When a list view control must display or sort a list view item for which the application stores callback data, the control sends the LVN_GETDISPINFO message to the parent window of the control. This message specifies an LV_DISPINFO structure that indicates the type of data that is required. The parent window must process LVN_GETDISPINFO to provide the requested data.

If the list view control detects a change in the callback data for an item, the control sends an LVN_SETDISPINFO message to notify you of the change. Changes that the list view control detects are alterations to the text, the icon, or the state data that is being tracked by the application.

The following code example shows how the list view control requests data.

  }

      // list view item.

    }

    case LVN_ODCACHEHINT:
    {
      LPNMLVCACHEHINT lpCacheHint = (LPNMLVCACHEHINT)lParam;

If you change the attributes or the state bits of a callback item, you can use the LVM_UPDATE message to force the control to repaint the item. This message also causes the control to arrange its items if the control has the LVS_AUTOARRANGE style. You can use the LVM_REDRAWITEMS message to redraw a range of items by invalidating the corresponding portions of the client area of the list view control.
