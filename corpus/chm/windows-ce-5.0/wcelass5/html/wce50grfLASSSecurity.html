LASS Security

LASS provides the infrastructure that will enable application-independent and authentication mechanism-independent user authentication. LAPs enable a user to be authenticated to a Windows CE-based device, and provide a method for application-independent user authentication. Therefore, compromising the security of either the LASS or LAP will have a direct effect on the security of your sensitive resources.

In general, you should always use secure coding techniques while you work with any Windows CE functionality. For more information about Windows CE security services, see Enhancing the Security of a Device.

Best Practices for LASS

Use a two-tier trust model to enhance security

LASS is dependent on a trust model. Without the trust model, LASS can be disabled by any running application. To enhance the security that you get from LASS, you must use a two-tier trust model, or make sure that you do not allow any ISV applications to run on your system. For more information about creating a trusted environment, see Trusted Environment Creation.

Best Practices for LAP

Use discretion when you assign trust levels to third-party applications

The password LAP that is available in Windows CE uses the SetPassword and GetPasswordActive APIs, and therefore can be interfered with a trusted application.

Always enroll before you call VerifyUser for the first time

The password LAP that is available in Windows CE is currently configured to return TRUE on calls to VerifyUser until the enrollment has completed. This can potentially compromise your device, so when you use the password LAP in Windows CE, you must always enroll the LAP before the first call to VerifyUser.

Implement the LASS Exponential Backoff mechanism

If your LAP is vulnerable to denial of service attacks, it is good practice to implement the LASS Exponential Backoff mechanism, because this mechanism is designed to deter brute force attacks that rapidly try several authentications on a LAP by introducing an exponentially increasing time delay between unsuccessful consecutive attempts of the VerifyUser call to a LAP. For more information about exponential backoff, see LASS Exponential Backoff.

Default Registry Settings

You should be aware of the registry settings that impact security. If a value has security implications, you will find a Security Note in the registry settings documentation.

For LASS related registry information, see LASS Registry Settings.

Ports

No specific ports are used for LASS.
