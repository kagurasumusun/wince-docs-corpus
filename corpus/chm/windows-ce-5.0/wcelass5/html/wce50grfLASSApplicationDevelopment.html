LASS Application Development

Local Authentication Subsystem (LASS) is the latest improvement in user authentication, and is much more versatile than the old method of password authentication. LASS provides the infrastructure that will enable application-independent and authentication mechanism-independent user authentication. Password authetication provides only one option, namely a password, for verification, but with LASS you can include sophisticated authentication mechanisms such as biometrics. In addition, you can also specify event-based policies to verify a user. For more information, see Comparing LASS and Password Authentication.

The default Local Authentication Plugin (LAP) that is available for LASS in Windows CE is a password LAP that authenticates a user based on password verification. Depending on your needs, the password LAP can be replaced by a customized LAP. In addition to a default LAP, predefined Authentication Events (AEs) are also available in Windows CE, but an application can create its own custom AE to control the policy based on which the user is verified.

Depending on your role in the device life-cycle, you may perform all or a certain subset of LAP related tasks. For example, if you are a system administrator that is configuring your device, you may be interested in installing a LAP, setting an active LAP, and setting an AE policy. If you are an application developer, you may be interested in installing a LAP, setting an AE policy, and calling the LAP's VerifyUser function with the appropriate AE. As an OEM, you may be interested in creating a custom LAP.

If your LAP is vulnerable to denial of service attacks, you may choose to enable the LASS Exponential Backoff mechanism.
