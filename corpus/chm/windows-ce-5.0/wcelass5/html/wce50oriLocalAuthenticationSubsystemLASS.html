Local Authentication Subsystem (LASS)

Security services in Microsoft® Windows® CE 5.0 include Local Authentication Subsystem (LASS). LASS provides the infrastructure that will enable user authentication independent of the application and authentication mechanism. Password authetication provides only one option, namely a password, for verification, but with LASS you can include sophisticated authentication mechanisms such as biometrics. In addition, you can also specify event-based policies to authenticate a user. For more information about how LASS differs from the traditional password-based authentication schemes in previous versions of Windows CE, see Comparing LASS and Password Authentication.

Local Authentication Plugin (LAP)

The authentication mechanisms that plug into LASS are called Local Authentication Plugins or LAPs. LAPs are typically created by OEMs and ISVs to enable a user to be authenticated to a Windows CE-based device, and provide a method for application-independent user authentication. A password LAP is available in Windows CE that you can choose to set as the active LAP. However, depending on your needs, you can install and activate a custom LAP. For example, on a device with a finger print scanner, you can use a fingerprint LAP.

Authentication Event (AE)

An Authentication Event (AE) is the point at which a pre-defined rule or policy is applied to determine if a user needs to be authenticated. Every AE has an associated policy setting, like an authentication interval, or a hardware event, and can be configured through registry settings. Windows CE has pre-defined AEs available, but you can also create custom AEs so that an OEM, a user, or a system administrator can apply event-based policy that is based on the usage of the device. The AE can be installed by using appropriate registry settings. An AE policy is independent of the active LAP.
