Searching for a Memory Leak

A memory leak is a condition caused by an application that does not free up the extra memory it allocates. A serious memory leak eventually consumes all available memory, bringing your system to a halt.

To search for a memory leak within an application

  1. From the Edit menu, choose Event Filer.
  2. Clear all check boxes on the Synchronization, Miscellaneous, User Defined, and Extensions tabs.
  3. Select all check boxes on the Memory tab.
  4. Choose OK.
  5. From the Edit menu, choose Find Event.
  6. In the Process box, choose the entry corresponding to your process.
  7. Choose Previous or Next to step through the events in your process.
  8. Verify that Allocate Heap events are associated with an appropriate number of Free Heap events. Do the same for Allocate Virtual Memory and Free Virtual Memory events.

If the application appears to have a memory leak, determine the function in which memory allocations occur and when the corresponding memory is freed. Remember that this is a simplistic method for examining memory usage. It is recommended that you use a resource tracker or bounds checker to more thoroughly monitor memory management.
