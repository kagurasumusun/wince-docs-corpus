Open Function

The system calls the Open function when an application first connects to the registry to collect performance data. This function performs the initialization required for the application to provide performance data.

The following code example shows the syntax for an Open function.

DWORD CALLBACK OpenPerformanceData(
LPWSTR lpDeviceNames 
);

The OpenPerformanceData function name is a placeholder for a name defined by your application. The lpDeviceNames parameter points to a buffer containing the Unicode strings stored in the Export value in the HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Application_Name\Linkage registry key.

The strings are REG_MULTI_SZ strings, separated by a UNICODE_NULL character and terminated by two UNICODE_NULL characters. If the Export value does not exist, the value of lpDeviceNames should be NULL. The strings are the names of the devices managed by the application. The Open function calls the CreateFile function to open a handle to each device named. If CreateFile fails, the Open function must return the error code returned by the GetLastError function; otherwise, it should return ERROR_SUCCESS.

The Open function initializes the data structures it returns to the performance monitoring application. In particular, it examines the registry to get the Counter and Help indexes of the objects and counters supported by the application. It then stores these indexes in the appropriate members of the PERF_OBJECT_TYPE and PERF_COUNTER_DEFINITION structures.

The Open function may also perform the following initialization tasks:

  • Open and map a file-mapping object used by the application to store performance data. Create a mutex to prevent the application from changing a value while the performance DLL is reading it.

    This is one way to communicate performance data from the application to the performance DLL. If you use a different form of interprocess communication, substitute the appropriate steps to initialize that mechanism.

  • Initialize event logging, if the DLL uses event logging to report errors. This is the only way for the performance DLL to report error conditions to the user, other than through the debugger.
  • Initialize the object and counter indexes. This must be done each time the performance DLL is loaded, because the indexes vary from machine to machine.
  • Perform other initialization tasks necessary for the Collect function to collect performance data efficiently.
  • Record, in the event log, any error that prevents the Open function from completing successfully.
