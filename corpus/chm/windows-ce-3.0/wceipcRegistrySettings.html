The EnableRemoteConnect and LegacyMutualAthentication registry settings are not supported on Windows CE and, if they are present, will be ignored.

The DefaultAccessPermission, DefaultLaunchPermission, AccessPermission, and LaunchPermission keys hold a REG_BINARY value that contains the access-control list (ACL) of the principals who can launch classes on the current system. The ACL has the following structure:

typedef struct {
    WORD  wVersion;
    WORD  wPad;
    GUID  gClass;
    WCHAR szPerms[1];
} Permissions;

The wVersion field should be set to = 3,

The gClass field contains the globally unique identifier (GUID) of the AccessControl object and should be set to CLSID_DCOMAccessControl. This value is ignored in the LaunchPermissions and DefaultLaunchPermission keys.

The szPerms field is an access string that the AccessControl::Load receives from the IStream interface. It uses the following BNF syntax:

szPerms := ""
szPerms := AccessList
AccessList := IndividualControl
AccessList := IndividualControl;AccessList
IndividualControl := Principal
IndividualControl := -Principal
Principal := @groupname
Principal := username
Principal := @star
star := *

Examples

The following string allows "user1" and "user2", and the "administrator" group; and restricts "user3" user and the "villains" group:

"user1;user2;-user3;@administrators;-@villains"

Strings are interpreted sequentially — in other words, if "user1" is a member of the "group1" group, the following strings will allow "user1":

user1
@group1
@group1;user1
user1;@group1
@group1;-user1
user1;-@group1
user1;-user1
*;-user1;-@group1

The following strings will restrict "user1":

-user1
-@group1
-user1;@group1
-@group1;user1
-user1;user1
-user1;*

Note that:

  • Group names are prefixed by "@" (the "at" sign).
  • User names or groups are prefixed by "-" to disallow access.
  • The wildcard character "*" or "@*" allows all users, while the wildcard character "-*" or "-@*" denies all users. The wildcard character "*" is a group and must be marked as such. Parsers inside DCOM understand both "@*" and "*" syntax, but they always use "@*" syntax themselves.

Note also that, in order to be able to use the remoting functionality of DCOM, the access credentials of the user must be set in the HKEY_CURRENT_USER\Comm\Ident ; the computer name should be set to a unique (on local network) value in the HKEY_LOCAL_MACHINE\Ident . In order for NTLM authentication to work, the domain must be configured in the HKEY_LOCAL_MACHINE\Comm\Redir .

Example

[HKEY_LOCAL_MACHINE\Ident]
    "Name"="WinCEDCOMServer"
    "Desc"="DCOM server box"
    "OrigName"="WinCE"
    
[HKEY_LOCAL_MACHINE\Comm\Redir]
    "DefaultDomain"="REDMOND"

See the Security Support Provider Interface topic in this SDK documentation for more information on local and pass-through authentication, as well as usage and configuration.
