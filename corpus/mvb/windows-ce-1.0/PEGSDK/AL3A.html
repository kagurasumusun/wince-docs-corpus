General Requirements

These guidelines for applications which bear the Windows CE Logo were fashioned with the end user in mind. The goal of the Logo program is to foster ease of use of compliant applications by providing a consistent user interface and consistent operation to the extent possible. The Microsoft Windows CE operating system is modeled on the Windows 95 operating system, which millions of people around the world are familiar with and use every day on their desktop and portable computers. The areas in which the interface of Microsoft Windows CE differs from the interface of Windows 95 are chiefly due to the unique performance characteristics of the hardware platform for Microsoft Windows CE. Like the other Microsoft logo programs, the Windows CE Logo is intended to inform consumers that the Logo’d product complies with a set of criteria that ensure a convenient and predictable user experience.

Important Notes on Application Types

Microsoft Windows CE compatible applications are currently available in two variants:

1. “Microsoft Windows CE-based Applications” are those which are singularly available for the Microsoft Windows CE-based platform.

2. “Microsoft Windows CE-based Desktop Companion Applications” are those which operate on the desktop and interact with Microsoft Windows CE and/or Microsoft Windows CE-compatible Applications. There are several additional requirements which these applications must meet, including earning the “Designed for Microsoft Windows 95” logo.

Applications may also be file-based or non-file based; there are additional requirements for file-based applications; see below.

Forthcoming standards: Development tools which target Microsoft Windows CE may earn the Logo, as well as browser plug-ins, and add-in products such as graphics, filters, custom dictionaries or other non-executables. Specific requirements for these products will be forthcoming; meanwhile, they will be handled on a case-by-case basis.

Hardware which is bundled with your software must be tested by the Windows Hardware Quality Lab, whql@microsoft.com

32-Bit Requirement

Required: 32-Bitness. A Microsoft Windows CE-based Application must be a Win32® programming interface executable, compiled with a 32-bit compiler and using the Microsoft Windows CE SDK via license from Microsoft or any other authorized distributor. Or if your application is not represented in exe format [interpreted code, for example], then the "runtime engine" must be a Win32-based executable built using the Microsoft Windows CE SDK. [e.g., if you develop an application in Microsoft Access, your application is an .mdb file, not an .exe, but paccess.exe would need to be a Win32-based executable]

Required: Desktop Companion Applications Must Earn the “Designed for Windows 95” logo. This requires a separate test and fee at VeriTest. Details are available at www.veritest.com or www.microsoft.com/windows/thirdparty.htm.

Installation Requirements

Applications destined for ROM in an OEM’s device are exempt from meeting the installation/uninstallation requirement for their application in ROM. However if the Logo is to be used with the application other than to meet an OEM requirement, the application must meet installation/uninstallation requirements as outlined here.

Required: Use Microsoft Windows CE AppInstall. Applications bearing the Windows CE Logo must be installed to the Microsoft Windows CE-based platform using the Microsoft Windows CE AppInstall installation utility on the desktop computer. Other, direct-from-the-desktop installation schemes may not be used.

Recommended: Install from the Internet to Desktop PC. Criteria for direct Internet installations will be forthcoming in a later OS release. It is recommended that applications, wishing to take advantage of the Internet for distribution and installation, install to the desktop and follow the requirements listed here for using AppInstall.

Required: Provide Installation/Uninstallation Scripts. Typically, the Microsoft Windows CE-based platform will support the installation of several applications (in addition to the applications in ROM); this installation is controlled by the user by means of the desktop Microsoft Windows CE AppInstall utility. Applications bearing the Windows CE Logo must participate in a user-selected multiple application installation. Accordingly, developers must include Microsoft Windows CE AppInstall- compliant installation and uninstallation scripts.

Required: Install to the Program files folder, and Find This Path from the Registry. Applications loaded to the Windows CE platform must first copy their application files to the desktop computer. The default installation location on the desktop computer should be a sub-folder of the HPC Applications folder, located in the HPC Explorer installed dir. The location of the HPC Explorer installation directory is in the desktop computer's registry, in HKLM\Software\Microsoft\Pegasus\InstalledDir.

For example, if HKLM\Software\Microsoft\Pegasus\InstalledDir is c:\Program Files\HPC Explorer and the application being installed is Blackjack, the default installation directory should be c:\Program Files\HPC Explorer\HPC Applications\Blackjack.

Recommended: Persistence of Data files. When an application is unloaded from the Microsoft Windows CE-based platform by the user, the application’s data files should remain on Microsoft Windows CE; the user should be required to take affirmative steps to remove data files

Recommended: Single Executable. If possible, the application should install only a single executable onto the Microsoft Windows CE-based platform.

Registry Requirements

Required: Persistence of User Configurations in Registry. User configuration data relating to a currently uninstalled application’s setup while on the Microsoft Windows CE-based platform must be installed within the Microsoft Windows CE registry, such that subsequent installations of the application to the Microsoft Windows CE-based platform retain the user’s most recent configuration settings.

Required: Register Installation/Uninstallation Script with AppInstall. Applications bearing the Windows CE Logo must also store the necessary installation/uninstallation scripts on the Microsoft Windows CE-based platform.

Required: Store DLLs Only in Windows or Application Directory. Any .dll files used in the installation of the application on the Microsoft Windows CE-based platform must be stored in the Windows directory or in the application’s own directory.

Required: Do Not Load Microsoft Windows CE System Components During Installation. Because Microsoft is not authorizing anyone to distribute the Microsoft Windows CE shared system components (included with the original Microsoft Windows CE operating system or with subsequent upgrades), it is not permissible to load these components onto the Microsoft Windows CE-based platform. Attempting to install Microsoft Windows CE core components on top of an existing Microsoft Windows CE-based platform installation could impair the functionality of both the developer’s application and all other applications loaded on the Microsoft Windows CE-based platform.

Recommended: Long, Meaningful Filenames for Installed Components. Microsoft Windows CE-based applications installing components to the Windows or application directories should assign long, meaningful filenames to assist users in determining the genesis of installed components. A typical filename might be company_application_function.dll. Note: this is especially important on Microsoft Windows CE where legacy 8.3 filename conventions are not supported.

UI/Shell Support Requirements

Consistency of the Command Bar is very important to Microsoft Windows CE-based applications. The basic order, left to right, should be consistent with MicrosoftWord, Pocket Edition. Hence:

Required: Command Bar Appears at the Top of Screen by Default. Where it is supported, the Microsoft Windows CE application command bar must always appear by default at the top of the screen of the primary window. Additionally, it must by default appear “Always on top” (to borrow terminology from the Windows 95 desktop environment), although it is permissible for Logo’d applications to provide a user option to hide the command bar as long as it can be retrieved. Games and certain utilities may be exempt from the Command Bar requirement. These will be considered on a case-by-case basis.

Required: Order of Menus and Buttons: Any menus appearing in the command bar must appear in the leftmost portion of the Command Bar. Tool buttons, both Microsoft Windows CE standard and application-specific must appear to the right of the menus in the command bar (between menus and Help).

Required: Help Must be the Rightmost Button in the Command Bar. The Help button, with its characteristic question mark icon, must always appear in the rightmost available position on the command bar, just before the close button which always appears to the right edge.

Required: Certain Menus Must Appear in Order. If you provide File, Edit, View, Insert, Format, Tools, Window menus, they must appear in this order, left to right.

Required: Certain Buttons Must Appear in Order. If you provide New, Open, Save, Print buttons, they must appear in this order, left to right. It is strongly recommended that you follow the UI guidelines for button size and style.

Required: Certain Functions Must Appear in Order. If you provide Style, Font, Font Size, Bold, Italic, Underline buttons or drop-down combo boxes, they must appear in this order, left to right. It is strongly recommended that you follow the UI guidelines for button size and style.

Required: Tool Tips. Microsoft Windows CE-based applications are required to support Tooltips for their command bar buttons. First-time users of an application can thus easily determine the function of an unfamiliar button.

Required: 16x16 and 32x32 Pixel Icons for Application and File Types. Applications are required to register 16x16 and 32x32 pixel icons for their main executable and saved file types.

Required: Dialog support for OK, Cancel Buttons. Dialog boxes appearing with Microsoft Windows CE-based applications must support the Microsoft Windows CE-standard OK and Cancel (X) buttons, as they appear in the top right corner of standard Microsoft Windows CE windows.

Required: Microsoft Windows CE Address Book API Functionality not Duplicated. Applications that use address book-type data must use the Microsoft Windows CE address book API – this is required to maximize available user storage space on the Microsoft Windows CE-based platform by preventing the storage of superfluous address books in Microsoft Windows CE memory; additionally, use of the Microsoft Windows CE address book API provides a consistent user interface and simplifies communications conducted with Microsoft Windows CE.

Required: Microsoft Windows CE Msgstore API Functionality Not Duplicated. Likewise, Logo’d applications are required to use the universal inbox provided by the msgstore data API where it is appropriate. For example, some communication applications (such as two-way paging applications) may require greater functionality than the msgstore data API provides, and are exempt from this requirement. All other applications, however, are expected to use the universal inbox provided with Microsoft Windows CE.

Required: IrDA for Infrared Connectivity. Applications supporting infrared transfer of data must support IrDA standards.

Required: Support for Standard Wait Cursor. Applications must use the standard Wait Cursor (i.e., hourglass) when asked to execute a command that renders the current window, or the system as a whole, unresponsive to user input. When displayed only for the current window, the user may continue to interact with other windows, including the taskbar.

Required: Alt-tap to Access Contextual Menus and Property Sheets The Microsoft Windows CE operating system as installed on Microsoft Windows CE-based platforms supports contextual menus and property sheets. These are recommended but not required of applications bearing the Windows CE Logo. However, if they are present, it is required that they are accessed on the Microsoft Windows CE-based platform desktop by means of an Alt-tap action. In other words, anything which emulates a right mouse action on Windows 95 must be accessed by Alt-tap.

Recommended: No Overlapping or Sizable Windows. Applications bearing the Windows CE Logo should use the full screen of the Microsoft Windows CE-based platform (480 pixels x 240 pixels) for their primary window unless the application may be used in conjunction with another application and the user benefits from seeing the window under the active application.

Recommended: HTML Help. It is recommended that Logo’d applications use Help files authored in HTML; this may be a future requirement.

Recommended: Shortcuts in Programs Folder Created on Installation. Developers are encouraged to create shortcuts for their applications within the My HPC>Programs Files folder on the Microsoft Windows CE-compatible device desktop. Like HTML Help, this may be a future requirement.

Recommended: No Title Bars. To save screen space, it is strongly recommended that you do not provide a Title Bar, and do not put the title of your application in the Command Bar, but rely on the icon which appears on the taskbar. If desired, an application or document name can be supplied on the line below the command bar as is done in the Microsoft Windows CE explorer.

Special UI/Shell Support Requirements for SDI/File Based Applications

These are applications whose primary purpose is to open, create and edit documents. Examples of non-file-based applications would include PIMs and Games.

Required: Support for Common Dialog Boxes. File-based and/or Single Document Interface applications operating on the Microsoft Windows CE-based platform must support common Microsoft Windows CE dialog boxes, including New, Save and Print (as supported), and not use proprietary interfaces for these functions.

Recommended: Recently Used File List. This must appear immediately above the Close command in the File menu, separated from other menu entries above and below by separator bars.

Required: Document Names on Taskbar Buttons. Document names (or Microsoft Windows CE assigned aliases) must appear on the associated taskbar buttons, to the right of the application icon.
