ioctlsocket

The Windows Sockets ioctlsocket function controls the mode of a socket.

int ioctlsocket (// winsock.h
SOCKET s,// descriptor identifying socket
long cmd,// command to perform on the socket s
u_long *argp// pointer to a parameter for cmd
);
Parameters
s
A descriptor identifying a socket.
cmd
The command to perform on the socket s.
argp
A pointer to a parameter for cmd. The following commands are supported.
Command		Semantics
FIONBIOEnable or disable nonblocking mode on the socket s. argp points to an unsigned long, which is nonzero if nonblocking mode is to be enabled and zero if it is to be disabled. When a socket is created, it operates in blocking mode (that is, nonblocking mode is disabled). This is consistent with BSD sockets.
The WSAAsyncSelect function automatically sets a socket to nonblocking mode. If WSAAsyncSelect has been issued on a socket, then any attempt to use ioctlsocket to set the socket back to blocking mode will fail with WSAEINVAL. To set the socket back to blocking mode, an application must first disable WSAAsyncSelect by calling WSAAsyncSelect with the lEvent parameter equal to zero.
FIONREADDetermine the amount of data that can be read atomically from socket s. argp points to an unsigned long in which ioctlsocket stores the result. If s is of type SOCK_STREAM, FIONREAD returns the total amount of data that can be read in a single recv; this is normally the same as the total amount of data queued on the socket. If s is of type SOCK_DGRAM, FIONREAD returns the size of the first datagram queued on the socket.
SIOCATMARKDetermine whether all out-of-band data has been read. This applies only to a socket of type SOCK_STREAM that has been configured for in-line reception of any out-of-band data (SO_OOBINLINE). If no out-of-band data is waiting to be read, the operation returns TRUE. Otherwise, it returns FALSE, and the next recv or recvfrom performed on the socket will retrieve some or all of the data preceding the "mark"; the application should use the SIOCATMARK operation to determine whether any data remains. If there is any normal data preceding the "urgent" (out-of-band) data, it will be received in order. (Note that a recv or recvfrom will never mix out-of-band and normal data in the same call.) argp points to a BOOL in which ioctlsocket stores the result.
Return Values
If the function succeeds, ioctlsocket returns zero. If the function fails, a value of SOCKET_ERROR is returned. To get extended error information, call GetLastError.
Error code		Description
WSANOTINITIALISEDA successful WSAStartup must occur before using this function.
WSAENETDOWNThe Windows Sockets implementation has detected that the network subsystem has failed.
WSAEINVALThe cmd parameter is not valid, or argp is not an acceptable parameter for cmd, or the command is not applicable to the type of socket supplied.
WSAEINPROGRESSA blocking Windows Sockets operation is in progress.
WSAENOTSOCKThe descriptor s is not a socket.
Remarks
This function may be used on any socket in any state. It is used to get or set operating parameters associated with the socket, independent of the protocol and communications subsystem.
Compatibility
This function is a subset of ioctl as used in Berkeley sockets. In particular, there is no command equivalent to FIOASYNC, while SIOCATMARK is the only socket-level command supported.
