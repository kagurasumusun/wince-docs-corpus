Traps

All traps are disabled by default. Traps are supported if and only if the kernel supports a real, non-stubbed version of RaiseException. Traps can then be enabled and disabled by making the appropriate calls to the _controlfp function, and caught by using try/except. The exception filter should use the _fpieee_flt function to extract the circumstances of the trap. _fpieee_flt also provides the ability to return an alternate result if desired. If traps are enabled but no trap handler is provided, the program behaves as it would for any other uncaught SEH trap.

If traps are disabled, all results from mathematical operations that would have generated a trap, had the corresponding bit in the floating-point control word been set, are defined according to IEEE for the basic arithmetic operations. The remainder are defined according to the VC/C++ elementary function library conventions.

If traps are enabled, the result delivered to a trap handler for a basic arithmetic operation is the same as the result that would have been generated had the trap been disabled.

The _controlfp function supports the trap enable mask flags from <float.h> shown in Table 7.

Table 7. Supported _controlfp Control Flags

CONTROL FLAGMEANING
_MCW_EMDisable all traps
_EM_INEXACTDisable inexact traps
_EM_UNDERFLOWDisable underflow traps
_EM_OVERFLOWDisable overflow traps
_EM_ZERODIVIDEDisable divide by zero traps

The _controlfp function does not support the x86-specific rounding control flags _MCW_RC or _RC_*.
