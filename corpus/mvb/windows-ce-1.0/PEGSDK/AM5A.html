Stylus Input

Stylus interaction should follow the same general input definitions for press, tap, double-tap, and drag as the pen input conventions outlined in The Windows Interface Guidelines for Software Design. However, Windows CE does not support all the interaction for pen input. For example, the Windows CE operating system does not currently support handwriting recognition or gestures. If you wish to add this support to your applications, you should refer to the main guidelines for recommended implementation conventions.

Stylus interaction is similar to the conventions for pen input. When the user presses the stylus to the screen, the input focus moves to the object under the stylus. If the object is a control, it should display its pressed appearance. If the user moves the stylus off the control while the stylus is still pressed against the screen, the control returns to its original state (unless the control includes a draggable object, in which case the object moves with the stylus). Moving the stylus back over the control while pressing against the screen returns the control to its pressed state. Similarly, for button controls, the command associated with the control only activates if the user lifts the stylus from the screen while over the button. If the stylus is not on the control when the user releases, no action occurs.

The ALT key can be used in combination with a stylus action to support right mouse button actions. For example, use ALT+tap if you want to support a right button click operation, such as displaying a pop-up menu.

Touch (finger) input can be used as a substitute for a stylus; however, if you design your application for touch input you will need to make input areas such as controls larger to accommodate finger size. For more information, see the section on Visual Design in this document.
