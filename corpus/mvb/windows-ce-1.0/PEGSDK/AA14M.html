Retrieving Messages

Before a message can be used by an application it must be retrieved from the message store by calling the MailGet, MailFirst, or MailNext function. The message flags in the MailMsg structure passed to the function determine how much of the message is read into memory. If the MAIL_GET_BODY flag is set, the entire message is read into memory. This requires the system to allocate memory from the local heap. If the MAIL_GET_FLAGS flag is set, only the flag values and the object ID are retrieved from the message store. Retrieving the flags and object ID does not require memory to be allocated. If neither of these flags is set then all of the message except the body is retrieved and memory is allocated from the local heap.

Using MailFirst and MailNext to cycle through the message store with the MAIL_GET_FLAGS flag set is an excellent way for an application to build an array of pointers to particular types of messages in a particular folder without allocating memory. For example, your application could specify all unread messages the inbox folder and call MailFirst with the MAIL_GET_FLAGS flag set. A call to MailFirst returns the flags and object ID of the first unopened message in the inbox. The application could store the ID number as the first entry in the array. After resetting the flags to specify the same folder and type of message, a MailNext call with the MAIL_GET_FLAGS flag set would return the next object ID to be inserted into the array. Continue to reset the flags, call MailNext, and save the ID numbers in the array until all of the messages have been read. The array would then contain the object IDs of all unopened mail in the inbox.
