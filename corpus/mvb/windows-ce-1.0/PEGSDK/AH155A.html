If source programs are compared to natural language writing, a source statement corresponds to a sentence. The words that make up a source statement are reserved words and symbols. This section describes these basic program elements.

2.1 Source Statements

Source Statement Structure: The following shows the structure of a source statement:

[<label>] [D<operation>[D<operand(s)>]] [<comment>]

An example of this structure is shown in figure 2.1.

Figure 2.1 Structure of the Source Statement

Label: A symbol is a label attached to a source statement. A symbol is a name defined by the programmer.

Operation: An operation is the mnemonic of an executable instruction, an extended instruction, an assembler directive, or a directive statement.

· Executable instructions must be SH microprocessor instructions.

· Extended instructions are instructions that are expanded into executable instructions and constant data (literals). For details, refer to Section 9, Automatic Literal Pool Generation Function.

· Assembler directives are instructions that give directions to the assembler.

· Directive statements are used for file inclusion, conditional assembly, macro functions, and other functions. For details of each of these functions, see section 6, section 7, and section 8.

Operands: The object(s) of the operation’s execution are written as the operands. The number of operands and their types are determined by the operation. Some operations do not require any operands.

Comment: Comments are notes or explanations that make the program easier to understand.

2.2 Coding of Source Statements

2.2.1 Label Coding

2.2.2 Operation Coding

2.2.3 Operand Coding

2.2.4 Comment Coding

Source statements are written using ASCII characters. In principle, a single statement must be written on a single line, with a maximum length of 950 bytes. See section 2.3 for reference.

2.2.1 Label Coding

The label is written in one of two ways:

1. Written starting in the first column.

2. Written with a colon (:) appended to the end of the label.

Example:

LABEL1			; This label is written starting in the first column.

LABEL2: ; This label is terminated with a colon.

LABEL3 ; This label is regarded as an error by the assembler

; since it is not written starting in the first column,

; and does not terminate with a colon.

2.2.2 Operation Coding

The operation is written starting in the second or later column when there is no label, and written after the label, separated by one or more spaces or tabs, when there is a label.

Example:

ADD	R0,R1	; An example with no label.

LABEL1: ADD R1,R2 ; An example with a label.

Note: Since white spaces and tabs are ASCII characters, each space or tab requires a byte of storage.

2.2.3 Operand Coding

The operand is written following the operation field, separated by one or more spaces or tabs.

Example:

ADD 	R0,R1		; The ADD instruction takes two arguments.

SHAL R1 ; The SHAL instruction takes one argument.

2.2.4 Comment Coding

Assembler comments may be written in any of three ways.

2.3 Source Statements Coding across Multiple Lines

We recommend writing a single source statement across several lines in the following situations:

· When the source statement is too long as a single statement

· When it is desirable to attach a comment to each operand

Write source statements across multiple lines using the following procedure:

1. Insert a new line between any two tokens (i.e., not in the middle of a word or multi-character operator).

2. Insert a plus sign (+) in the first column of the next line.

3. Continue writing the source statement following the plus sign.

Spaces and tabs can be inserted following the plus sign.

Example:

.DATA.L	H'FFFF0000,	; In this example, a single source statement

+ H'FF00FF00, ; is written across three lines.

+ H'FFFFFFFF

A comment can be attached at the end of each line.

Example:

.DATA.L	H'FFFF0000,	; Initial value 1.

+ H'FF00FF00, ; Initial value 2.

+ H'FFFFFFFF ; Initial value 3.

; This is an example of attaching a comment

; to each operand.

2.5 Symbols
2.5.1 Symbol Functions
2.5.2 Symbol Coding
2.5.1 Symbol Functions
Symbols are names defined by the programmer, and perform the following functions:
· Address symbols: Express data storage and destination addresses
· Constant symbols: Express constants
· Aliases of register name: Express general registers
· Section names: Express section names
Note A section is a part of a program, and the linkage editor regards it as a unit of processing.
The following are four examples of symbol usages:
Example 1:
BRA SUB1 ; BRA is a branch instruction.
; SUB1 is the address of the destination.
SUB1:
Example 2:
MAX: .EQU 100 ; .EQU is an assembler directive that sets a value
; to a symbol.
MOV #MAX,R0 ; MAX expresses the constant value 100.
Example 3:
MIN: .REG R0 ; .REG is an assembler directive that defines a
; register name.
MOV #100,MIN ; Here, MIN is a name for R0.
Example 4:
.SECTION CD,CODE,ALIGN=4
; .SECTION is an assembler directive that declares
; a section.
; CD is the name of the current section.
2.5.2 Symbol Coding
Keep the following protocol in mind when coding symbols:
Available characters: The following members of the ASCII character set can be used:
· Upper-case and lower-case letters (A to Z, a to z)
· Numbers (0 to 9)
· The underscore character (_)
· The dollar sign character ($)
· The assembler distinguishes between upper-case and lower-case in symbols
Initial Symbol Characters: The first character in a symbol must be one of the following:
· Upper-case and lower-case letters (A to Z, a to z)
· The underscore character (_)
· The dollar sign character ($)
The assembler provides a method to reference symbols whose names contain characters other than those normally allowed. This is required in order to support “mangled” names for C++, such as output by the compiler when it is given the -S or -FAs options.
Any symbol name may be enclosed in backquotes (ASCII character 0x60); the symbol name will then be comprised of any and all characters occurring between the first and second backquotes. There is no way to define a symbol whose name contains a backquote character. It is possible to use this method to reference symbols whose names may be handled incorrectly by other tools (such as the linker, operating system loader, etc.); the assembler does no checking of any kind on the validity of the name.
Examples:
`.legal?symbol@thisway`: .data 0
.import `_??abc@@@xyz`
mov #`_??abc@@@xyz`+5,r1
Maximum length of a symbol: A symbol may contain an unlimited number of characters. Reserved words cannot be used as symbols. The following names must not be used because they are used as internal symbols by the assembler:
_$$nnnnn (n is a number from 0 to 9.)
Notes: 1. Internal symbols are necessary for assembler internal processing. Internal symbols are not output to assembler listings.
2. The dollar sign character used alone is a reserved word that expresses the location counter. See section 2.4, Reserved Words.
2.6 Constants
2.6.1 Integer Constants
2.6.2 Character Constants
2.6.1 Integer Constants
Integer constants are expressed with a prefix that indicates the radix. The radix prefix indicates the base of the constant. Table 2.2 lists integer types and their radix prefix.
Table 2.2 Integer Constants
Integer		Prefix
Binary numbersThe radix indicator B' plus a binary constant
Octal numbersThe radix indicator Q' or O' plus an octal constant
Decimal numbersThe radix indicator D' plus a decimal constant
Hexadecimal numbersThe radix indicator H' or X' or 0x plus a hexadecimal constant
The assembler does not distinguish upper-case and lower-case letters in the radix indicator. The radix indicator and the constant value must be written with no intervening space.
Example:
.DATA.B B'10001000
.DATA.B Q'210 ; These source statements all have the same
.DATA.B O'210 ; numerical value.
.DATA.B D'136
.DATA.B H'88
.DATA.B X'88
.DATA.B 0x88
The radix indicator can be omitted. Integer constants with no radix indicator are normally decimal constants, although the radix for such constants can be changed with the .RADIX assembler directive. See section 5.8.1, .RADIX: Default Integer Constant Radix Setting.
2.6.2 Character Constants
Character constants are considered to be constants that represent ASCII codes. Character constants are written by enclosing up to four ASCII characters in double quotation marks. The following ASCII characters can be used in character constants:
ASCII codes: H'09 (tab)
H'20 (space) to H'7E (tilde)
Example:
.DATA.L "ABC" ; This is the same as .DATA.L H'00414243.
.DATA.W "AB" ; This is the same as .DATA.W H'4142.
.DATA.B "A" ; This is the same as .DATA.B H'41.
; The ASCII code for A is: H'41
; The ASCII code for B is: H'42
; The ASCII code for C is: H'43
Use two double quotation marks in succession to indicate a single double quotation mark in a character constant.
Example:
DATA.B """" ; This is a character constant consisting of a
; single double quotation mark.
2.7 Location Counters
The location counter expresses the address (location) in memory where the corresponding object code (the result of converting executable instructions and data into codes the microprocessor can handle) is stored. The value of the location counter is automatically adjusted according to the object code output, and can be changed intentionally using assembler directives.
Example:
.ORG H'00001000 ; This assembler directive sets the location
; counter to H'00001000.
.DATA.W H'FF ; The object code generated by the assembler
; directive has a length of 2 bytes.
; The location counter changes to H'00001002.
.DATA.W H'F0 ; The object code generated by the assembler
; directive has a length of 2 bytes.
; The location counter changes to H'00001004.
.DATA.W H'10 ; The object code generated by the assembler
; directive has a length of 2 bytes.
; The location counter changes to H'00001006.
.ALIGN 4 ; The value of the location counter is corrected
; to be a multiple of 4.
; The location counter changes to H'00001008.
.DATA.L H'FFFFFFFF ; The object code generated by the assembler
; directive has a length of 4 bytes.
; The location counter changes to H'0000100C.
; .ORG is an assembler directive that sets
; the value of the location counter.
; .ALIGN is an assembler directive that adjusts
; the value of the location counter.
; .DATA is an assembler directive that reserves
; data in memory.
; .W is a specifier that indicates that data is
; handled in word (2 byte) size.
; .L is a specifier that indicates that data is
; handled in longword (4 byte) size.
See section 5.2.2, .ORG: Location-Counter Value Setting, and section 5.2.3, .ALIGN: Location-Counter Value Corrections.
The location counter is referenced using the dollar sign symbol or the PC symbol.
Example:
LABEL1: .EQU $ ; This assembler directive sets the value of the
; symbol LABEL1 to the current value of the location
; counter. .EQU is an assembler directive that sets the
; value of a symbol.
LABEL2: .EQU PC

Expressions are combinations of constants, symbols, and operators that derive a value and are used as the operands of executable instructions and assembler directives.
2.8.1 Expression Elements
An expression consists of terms, operators, and parentheses. Expressions of arbitrary complexity, using C operators and precedence, may be used almost anywhere that a number is required. The assembler supports many C language operators, using the C precedence.
Terms: Terms include the following:
· A constant
· The location counter reference ($ or PC)
· A symbol (excluding aliases of register names)
· The result of a calculation specified by a combination of the above terms and an operator
An independent term is also a type of expression.

2.8.3 Notes on Expressions
Internal Processing: The assembler regards expression values as 32-bit signed values.
Example:
~H'F0
; The assembler regards H'F0 as H'000000F0.
; Therefore, the value of ~H'F0 is H'FFFFFF0F (note that this is not
; H'0000000F).
Arithmetic Operators: Any expressions (arithmetic) involving relative symbols (symbols whose values cannot by determined until link time) must be reducible (by computing subparts of the expression whose operands are known at assembly time) to one of the following forms:
expr: constant
| symbol
| expr + expr
| expr - constant
2.9 Character Strings
Character strings are sequences of character data. The following ASCII characters can be used in character strings:
ASCII codes: H'09 (tab)
H'20 (space) to H'7E (tilde)
A single character in a character string has as its value the ASCII code for that character and is represented as a byte-sized data object. Character strings are written enclosed in double quotation marks. Use two double quotation marks in succession to indicate a single double quotation mark in a character string.
Example:
.SDATA "Hello!" ; This statement reserves the character
; string data Hello!
.SDATA """Hello!""" ; This statement reserves the character
; string data "Hello!"
; .SDATA is an assembler directive that reserves character string data
; in memory.
The difference between character constants and character strings is that character constants are numeric values. They have a data size of either 1 byte, 2 bytes, or 4 bytes. Character strings cannot be handled as numeric values. There is no limit on the length of the character string. The length of the character string can range from zero bytes to the size of available memory.
