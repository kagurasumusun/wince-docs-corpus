Application Hibernation

The system uses the WM_HIBERNATE message as the mechanism for asking applications to free memory. The system posts the message to an application whenever it needs memory. The system tries to be intelligent. It starts with the applications that have been inactive the longest, and hibernates the active application last.

An application should take the following actions when it receives a WM_HIBERNATE message:

1. Free any large pieces of memory (such as caches) that were allocated by a call to the VirtualAlloc function.

2. Free as many GWES objects as possible. Such objects include windows, bitmaps, and device contexts.

3. Save the state of the heap in order to restore it later, and then free the entire heap.

Hibernating is vital.All applications must handle the WM_HIBERNATE message and must do as good a job as possible on receiving it.

As the amount of available memory drops, the system posts WM_HIBERNATE messages at an increasing rate. If the system still reaches a situation where a call to VirtualAlloc is about to fail, it tries to free pages by shrinking the stacks. The system shrinks stacks last in order to minimize the risk of a stack fault, which is fatal to the application. If the system cannot free any stack pages, VirtualAlloc fails, and the failure is typically returned to the application as a failed function call.
