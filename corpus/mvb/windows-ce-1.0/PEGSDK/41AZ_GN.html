2. The PR3910 Core Architecture

The PR3910 core is a 32-bit RISC based CPU core with memory mangement unit and extended ISA designed for PDA and embedded applications.

2.1 Overview

Full 32-bit registers and datapaths. The PR3910 core is a 32-bit core with full 32-bit data paths and the standard MIPS R3000A general purpose registers.

Five stage RISC pipeline. The PR3910 core is a true RISC processor core and achieves close to one instruction per clock cycle. It is based on a load/store architecture and implements a five stage pipeline to achieve this low cycles per instruction (CPI) rate.

Large address space. A full 32-bit address space is available giving access to 4 G Bytes of virtual address space. Users can define their own virtual-to-physical address translators, kernel/user segmentations and memory protection schemes to protect kernel software or other critical codes.

2.2 Registers

The PR3910 core has a 32, 32-bit General Purpose Register set (GPR) used for data computation and manipulation. In addition to the GPRs, other registers are implemented to support additional functionality.

The PR3910 core implements a CP0 registers. This coprocessor contains registers used for exceptions handling, configuration, cache control, and debug support.

2.2.1 Processor Registers

The processor registers consist of a set of 32 general purpose registers of 32-bits each. In addition there are two 32-bit registers used for the hardware multiplier/divider result and a 32-bit program counter.

2.2.1.1 General Purpose Registers

The general purpose register set consists of 31 read write registers, (r1 through r31) and one register which is permanently zero (r0).The 31 registers which can be read and written are treated symmetrically and are accessible in both kernel and user modes of operation.

The registers have predefined uses by the system architecture and the compiler. The compiler mnemonics are given after the register names in 9.

2.2.1.2 MAC/Multiply/Divide Registers

The two 32-bit registers used to support the hardware multiplier, divider and the multiplier-accumulator (MAC) are the HI and LO registers. When a multiply or multiply-add operation is performed, the HI register contains the upper 32-bits of the 64-bit result and the LO register contains the lower 32-bits of the 64-bit result.

For divide operations the quotient is loaded into the LO register and the remainder (modulus) is loaded into the HI register.

2.2.1.3 Program Counter

The processor contains a 32-bit program counter allowing a full 4 GB virtual address space. The program counter is not directly accessible by any instruction and can only be modified by executing one of the jump or branch instructions.

The program counter is indirectly accessible by executing one of the jump and link or branch and link instructions or by examining the exception program counter (EPC) register after an exception has been taken.

2.2.2 CP0 Registers

The R3900 processor Core can be connected to as many as three coprocessors, CP1, CP2 and CP3.

A number of the internal CP0 registers are standard R3000A CP0 registers: STATUS, CAUSE, EPC, BADVADDR and PRID. The PR3910 also includes implementation dependent registers such as Config register, Cache register, Debug register and DEPC register.

2.2.2.1 Processor ID Register

The PR3910 core implements the processor ID register found in the MIPS processors.

2.2.2.2 Implementation Registers

There are additional registers implemented in PR3910 core such as Config register, Cache register, debug register and DEPC register; refer to Registers section for their functionality.

2.3 The PR3910 Pipeline

The PR3910 core is based on a RISC architecture with a 5-stage pipeline. This means that during any one clock cycle five instructions are in different stages of execution. The five pipeline stages in order of execution are instruction fetch (IF), decode (RD), ALU operation (ALU), memory (MEM) and write back (WB). 2.4 PR3910 Memory Architecture

The PR3910 core has a full 32-bit address space for a virtual address space of 4 Gbytes. It supports various kernel/user segmentations, cache and other memory architectures, address translations, and memory protection. It is discussed in detail in a subsequent chapter.

2.5 Endianness

The big or little endian configuration determines the byte addressing of a data word. Instructions must always fall on a word address and this option has no effect of the instruction addresses.

The PR3910 core has a hardware option that can be used to configure the endianness upon reset. This is done via a hardware pin strap, which determine the power-up state of an endian bit.
