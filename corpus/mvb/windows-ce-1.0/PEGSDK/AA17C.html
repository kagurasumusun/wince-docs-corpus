System Low Memory Handler

The system constantly monitors the amount of available memory and tries to prevent low memory conditions from occurring. The system maintains the following precautions in helping to achieve this goal:

· When an application allocates memory, the system “filters” this request by limiting the memory size. This prevents a single application from stealing all available memory with one large allocation. When the system enters a low memory situation, the maximum memory limit is further reduced.

· The system monitors available memory and handles two levels of memory conditions: a “Low Memory” threshhold, and a “Critical Memory” threshhold.

· When system memory falls below a specific “Hibernation Threshhold” (HIBERNATION_THRESHOLD in the table below), the system begins asynchronously sending WM_HIBERNATE messages to the applications.

The table below defines values for low memory threshholds and maximum memory allocations for the two levels of low memory conditions. These names are defined simply to aid in describing the low memory scenarios below.

ItemValueDescription
HIBERNATION_THRESHOLD128KMinimum available system memory, below which defines a “low memory” system. A WM_HIBERNATE message is sent when the system memory falls below this value.
LOWMEM_THRESHOLD64KMinimum available memory size system must maintain when system is in a “low” memory state.
LOWMEM_MAXSIZE16KMaximum size allowed to be allocated (using VirtualAlloc) when system is in a “low” memory state.
CRITMEM_THRESHOLD16KMinimum available memory size system must maintain when system is in a “critical” memory state.
CRITMEM_MAXSIZE8KMaximum size allowed to be allocated (using VirtualAlloc) when system is in a “critical” memory state.
Under a low memory condition, the system’s low memory handler appropriately responds to basically four situations:
· An application calls VirtualAlloc requesting a memory size greater than LOWMEM_MAXSIZE.
· An application calls VirtualAlloc requesting a memory size less than LOWMEM_MAXSIZE.
· An application calls VirtualAlloc requesting a memory size greater than CRITMEM_MAXSIZE.
· An application calls VirtualAlloc requesting a memory size less than CRITMEM_MAXSIZE.
1. Any VirtualAlloc requesting a memory size greater than LOWMEM_MAXSIZE will be failed if it would cause the amount of free physical memory in the system to go below the LOWMEM_THRESHOLD . No System Out of Memory Dialog will be displayed. Note that this could, but does not necessarily, translate into the same constraint being placed on a LocalAlloc. Depending on the state of the system’s heap, a LocalAlloc may still succeed, and a VirtualAlloc may not be necessary.
2. If a VirtualAlloc requesting a memory size less than LOWMEM_MAXSIZE would cause the amount of free physical memory in the system to go below the LOWMEM_THRESHOLD, then the System Out of Memory Dialog is displayed. The user is allowed to either select some applications that the system will try to close, or to move the object store slider by about 20K to get some more memory. The system sends WM_CLOSE messages to the applications selected by the user. If an application marked to be closed does not shutdown within 8 secs, an End Task/Wait dialog is displayed, giving the user the choice of terminating the application or waiting some more time.
3. Any VirtualAlloc requesting a memory size greater than CRITMEM_MAXSIZE will be failed if it would cause the amount of free physical memory in the system to go below the CRITMEM_THRESHOLD. Again, depending on the state of the system’s heap, this will vary somewhat.
4. If a VirtualAlloc requesting a memory size less than CRITMEM_MAXSIZE would cause the amount of free physical memory in the system to go below the CRITMEM_THRESHOLD, then the System Out of Memory Dialog is displayed. The user is allowed to either select some applications that the system will try to close, or to move the object store slider by about 20K to get some more memory. The system calls TerminateProcess to terminate any applications selected by the user.
Memory Allocations Tips
Any single allocation of greater than about 16K potentially will fail without the System Out of Memory Dialog being displayed or without the user’s awareness of a low memory state. The application must handle such failures gracefully.
Once the system is in a low memory condition, any allocation of greater than 8K potentially could fail. It is highly recommended that applications not allocate large sizes of memory in their shutdown code. Note that in this case, the user does know that a low memory situation exists.
Small memory allocations should almost never fail. Before any such allocation fails, the user will have gone through both the low memory and displays of the critical memory System Out of Memory Dialog. An application does not necessarily have to plan to handle such failures quite as gracefully.
