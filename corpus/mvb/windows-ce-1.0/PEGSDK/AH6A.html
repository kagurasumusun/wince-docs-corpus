The second section discusses the use of SHCL to compile and link programs and describes response files and the CL environment variable. The third section offers a quick alphabetical reference to all of the SHCL options, followed by more detailed descriptions and examples, organized by category.

Specifying SHCL Options

The SHCL command line uses the following syntax:

SHCL [[option...]] file... [[option | file]]... [[lib...]] [[/link link-opt...]][[@response-file]]

The following list describes input to the SHCL command:

EntryMeaning
optionOne or more SHCL options. NOTE: all options apply to all specified source files.
fileThe name of one or more source files, object files, or libraries. You must specify at least one filename. SHCL compiles source files and passes the names of the object files and libraries to the linker.
libOne or more library names. SHCL passes the names of these libraries to the linker for processing.
link-optOne or more of the linker options. The SHCL command passes these options to the linker for processing.
response-fileA file that can contain multiple options and filenames which you would otherwise type on the command line or specify by using the CL environment variable.
You can specify any number of options, filenames, and library names, as long as the length of the command line does not exceed the limit dictated by the operating system.
Filename Syntax
A filename can contain any combination of uppercase and lowercase letters, hyphens, underscores, and a period. Any filename can include a full or partial path. A full path includes a drive name and one or more directory names separated by backslashes (\). A partial path omits the drive name, which SHCL assumes to be the current drive. If you don’t specify a path, SHCL assumes the file is in the current directory.
The filename extension determines how files are processed. The filename extensions and the processes performed on the associated files are listed below.
Filename Extension		File TypeProcessing
.CC source fileFile is compiled.
.CXX, .CPPC++ source fileFile is compiled.
.OBJObject fileFile is passed to the linker.
.LIBLibraryFile is passed to the linker. The linker links this library with the object files SHCL created from source files and the object files given on the command line.
.DEFDefinition fileThe file is passed to the linker.
Any other extension or no extensionObject fileThe file is passed to the linker.
Specifying SHCL Options
You can specify SHCL options on the command line, in response files, and in the CL environment variable. Options specified in response files and the CL environment variable are used everytime you invoke SHCL. Unlike either the command line or the CL environment variable, a response file allows you to use multiple lines of options and filenames.
Options to the SHCL command consist of either a forward slash (/) or a dash ( - ) followed by one or more letters. Certain options take arguments; in some of these options, a space is required between the option and the argument; in others, no space is allowed. The spacing rules for the options are given in their descriptions. Options (except for the /HELP option) are case sensitive. For example, /C and /c are different options.
Order of Options
With the exception of the /link option, which precedes all options to be passed to the linker, options can appear anywhere on the SHCL command line. The compiler reads options from left to right. It begins with options specified in the CL environment variable and reads the content of response files when it encounters a @filename during its left-to-right scan of the command line. After gathering all options, the compiler applies each option to all files on the command line. If SHCL encounters conflicting options, the rightmost option will be used.

Using the Alternate Output File Options
The following paragraphs describe how to use the alternate output file options. Information is included on specifying paths and extensions, combining options, and using MS-DOS device names.
Path Specifications and Extensions
The filename argument must follow the option with no intervening space. It can be a file specification, a drive name, or a path specification. If filename is a drive name or path specification, the SHCL command creates the specified file or files in the given location; the default name is the base name of the first file plus the default extension. If the filename argument is a path without a filename (that is, a directory), end the path with a backslash (\) or SHCL cannot differentiate the path from a filename.
You can give any name and extension you want for filename. If you give a filename without an extension, SHCL automatically appends the default extension.
Only one kind of object or assembly listing can be produced for each source file. The following list summarizes the effects of each option with each type of argument:

MS-DOS Device Names
You can append the MS-DOS device names AUX, CON, PRN, and NUL to the alternate output-file options, except for the /FAstring option, and direct the resulting listing files to your terminal or printer. There can be no space between the option and the device name. For instance, the following command line generates assembly code for TEST.C and directs the output to the console:
SHCL /FaCON TEST.C
The following list summarizes the result when a device name is appended to an option:
Device name		Result
AUXSends the listing file to an auxiliary device
CONSends the listing file to the console
PRNSends the listing file to a printer
NULNo file is created
Note: Do not append a colon (:) to the device names when you use them as arguments to the listing options. For example, use CON instead of CON: and PRN instead of PRN:.
Examples
SHCL /FAsc HELLO.CPP
In the first example, SHCL produces a combined source and machine-code listing called HELLO.COD. The object file has the default name HELLO.OBJ.
SHCL /FaPRN HELLO.CPP
In this example, SHCL sends an assembly-code listing to the printer.
Precompiled Header Options
The Microsoft C and C++ compilers provide options for precompiling any C or C++ code — including inline code. This performance feature allows you to compile a stable body of code, store the compiled state of the code (including debugging information) in a file, and, during subsequent compilations, combine the precompiled code with code that is still under development. Thus, each subsequent compilation is faster by the time not required to recompile the stable code.
With Microsoft C/C++ you can precompile any C or C++ code. You are not limited to precompiling only header files. There are two different precompiled header facilities:
Automatic precompiled headers. Simply use one option, /YX, and let the compiler decide when to create and use precompiled headers.
Manual precompiled headers. Use the options /Yc and /Yu when you know that your source files use common sets of header files but do not include them in the same order, or when you want to include source code in your precompilation.
The first choice is quick and easy. The second requires the investment of a small amount of project-management time, but it offers faster compilations and the ability to precompile code other than simple header files.
Creation or use of precompiled headers is governed by the compilation options described in this section. In many cases, the behavior dictated by these options is affected by the hdrstop pragma. A related option, /Fp, allows you to specify a precompiled header filename
Optimization Options
Option
/Ostring
The /O options allow you to control the level of optimization that is applied to the code that the compiler generates for your program. In general, use the /Od option to disable optimization and thus speed compilation and simplify debugging; use the /Og option to enable a basic set of global optimizations.
The string argument is one or more letters, with no intervening spaces. The letters following the /O, including the number argument to /Obn and the minus argument to /Op-, can appear in a continuous series in any order. Detailed descriptions of all /O options follow the table below.
