Memory Viewer Application

The Windows CE SDK includes a Windows-based application called PMemView that allows you to remotely view all of the virtual memory in the Windows CE system and its usage. Before running PMemView, you must first enable remote access to the HPC from your workstation. This requires RAS for your Windows NT workstation and Repllog.exe running on the HPC. See Chapter 6, "Remote API Functions," for further details.

PMemView displays information about each process running on the HPC in a multiple-column list box. Double-clicking on a process name brings up a dialog box showing a detailed memory layout for that process.

In the detailed memory layout, the addresses on the left are the virtual addresses into which the pages are mapped. A 'C' represents ROM code pages, 'S' represents stack pages in RAM, 'W' represents read/write data in RAM, and 'P' represents peripherals mapped into your memory space. Each separate "pool" of pages, such as a stack or a heap, starts on a 64K virtual address boundary (that is, they start on a new line in the memory layout). Use the following guidelines to determine the type of data that each line represents:

· The first line of a process is the process code, R/W data, and read-only (RO) data that the loader created while loading the process. You will typically see a list of 'C's, followed by some 'W's and 'R's. These are your code, your RW data, and your RO data, respectively.

· You will probably see a few lines starting with 'S' at the end of the layout-these are stacks, and there is one per thread. These lines are at the end because the stack starts at the top of its reserved address range and grows downward.

· Sections starting with a 'W' are typically part of your heap. There can be more than one if you use the HeapAlloc function.

At a virtual address above 01000000 (your process slot base address-which is right at the top of your section) is memory being taken up by DLLs that are loaded in your address space. As with the first line of your detailed memory layout, all DLL lines are typically ROM code pages ('C's), followed by R/W data ('W's), followed by RO data ('R's). If you know the page size for the system you are running, multiply by the size to get the actual RAM usage ('W's + 'S's).
