The Transport Service Interface Functions

Inbox expects a set of Transport* functions that are exported by the transport service DLL. Note that if you were to write another mail client similar to Inbox, these functions could be named as desired. To create a transport service driver (that is, to be connected using Inbox), you must export all of the transport interface functions and provide an implementation for each of the transport interface functions listed in the table below. Even if the function is not relevant to your service, you still provide a stub for the function.

The following functions are used by Inbox and must be exported by a transport service DLL. These functions are identified by the prefix Transport.

FunctionDescription
TransportConnectConnects to a service for transmission or reception
TransportCountDetermines the number of message files present
TransportDelDeletes a message file
TransportDisconnectDisconnects the current service
TransportErrorReturns the current error number
TransportErrorMsgReturns a string describing the current error
TransportFreeMsgDestroys the MailMsg heap allocated by TransportRecv
TransportInitAllocates a local heap for a SERVICE structure and initializes several fields
TransportPropsModifies the transport service properties
TransportRecvGets and handles received messages
TransportReleaseFrees the SERVICE heap created by TransportInit
TransportSendSends a message
TransportViewProcesses and displays the body of a message
