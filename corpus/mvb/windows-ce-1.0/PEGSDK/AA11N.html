The Sample Transport Service

The Sample Code

The SDK includes sample code for a transport service (located in the directory \Peg\Samples\Svcsampl). The sample transport service interfaces with the file system and performs message service routines by creating, writing to, and reading from files that are located in the inbox. This is performed using file system functions such as CreateFile, ReadFile, and WriteFile. For transport functions that perform such tasks as sending, receiving, and deleting messages, a handle to a MailMsg structure is passed. The MailMsg structure contains the message header, body, and information about the message.

The sample transport service provided with the SDK sample code allocates a local heap (in TransportInit) for a transport-defined SERVICE structure that supports handling the messages, and provides a number of service functions to be used for message handling. For example, the sample service locates messages in a mail directory specified by the szMailDir field of the SERVICE structure. These messages are stored as individual text files; file names are simply numbers with a .txt suffix, assigned in sequence.

Every mail message that arrives on a server is given a unique ID. This id is guaranteed to be different for every mail message and this ID never changes. However, these IDs are rather long (up to 70 characters) and are not too convenient to work with inside the transport service.

So, for each session, the service generates a session ID to reference a long unique ID (see the TransportRecv function). Each time a connection is made to the server (that is, a POP3 session is created), the server looks at all of the currently stored messages and assigns a session ID to each message (numbered 1 thru the total number of messages). This makes it easier to reference a particular message without having to use its long unique ID. The drawback is that there is no guarantee that message number 5 (session ID is 5) on this session will still be message number 5 the next time the service is connected. So, the session ID can not be trusted from one connection of a service to the next reconnection of that service.

Efficient Memory Usage (Using the Heap)

Inbox allocates a private heap (using HeapCreate and HeapAlloc) for each mail message; however, Inbox opens only one mail message at a time, in order to conserve memory. When Inbox is finished working with a message, the application frees the allocated memory by calling HeapDestroy. If a service or application needs to create a memory heap, following this method can help to minimize the effects of memory fragmentation.

When working with a mail message, if Inbox has already allocated a heap for a message, then the service can reallocate memory on the existing heap. For example, if the handle hHeap in the MailMsg structure is not NULL, then additional memory can be allocated to this existing heap. So, Inbox will take care of freeing this memory when it calls the MailFree function.

Using the Sample Transport Service DLL

The sample transport service DLL can be built using the SDK IDE. The makefile for the sample service provided with the SDK is located in the directory \Peg\Samples\Svcsampl. To use the sample service with Inbox, you need to:

· Build Svcsampl.dll for your target platform using the sample code.

· Register the DLL in the HPC registry.

· Using Inbox, add a new service that uses the Sample Service Library.

· Connect the sample service within Inbox.
