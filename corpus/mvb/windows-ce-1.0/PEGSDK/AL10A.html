Functionality Requirements

Required: Full Functionality and Stability. Microsoft Windows CE-based applications must be fully functional and stable on the designated test platforms. All functionality must be in place when the application is submitted for testing. While Windows CE Logo testing is not QA testing, the goal is to confirm that the application being tested does not appear to adversely affect the overall stability of the Microsoft Windows CE-based device environment. The application must recover from standby/suspend situations on leading equipment.

Required: Help Must be Functional. Any online help included with Microsoft Windows CE-based applications must be fully functional at the time of testing. Content does not matter, however.

Required: RAPI. Microsoft Windows CE-compatible applications are required to use RAPI (Remote API) where applicable. When coded into an application, RAPI give the user full access to the file systems on the Microsoft Windows CE-based platform and the companion desktop computer. Applications are not allowed to use proprietary methods of accessing Microsoft Windows CE from the desktop.

Required: Filters that Support Drag and Drop File Exchange. Developers must provide filters to manage inter-device file transfer, capable of being installed and uninstalled where applicable. These filters must be constructed, installed and registered according to the guidelines provided in the Software Developer’s Kit (SDK). When the Microsoft Windows CE-compatible application is accompanied by a companion application on the companion desktop computer, a file of the type generated by the desktop application must, when dragged onto the Microsoft Windows CE Manager icon, be recognized by the Manager (through its use of the supplied filter) and properly converted to the file type used by the Microsoft Windows CE-based application.

Required: WinSock. Any companion application that communicates with the Microsoft Windows CE-based device is required to use WinSock. This allows other applications to communicate with the device at the same time, over the same cable, and prevents system resource allocation conflicts.

Required: Hibernation. When available system memory becomes low, the Microsoft Windows CE operating system sends a hibernation message to all applications. A hibernating application should reduce their memory footprint substantially from that which is necessary doing normal foreground operation. It is recommended each application reduce its RAM footprint when receiving a WM_HIBERNATE message by at least 25%, as measured by pMemtool.exe, a utility provided in the Windows CE SDK.

Required: Tray Icon. Companion desktop applications are required to support the Tray Icon, which gives a visual indication that the Microsoft Windows CE-compatible device is connected to the desktop computer. Support for the Tray Icon is recommended for the Microsoft Windows CE-based application itself.

Long Filename Support Requirements

Required: Windows 95- and Windows NT®- Style Long Filename Support. The application must use long filenames; i.e., your application must 1) support long filenames; 2) use long filenames for displaying all document and data filenames in the shell, in dialogs and controls, and with icons; and 3) hiding the .XXX extension names in the application itself is strongly recommended. Microsoft Windows CE-based applications that save files that are exposed to the user must support LFNs with all of the following required features:

1. Users must be able to enter names of 255 characters, including all uppercase and lowercase standard characters, embedded spaces, embedded periods, etc.

2. Leading and trailing spaces must be stripped by the Save As command. To test this, enter a name with leading and trailing spaces, such as “####This is a test###”, retrieve the file, and then make sure the spaces are deleted (Note: Here and throughout these guidelines, the number sign <#> indicates a spacebar space).

3. Question marks anywhere in the file name must prevent the file from being saved. No error message needs to be displayed.

4. The characters within the quotation marks “ . + , ; = [ ] ” must be supported anywhere in the name, including leading and trailing. These should not cause any error conditions.

Verification:

Here is how to test whether one’s product properly handles LFNs. Basically, LFNs must do the following:

· Allow periods, plus signs, commas, semicolons, equal signs, and square brackets anywhere.

· Not save leading or trailing spaces. (You can test for this by removing the name inserted into the Save As dialog box and typing “###test###” or similar text. The program should strip the spaces and add an extension, returning the file name “test.ext”.)

· Not save question marks.

· Support 255 characters (including the path and extension).
