About the Power Management States

In the most general sense, a portable computer can be in one of three states: dead, on, or off. Because a HPC is rarely completely off, these terms have slightly different definitions than for a desktop computer. The following table defines the possible states for a HPC.

Device StateDescription
deadThe computer has no batteries, or all batteries are completely dead. All contents of RAM are lost. (The device is purchased in this state.)
onAny time the display, keyboard, and touch panel are active, the device is in the on state. The CPU can be in either full-speed or idle CPU mode but this is transparent to the user.
offIn most cases the CPU is in suspend mode.
With the exception of the dead state, the computer never completely stops using power. In the off state, the computer switches to a minimum power state to maintain its clock and the applications and persistent data stored in RAM. Unneeded circuits and devices, such as the keyboard decoder, display, scratch-pad memory, and processor are de-energized in this state to reduce power requirements. The power used by PC Cards in the off state is determined by their drivers. For more information about device drivers, see the Windows CE DDK.
When the computer is in the on state, it selects various modes of operation to manage its power usage. These CPU operating modes expand the definitions of the on and off device states. The following table defines the possible CPU modes.
CPU Mode		Description
full-speedThe CPU is running at normal operating frequency.
idleThe CPU internal clock is stopped and the CPU is using little power. Peripherals and DRAM may be on or off. The CPU can enter and exit this mode in approximately 10 msec.
suspendThe CPU internal and external clocks are stopped and the CPU is using extremely low power. Peripherals and DRAM are usually off. The CPU might take as long as 100 milliseconds to wake-up from this mode.
Of these modes, applications are most affected by the idle and suspend modes.
The Idle Mode
The computer switches from the on mode to idle mode when all processes are idle. Switching to the idle mode is transparent to the user and most applications—peripheral modes do not change and the system continues to process interrupts (including the time slice interrupt).
Applications that retain control by using idle loops or using functions that do not let the operating system block operation prevent the operating system from switching the computer to the idle mode. All applications can contribute to power management by using functions that let the operating system block a return to the application (for example, GetMessage) rather than using functions that do not let the system block a return (for example, PeekMessage). Returning control to the operating system when possible lets the operating system determine when the system is inactive and it can select the most efficient operating state for the computer.
The Suspend Mode
The computer switches from the on or idle mode to the suspend mode for the following events:
· The user turns the computer off.
· The computer detects a critical power condition.
· The activity timer times-out.
Power management uses an activity timer to gauge whether the user is actively using the computer. The timer counts down while the computer is in the on state. When the timer reaches zero, the computer switches to the off state. The user can set the maximum value of this timer. The following events reset the timer to its maximum value:
· Key press or release
· Touch event
When the timer reaches five seconds, the computer plays a warning sound to alert the user that it is about to suspend operation.
The operating system does not notify an application when it enters the suspend mode. Most applications are not affected by this transition—when the device resumes operation, applications also resume operation as if they were continuously executing.
If an application uses the Sleep function, the elapsed time counter used for this function is not incremented while the computer operation is suspended. It starts counting again when computer operation is resumed. The real-time clock is not affected when the computer operation is suspended.
While applications are not notified about entering the suspend mode, the operating system does notify device drivers by calling a power handler function. Device drivers might use this notification to suspend operation of the devices they control.
This might result in a device not being available immediately after the computer switches back to the on mode. For example, when a file stored on a PC Card is open and the user tries to save the file immediately after turning on the computer (that is, before the card is powered up), the system returns error code 5. (The system also returns this error code if the card has been removed.)
The computer switches to the suspend mode if the user turns the computer off. Applications cannot suspend device operation.
The computer changes from the suspend mode to the on mode for the following events:
· The user presses the “On” button.
· An alarm event occurs.
· A warm or cold boot occurs (reset still waits for the user to turn on the computer).
The computer also changes to the on mode after a battery change. When changing to the on mode, power management notifies the shell so it can play a sound on wake-up.
Resuming Operation, Rebooting, and Resetting the Computer
Resuming computer operation from the idle or suspend mode does not alter computer memory or change application settings. In contrast, rebooting or resetting the computer does alter memory and affect program operation. The following table summarizes the differences between these transitions.
Transition		Description
wake-up
(or resume)		The transition from suspend mode to full-speed mode. Does not change memory or application settings.
cold boot
(or cold reset)		The device is completely reset. All applications are terminated, the working memory is cleared, and the object store is cleared.
warm boot
(or warm reset)		All applications are terminated and working memory is cleared. The object store integrity is maintained.
power-on resetThe transition from dead to on state. Same consequences as cold boot.
The power-on reset and cold boot transitions occur when power is first applied to the computer, or when all power is removed from the computer then reapplied after a minute. Unless the computer uses nonvolatile memory, the user will have to load or reload applications after a power-on reset. Object store data is lost after a cold boot.
The user warm boots the computer by pressing the reset button. Because this button is normally protected from accidental activation by being placed in a pin-hole recess or under the battery cover, users warm boot the computer only when it has stopped responding or has become unstable. A warm boot stops running applications and clears the memory used for application execution. Memory used for the object store and file system is preserved.
