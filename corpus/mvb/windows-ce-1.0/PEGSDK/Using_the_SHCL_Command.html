Using the SHCL Command

Compiling

Linking

Response Files

CL environment variable

You can use SHCL to compile specified source files into an object file, or to compile and link specified source files, object files, and libraries into an executable file or a dynamic-link library (DLL).

Fast compile by default.

If you do not specify any optimization options, SHCL uses the disable optimization option (/Od). This feature allows you to quickly compile code that is under development and to reserve use of the optimizing compiler until it is needed.

Use precompiled headers to speed compilation.

You can also use the precompiled header options (/YX, /Yc, /Yd, /Yu, /Fp, and the hdrstop pragma) to speed compilation.

Compiling

SHCL compiles each source file, creating an object file for each. It automatically includes the options listed in the CL environment variable and any specified response files.

You can use the Compile Without Linking option (/c) to create only an object file. The option /c stops SHCL before it invokes LINK.

Linking

SHCL automatically invokes the linker after compiling unless the /c option (Compile Without Linking) is used. It gives the names of the object files created during compiling, and the names of any object files or libraries given on the command line to the linker. The linker uses the options listed in the LINK environment variable. If you use /link to specify linker options on the SHCL command line, these options apply as well. If conflicts occur, options that follow /link override those in the LINK environment variable.

Before it creates the executable file or DLL, the linker resolves external references in the object files. An external reference is a function call in one object file that refers to a function defined in another object file or in a library. To resolve an external reference, the linker searches for the called function in the following order:

· The object files passed by SHCL

· The libraries given on the SHCL command line, if any

· The libraries named in the object files

After all external references are resolved, the linker links the object files and libraries named by SHCL to create a single executable file or DLL.

Example

Assume that you are compiling three C source files: MAIN.C, MOD1.C, and MOD2.C. Each file includes a call to a function defined in a different file:

· MAIN.C calls the function named func1 in MOD1.C and the function named func2 in MOD2.C.

· MOD1.C calls the standard library functions printf and scanf.

· MOD2.C calls graphics functions named myline and mycircle, which are defined in a library named MYGRAPH.LIB.

Compile with the following command line:

SHCL MAIN.C MOD1.C MOD2.C MYGRAPH.LIB

SHCL first compiles the C source files and creates the object files MAIN.OBJ, MOD1.OBJ, and MOD2.OBJ. The compiler places the name of the standard library (libc.lib or coredll.lib) in each object file. (Use the -Zl flag to override the placement of the name.)

Next, SHCL passes the names of the generated object files to the linker. Finally, the linker resolves the external references as follows:

In MAIN.OBJ, the reference to the function func1 is resolved using the definition in MOD1.OBJ; the reference to the function func2 is resolved using the definition in MOD2.OBJ.

In MOD1.OBJ, the references to printf and scanf are resolved using the definitions in the library that the linker finds named within MOD1.OBJ.

In MOD2.OBJ, the references to myline and mycircle are resolved using the definitions in MYGRAPH.LIB.

Response Files

A response file is an ASCII file containing options and filenames you would otherwise type on the command line or specify by using the CL environment variable. SHCL accepts a compiler response file as an argument on the command line. Unlike either the command line or the CL environment variable, a response file allows you to use multiple lines of options and filenames.

The options in the response file are interpreted as if they were present on the command line at the position of the response file invocation. An exception to this rule is the /link command. If /link appears in the response file, all options on the rest of the line are passed to the linker. Options in subsequent lines in the response file and options on the command line after the response file invocation are still accepted as compiler options.

Note: A response file should not contain the SHCL command. Also, each option must begin and end on the same line; you cannot use the backslash (\) to concatenate an option across two lines.

To invoke a response file, type the “at” sign (@) followed immediately by a filename; you can also specify a drive and path. A response file invocation is not allowed in the SHCL environment-variable string or in another response file.

Examples

You could put the following into a file named RESP:

/Og /link LIBC.LIB

SHCL uses these options in addition to any options you specify on the SHCL command line. If you specify the following SHCL command:

SHCL /Ob2 @RESP MYAPP.C

the following command to SHCL is the result:

SHCL /Ob2 /Og MYAPP.C /link LIBC.LIB

Note that the command-line and the response-file commands are effectively combined.

You can use NMAKE to create a temporary response file for a single compilation step as shown in the following response file:

MYAPP.OBJ : MYAPP.C

SHCL @<< MYAPP.C

/DV100 /Og

<<

CL Environment Variable

Note: Do not confuse the CL Environment Variable used by the SHCL cross compiler with CL.EXE, a separate compiler program.

Use the CL environment variable to specify files and options without giving them on the command line. The environment variable has the following syntax:

SET SHCL=[[ [[option]] ... [[file]] ...]] [[/link [[ link-libinfo]] ]]

The CL environment variable is useful if you often specify a large number of files and options when you compile. Ordinarily, MS-DOS limits the command line to 128 characters. The files and options that you define with the CL environment variable, however, do not count toward this limit. Therefore, you can define the files and options you use most often with the SHCL variable and then give only the files and options you need for specific purposes on the command line.

Note that if you have given an option in the CL environment variable, you cannot turn off or change the option from the command line. You must reset the CL environment variable and omit the file or option that you do not want to use. The information defined in the SHCL variable is treated as though it appeared before the information given on the SHCL command line.

With MS-DOS, you cannot use SHCL to set options that use an equal sign (for example, the /Didentifier= string option). With Microsoft C and C++, the define constants and macros option (/D) accepts the number sign (#) as an equal sign (=). You can now use the CL environment variable to define preprocessor constants and macros (for example, /D identifier #string).

You can use wildcards in filenames to specify multiple files with SHCL.

Examples

In the following example, the CL environment variable tells the SHCL command to use the /Zp, /Ox, and /I options during compilation and then to link with the object file \LIB\BINMODE.OBJ.

SET SHCL=/Zp2 /Ox /I\INCLUDE\MYINCLS \LIB\BINMODE.OBJ INPUT.C

Both the CL environment variable above and the SHCL command below specify structure packing on 2-byte boundaries, perform maximum optimizations, and search for include files in the \INCLUDE\MYINCLS directory for the source file INPUT.C.

SHCL /Zp2 /Ox /I\INCLUDE\MYINCLS \LIB\BINMODE.OBJ INPUT.C

In the following example, the CL environment variable instructs the SHCL command to compile and link the source files FILE1.C and FILE2.C:

SET SHCL=FILE1.C FILE2.C

>SHCL FILE3.OBJ

The preceding SHCL command line has the same effect as the command line:

SHCL FILE1.C FILE2.C FILE3.OBJ
