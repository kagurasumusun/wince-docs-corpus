Handling Errors

The primary difference between the Win32 based Windows CE functions and their RAPI counterparts is that RAPI related errors may occur when invoking a RAPI function. Errors such as networking errors need to be communicated back to the calling application. Because the parameters and return typing of the RAPI functions are similar to that of the Win32 based Windows CE functions, it is impossible to communicate the exact nature of the error back to the calling application through the original function call. For this reason, RAPI functions that fail because of a RAPI-related error return the default general failure error value defined for their Win32 based counterpart. To distinguish between errors which occur within RAPI from an error reported by the call, two functions are provided. PegGetLastError works identically to GetLastError and returns errors associated with the function (such as invalid parameters). GetRapiError provides a means of reporting failures within RAPI itself, the most important being the an unexpected termination of the link between the PC and the HPC.
