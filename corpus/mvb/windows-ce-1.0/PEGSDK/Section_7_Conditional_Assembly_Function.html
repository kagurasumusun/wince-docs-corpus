The conditional assembly function provides the following assembly operations:

· Selects whether or not to assemble a specified part of a source program according to the specified condition

· Iteratively assembles a specified part of a source program

7.1.1 Preprocessor variables

Preprocessor variables are used to write assembly conditions. Preprocessor variables are of either integer or character type.

Integer preprocessor variables: Integer preprocessor variables are defined by the .ASSIGNA directive and can be redefined. When referencing integer preprocessor variables, insert a backslash (\) and an ampersand (&) in front of them.

Example:

FLAG:	.ASSIGNA 1

.AIF \&FLAG == 1 ; MOV R0,R1 is assembled

MOV R0,R1 ; when FLAG is 1.

.AENDI

Character preprocessor variables: Character preprocessor variables are defined by the .ASSIGNC directive and can be redefined. When referencing character preprocessor variables, insert a backslash (\) and an ampersand (&) in front of them.

Example:

FLAG:	.ASSIGNC "ON"

.AIF \&FLAG == "ON" ; MOV R0,R1 is assembled

MOV R0,R1 ; when FLAG is "ON".

.AENDI

7.1.2 Conditional Assembly

The conditional assembly function determines whether or not to assemble a specified part of a source program according to the specified condition.

Example:

.AIF	<condition1>

<Statements to be assembled when condition1 is satisfied>

.AELSIF <condition2>

<Statements to be assembled when condition1 is not satisfied, but condition2 is satisfied>*

.AELSE

<Statements to be assembled when neither condition1 nor condition2 is satisfied>*

.AENDI

Note: These parts can be omitted from the coding.

Example:

.AIF	\&FLAG == "ON"

MOV R0,R10 ; These statements

MOV R1,R11 ; will be assembled

MOV R2,R12 ; when FLAG is "ON".

.AELSIF \&FLAG == "OFF"

MOV R10,R0 ; These statements

MOV R11,R1 ; will be assembled

MOV R12,R2 ; when FLAG is "OFF".

.AELSE

; issue error if FLAG has unexpected value

.ERROR "FLAG is ""\&FLAG""; expecting ""ON"" or ""OFF""."

.AENDI

7.1.3 Iterated Expansion

A part of a source program can be iteratively assembled the specified number of times.

Example:

.AREPEAT <count>

<Statement to be iterated>

.AENDR

Example:

; This example is a division of 64-bit data by
; 32-bit data. R1:R2 (64 bits) _ R0 (32 bits)= R2

TST R0,R0 ; (32 bits): Unsigned Zero divisor check

BT zero_div

CMP/HS R0,R1 ; Overflow check

BT over_div

DIV0U ; Flag initialization

.AREPEAT 32

ROTCL R2 ; These statements are

DIV1 R0,R1 ; iterated 32 times.

.AENDR

ROTCL R2 ; R2= quotient

7.1.4 Conditional Iterated Expansion

A part of a source program can be iteratively assembled while the specified condition is satisfied.

A coding example is shown below.

.AWHILE <condition>

<Statements to be iterated>

.AENDW

Example:

; This example is a multiply and

; accumulate operation.

TblSiz: .ASSIGNA 50 ; TblSiz: Data Table size

MOV A_Tb11,R1 ; R1: Start address of data Table 1

MOV A_Tb12,R2 ; R2: Start address of data Table 2

CLRMAC ; Mac register initialization

.AWHILE \&TblSize > 0 ; While TblSiz is larger than 0,

MAC.W @R0+,@R1+ ; this statement is iteratively ; assembled

TblSiz: .ASSIGNA \&TblSiz-1 ; 1 is subtracted from TblSiz.

.AENDW

STS MACL,R0 ; The result is obtained in R0.

Example:

two:		.assigna	2

label1: .data.l 1

label2: .data.l \&two ; same as .data.l 2

mult: .equ 5

str: .assignc “mumble”

num: .assigna 38 + (label2 - label1) ; num = 42

.sdata \&str ; same as “mumble”

.sdata “\&str = \&num” ; same as “mumble = 42”

.arepeat (mult < \&two) ? (\&num * mult) : \&num

nop

.aendr

permnum: .equ \&num

.awhile \&num > mult ne 0 ; same as \&num > mult

.data.l \&num

num: .assigna \&num - 1

.aendw

.aif “fumble” < \&str

.sdata “fumble < \&str”

.aelif mult * \&num eq 42

.sdata “5 * \&num == 42”

.aelsif label1 > label2

.sdata “label1 > label2”

.aelseif \&num == permnum || \&num == 0

.sdata “last chance”

.aelse

.sdata “giving up”

.aendi

7.2.1 .ASSIGNA: Integer Preprocessor Variable Definition
Syntax:
<preprocessor variable>[:].ASSIGNAD<value>
Statement Elements:
· Label: Enter the name of the preprocessor variable
· Operation: Enter the .ASSIGNA mnemonic in the operation field
· Operands: enter the value to be assigned to the preprocessor variable
Description: .ASSIGNA is the assembler directive that defines a value for an integer preprocessor variable. The syntax of integer preprocessor variables is the same as that for symbols. The assembler distinguishes uppercase and lowercase letters. The preprocessor variables defined with the .ASSIGNA directive can be redefined with the .ASSIGNA or .ASSIGNC directive. The values for the preprocessor variables must be absolute values. Relative values, forward references, and external references are not permitted. Arithmetic involving relative values is permitted, subject to the usual restrictions as long as the result is absolute. Defined preprocessor variables are valid from the point of specification forward in the source program.
When referencing integer preprocessor variables, insert a backslash (\) and an ampersand (&) in front of them.
\&<preprocessor variable>[']
To clearly distinguish the preprocessor variable name from the rest of the source statement, an apostrophe (') can be added. This is only necessary in certain cases when preprocessor variables are embedded in strings or macro bodies.
Coding Example:
; This example generates a general-
; purpose multiple-bit shift instruction
; which shifts bits to the right by the
; number of SHIFT.
RN: .REG R0 ; Rn is set to R0
SHIFT: .ASSIGNA 27 ; SHIFT is set to 27
.AIF \&SHIFT >= 16 ; Condition: SHIFT >= 16
SHLR16 Rn ; When the condition is satisfied, Rn is
; shifted to the right by 16 bits.
SHIFT: .ASSIGNA \&SHIFT-16 ; 16 is subtracted from SHIFT.
.AENDI
.AIF \&SHIFT >= 8 ; Condition: SHIFT >= 8
SHLR8 Rn ; When the condition is satisfied, Rn is
; shifted to the right by 8 bits.
SHIFT: .ASSIGNA \&SHIFT-8 ; 8 is subtracted from SHIFT.
.AENDI
.AIF \&SHIFT >= 4 ; Condition: SHIFT >= 4
SHLR2 Rn ; When the condition is satisfied, Rn is
SHLR2 Rn ; shifted to the right by 4 bits.
SHIFT: .ASSIGNA \&SHIFT-4 ; 4 is subtracted from SHIFT.
.AENDI
.AIF \&SHIFT >= 2 ; Condition: SHIFT >= 2
SHLR2 Rn ; When the condition is satisfied, Rn is
; shifted to the right by 2 bits.
SHIFT: .ASSIGNA \&SHIFT-2 ; 2 is subtracted from SHIFT.
.AENDI
.AIF \&SHIFT == 1 ; Condition: SHIFT = 1
SHLR Rn ; When the condition is satisfied, Rn is
; shifted to the right by 1 bit.
.AENDI
The expanded results are as follows:
SHLR16 R1 ; When the condition is satisfied, Rn is shifted to the
; right by 16 bits.
SHLR8 R1 ; When the condition is satisfied, Rn is shifted to the
; right by 8 bits.
SHLR2 R1 ; When the condition is satisfied, Rn is shifted to the
; right by 2 bits.
SHLR R1 ; When the condition is satisfied, Rn is shifted to the
; right by 1 bit.
7.2.2 .ASSIGNC: Character Preprocessor Variable Definition
Syntax:
<preprocessor variable>[:].ASSIGNCD<character string>
Statement Elements:
· Label: Enter the name of the preprocessor variable
· Operation: Enter the .ASSIGNC mnemonic in the operation field
· Operands: Enter the character string enclosed with double quotation marks (")
Description: .ASSIGNC is the assembler directive that defines a character string for an character preprocessor variable. The syntax of character preprocessor variables is the same as that for symbols. The assembler distinguishes uppercase and lowercase letters. The preprocessor variables defined with the .ASSIGNC directive can be redefined with the .ASSIGNC or .ASSIGNA directive. Character strings are specified by constant strings enclosed in double quotation marks ("), preprocessor variables, or values computed from them (using +, .SUBSTR, or other operators). Defined preprocessor variables are valid from the point of specification forward in the source program.
When referencing character preprocessor variables, insert a backslash (\) and an ampersand (&) in front of them.
\&<preprocessor variable>[']
To clearly distinguish the preprocessor variable name from the rest of the source statement, an apostrophe (') can be added. This is only necessary in certain cases when preprocessor variables are embedded in strings or macro bodies.
Coding Example:
FLAG: .ASSIGNC "ON" ; "ON" is set to FLAG.
.AIF \&FLAG == "ON" ; MOV R0,R1 is assembled
MOV R0,R1 ; when FLAG is "ON".
.AENDI
FLAG: .ASSIGNC \&FLAG ; A space (") is added to FLAG.
FLAGA: .ASSIGNC "OFF" ; "OFF" is added to FLAGA.
FLAG: .ASSIGNC "\&FLAG AND \&FLAGA"
; FLAG becomes "ON AND OFF".
7.2.3 .AIF, .AELSIF, .AELSE, and .AENDI: Conditional Assembly
Syntax:
.AIFD<condition1>
<Source statements assembled if condition1 is satisfied>
.AELSIFD<condition2>
<Source statements assembled if condition1 is not satisfied, but condition2 is satisfied>
.AELSE
<Source statements assembled if neither condition1 nor condition2 is satisfied>
.AENDI
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .AIF, .AELSIF (can be omitted), .AELSE (can be omitted), or .AENDI mnemonic in the operation field
· Operands: .AIF or .AELSIF: Enter the condition. For .AELSE and .AENDI the operand field is not used
Description: .AIF, .AELSIF, .AELSE, and .AENDI are the assembler directives that select whether or not to assemble source statements according to the condition specified. The .AELSIF and/or .AELSE directives can be omitted. Multiple .AELSIF directives are permitted with a single .AIF, to test a list of conditions in sequence. There may be at most one .AELSE per .AIF. The alternate spellings .AELIF or .AELSEIF may be used in place of .AELSIF. The condition may be any expression with an absolute numeric result value. Expressions whose result is a relative value, or which involve forward references or external references, are not permitted. If the value is non-zero, the source statements up to the following .AELSIF, .AELSE, or .AENDI are assembled, and then any remaining statements up to the .AENDI are skippd. If the value is zero, the next .AELSIF (if any) is considered. If no .AELSIF's remain, and if all of the conditions have been zero, the source statements following the .AELSE are assembled.
For compatibility with other Hitachi assemblers, the following syntax is also supported. Term 1 and term 2 may be any expression (including constants).
The condition may be specified as follows:
.AIFD<term1>D<relational operator>D<term2>
Terms are specified with numeric values or character values. Table 7.2 lists the relational operators that can be used.
Table 7.2 Relational Operators
Operator		Explanation
EQterm1 = term2
NEterm1 != term2
GTterm1 > term2
LTterm1 < term2
GEterm1 >= term2
LEterm1 <= term2
Note: Numeric values are handled as 32-bit signed integers.
Coding Example:
.AIF "\&FLAG" EQ "ON"
MOV R0,R10 ; These statements
MOV R1,R11 ; are assembled
MOV R2,R12 ; when FLAG is "ON".
.AELSE
MOV R10,R0 ; These statements
MOV R11,R1 ; are assembled
MOV R12,R2 ; when FLAG is not "ON".
.AENDI
7.2.4 .ERROR and .AERROR
Syntax:
.ERRORD[<expression>[,<expression>...]]
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .ERROR (or .AERROR) mnemonic in the operation field
· Operands: Enter zero or more expressions with string or absolute numeric result values
Description: The .ERROR directive may be used to report errors detected at assembly time by user code. If a .ERROR directive is assembled, its operands (if any) are evaluated, the results concatenated, and the result of the concatenation is used as the error message. The operands may have either string or numeric values. The alternate spelling .AERROR is also supported, for compatibility with other Hitachi assemblers.
Coding Example:
.section .text
.org 0x202 ; force the .error to be assembled
.aif $ - .text > 0x200
.error “PC overflow: is ”, $, “, expecting < ”, 0x200
.aendi
7.2.5 .AREPEAT and .AENDR: Iterated Expansion
Syntax:
.AREPEATD<count>
<Source statements iteratively assembled>
.AENDR
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .AREPEAT or .AENDR mnemonic in the operation field
· Operands:
— .AREPEAT: Enter the number of iterations
— .AENDR: The operand field is not used
Description: .AREPEAT and .AENDR are the assembler directives that assemble source statements by iteratively expanding them the specified number of times. The source statements between the .AREPEAT and .AENDR directives are iterated the number of times specified with the .AREPEAT directive. Note that the source statements are simply copied the specified number of times, and therefore, the operation does not loop at program execution. Count must be an abolute value, and cannot be a relative value, forward reference, or external reference. Nothing is expanded if a value of 0 or smaller is specified.
Coding Example:
; This example is a division of 64-bit data by
; 32-bit data. R1:R2 (64 bits) _ R0 (32 bits):
; Unsigned
TST R0,R0 ; Zero divisor check
BT zero_div
CMP/HS R0,R1 ; Overflow check
BT over_div
DIV0U ; Flag initialization
.AREPEAT 32
ROTCL R2 ; These statements are
DIV1 R0,R1 ; iterated 32 times.
.AENDR
ROTCL R2 ; R2 = quotient
7.2.6 .AWHILE and .AENDW: Conditional Iterated Expansion
Syntax:
.AWHILED<condition>
<Source statements iteratively assembled>
.AENDW
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .AWHILE or .AENDW mnemonic in the operation field
· Operands:
— .AWHILE: Enter the condition to iteratively expand source statements
— .AENDW: The operand field is not used
Description: .AWHILE, .AELSIF, and .AENDW are the assembler directives that assemble source statements by iteratively expanding them while the specified condition is satisfied.
The source statements between the .AWHILE and .AENDW directives are iterated while the condition specified with the .AWHILE directive is satisfied. Note that the source statements are simply copied iteratively, and therefore, the operation does not loop at program execution.
The condition may be any expression with an absolute numeric value. Expressions whose result is a relative value, or which involve forward references, are not permitted. If the value is non-zero, the condition is considered to be satisfied.
For compatibility with other Hitachi assemblers, the following syntax is also supported. Term 1 and term 2 may be any expression (including constants).
The condition may be specified as follows:
.AWHILED<term1>D<relational operator>D<term2>
Terms are specified with numeric values or character values. Table 7.3 lists the relational operators that can be used.
Table 7.3 Relational Operators
Operator		Explanation
EQterm1 = term2
NEterm1 != term2
GTterm1 > term2
LTterm1 < term2
GEterm1 >= term2
LEterm1 <= term2
Note: Numeric values are handled as 32-bit signed integers.
Coding Example:
; This example is a multiply and
; accumulate operation.
TblSiz: .ASSIGNA 50 ; TblSiz: Data Table size
MOV A_Tbl1,R1 ; R1: Start address of data Table 1
MOV A_Tbl2,R2 ; R2: Start address of data Table 2
CLRMAC ; Mac register initialization
.AWHILE \&TblSize GT 0 ; While TblSiz is larger than 0,
MAC.W @R0+,@R1+ ; this statement is iteratively
; assembled.
TblSiz: .ASSIGNA \&TblSiz-1 ; 1 is subtracted from TblSiz.
.AENDW
STS MAC,R0 ; The result is obtained in R0.
7.2.7 .EXITM: Expansion Termination
Syntax:
.EXITM
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .EXITM mnemonic in the operation field
· Operands: The operand field is not used
Description: .EXITM is the assembler directive that terminates an iterated expansion (.AREPEAT to .AENDR) or a conditional iterated expansion (.AWHILE to .AENDW). Either expansion is terminated when this directive appears. This directive is also used to exit from macro expansions. The location of this directive must be specified carefully when macro instructions and iterated expansion are combined. See also section 8.2, Macro Function Directives.
Coding Example:
COUNT .ASSIGNA 0 ; 0 is set to COUNT.
.AWHILE 1 ; An infinite loop (condition is always
; satisfied) is specified.
ADD R0,R1
ADD R2,R3
COUNT .ASSIGNA \&COUNT+1 ; 1 is added to COUNT.
.AIF \&COUNT EQ 2 ; Condition: COUNT = 2
.EXITM
.AENDI
.AENDW
When COUNT is updated and satisfies the condition specified with the .AIF directive, .EXITM is assembled, and .AWHILE expansion is terminated. The expansion results are as follows:
ADD R0,R1 ; When COUNT is 0
ADD R2,R3
ADD R0,R1 ; When COUNT is 1
ADD R2,R3
After this, COUNT becomes 2 and expansion is terminated.
7.2.8 .ALIMIT: Limit .AWHILE Expansion
Syntax:
.ALIMITD<maximum count>
Statement Elements:
· Label: The label field is not used
· Operation: Enter the .EXITM mnemonic in the operation field
· Operands: Enter the maximum number of times to expand .AWHILE statements
Description: The .ALIMIT directive specifies the upper limit value for expansion of the .AWHILE directive in the preprocessor. During expansion of the .AWHILE directive, if the statement expansion count exceeds the upper limit value specified by this directive, a warning message is output and the expansion is terminated. If this directive is not specified, the upper limit value is 65535.
Coding Example:
FLG .ASSIGNA 0
.ALIMIT 20
.AWHILE \&FLG eq 0
NOP
.AENDW
