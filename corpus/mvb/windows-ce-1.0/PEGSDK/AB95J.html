Load

The main entry point to download an application from the desktop to the Handheld PC.

LOADERROR Load(
HWNDhwndParent,// parent window handle, used for displaying the progress bar
LPSTRlpszCmdLine// Pointer to the buffer containing string
);
Parameters
hwndParent
The parent window handle, used for displaying the progress bar.
lpszCmdLine
Pointer to the buffer containing the command-line string of arguments to be parsed:
cpu_type application_name install_directory total_bytes_to_copy
user_name user_company load_file
The command-line arguments must separated from one another by a space character. All of the items except total_bytes_to_copy should be enclosed in double quotes. Following is a description of the command-line arguments.
Argument		Description
cpu_typeSpecifies the type of CPU on the device. This information can be obtained by calling the Load_PegCpuType function. Currently “MIPS” and “SH3” are only supported CPU types.
application_nameSpecifies a unique name for the application. This information is used to create a key in the Windows CE registry for storing information about the application.
install_directorySpecifies the directory on the device where the application will be stored. Directory names must begin with a backslash (\).
total_bytes_to_copySpecifies the total number of bytes to be copied to the device. The application installer uses this number to set the range of the progress bar displayed during the load process.
user_nameSpecifies the name of the person using the device. Currently, this argument is unused and can be an empty string, (“”).
user_companySpecifies the name of the organization where the person using the device works. Currently, this argument is unused and can be an empty string, (“”).
load_file
Specifies the path and name of the file containing the list of application installation statements to be executed during the load procedure.
Return Value
This function returns one of the following error codes.
Error Code		Description
LOAD_SUCCESSLoad process completed successfully.
LOAD_OUTOFSTORAGEOut of memory on the Handheld PC.
LOAD_CANCELLEDBYUSERLoad canceled by the user.
LOAD_INVALID_PARAMETERInvalid command line parameter.
LOAD_FAILEDGeneric load failure.
LOAD_FAILEDCANTCLEANUPLoad failure, clean-up cannot be performed on the Handheld PC.
LOAD_DISCONNECTEDCommunications disconnected.
LOAD_CANT_CREATE_DIRCannot create the destination directory.
LOAD_REG_ERRORCannot create the registry entry
LOAD_ERRORUnknown error
Remarks
This function requires a prior successful call to the Load_Init function.
This function is exported by Ppcload.dll, which runs on the desktop PC—it is intended to be called from a setup program.
When this function is used to load .exe or .dll files, the file being loaded from the desktop PC must have the CPU type added to the file name as an extension. For example, if the cpu_type argument is “MIPS” and the application_name argument is “MyApp.exe”, the file being loaded should be named MyApp.exe.MIPS on the desktop PC. The CPU type should only be appended to .exe and .dll files, the Load function will look for all other file types without the CPU type extension.
The file name specified by the application_name argument must match the file name specified by the load_file argument. For example, if the file specified by the application_name argument is “MyFile.exe” the file specified by the load_file argument should be “MyFile.load”.
