Issues

At the time of this writing there are several open issues. These are related to optimizations under consideration and aspects of the hardware or software environment that are not yet fully understood.

The open issues are:

1. In this specification the instruction sequence which must be used to establish the frame pointer is rigidly fixed due to requirements of the Virtual Unwinder. Several alternatives to this sequence are under consideration to allow compilers and assembler language writers additional latitude in optimizing the prolog sequence.

2. If instruction scheduling is to be made available via the assembler, then special pseudo-operations will be needed to limit code motion across prolog, epilog, and user defined exception scope boundaries.

3. The types and uses of the instructions in the prologs and epilogs of routines must be limited to permit efficient execution of the Virtual Unwinder. But some instructions are expanded automatically by the assembler to resolve limitations on the sizes of literal values which may appear in those instructions. It may be necessary to develop additional rules concerning these expanded instructions to avoid unnecessary complications in the Virtual Unwinder.
