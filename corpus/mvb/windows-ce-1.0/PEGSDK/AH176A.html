3.1 Sections

3.1.1 Section Types by Usage

If source programs are compared to natural language writing, a section will correspond to a chapter. The section is the processing unit used when the linkage editor links object modules.

3.1.1 Section Types by Usage

Sections are classified by usage into the following types:

· Code section

· Data section

· BSS section

· Dummy section

Code Section: Executable instructions, extended instructions, and assembler directives that reserve initialized data can be written in a code section.

Example:

.SECTION	CD,CODE,ALIGN=4	; This assembler directive declares a

; code section with the name CD.

MOV.L X,R1 ; This is an executable instruction.

MOV R1,R2

.ALIGN 4

X: .DATA.L H'FFFFFFFF ; This assembler directive reserves

; initialized data.

Data Section: Assembler directives that reserve initialized data, and assembler directives that reserve uninitialized data can be written in a data section.

Example:

.SECTION	DT1,DATA,ALIGN=4	; This assembler directive declares a

; data section with the name DT1.

.DATA.W H'FF00 ; These assembler directives reserve

.DATA.B H'FF ; initialized data.

.SECTION DT2,DATA,ALIGN=4 ; This assembler directive declares a

; data section with the name DT2.

.RES.W 10 ; These assembler directives reserve

; data areas that do not have initial

.RES.B 10 ; values.

BSS section: The bss section type can be used for a section of any name. By convention, the .bss section is used for data that should be automatically initialized to zeroes when the program is loaded. The program does not need to initialize the data, and no space is wasted on zeroes in the object and executable files. In a bss type section, you may only use assembler directives that reserve uninitialized data (such as .RES, .SRES, .ALIGN, and .ORG). The data will be initialized to zero before the program begins execution.

Dummy Section: A dummy section is a hypothetical section for representing data structures. The assembler does not output dummy sections to the object module, and labels in a dummy section cannot be exported. Assembler directives that reserve uninitialized data can be written in a dummy section.

Example:

.SECTION DM,DUMMY	; This assembler directive declares a dummy

; section with the name DM.

.RES.B 1 ; This assembler does not output the section DM

A: .RES.B 1 ; to the object module.

B: .RES.B 2

It is possible to access areas in memory by using address symbols from a dummy section. Specific methods for specifying data structures are shown in figure 3.2.

Figure 3.2 Data Structure Example Using Dummy Section

Coding Example:

; in the example above,

; assume that R1 holds the starting address of area 1 and R2 holds the

; starting address of area 2.

MOV.L @(B,R1),R0 ; Moves the contents of item B in area 1 to R0.

MOV.L R0,@(B,R2) ; Moves the contents of R0 to item B in area 2.

Note: The following cannot be used in dummy sections:

· · Executable instructions

· Extended instructions

· Assembler directives that reserve initialized data (.DATA, .DATAB, .SDATA, .SDATAB, .SDATAC, .SDATACB .SDATAZ and .SDATAZB.)

When using a data section, be sure to keep in mind whether that section is reserved to ROM or RAM.

3.2 Absolute and Relative Values

3.2.1 Absolute Values

3.2.2 Relative Values

Absolute values are determined at assembly time. Relative values are determined by the linkage editor.

3.2.1 Absolute Values

The absolute values handled by the assembler include constants, absolute address values, and other absolute values.

Constants:

· Integer constants

· Character constants

· Symbols that have a value that is one of the above (referred to as constant symbols)

Absolute Address Values:

· The location counter referenced in a dummy section

· Symbols that have the above as a value (referred to below as absolute address symbols)

Other Absolute Values:

· Expressions whose value is determined at assembly time

3.2.2 Relative Values

The relative values handled by the assembler include relative address values, external reference values, and other relative values.

Relative Address Values:

· The location counter referenced in a relative address segment

· Symbols that have the above as a value are referred to as relative address symbols

External Reference Values: Symbols that reference another file are referred to as import symbols.

Other Relative Values: Expressions whose value is determined by the linkage editor.

3.3 Symbol Definition and Reference

3.3.1 Symbol Definition

3.3.2 Symbol Reference

3.3.1 Symbol Definition

Normal Definition: The normal method for defining a symbol consists of writing that symbol in the label field of a source statement. The value of that symbol will then be the value of the location counter at that point in the program.

Example:

.SECTION	DT,DATA	; This statement declares a section

X: .DATA.W 0x1111 ; The value of X is determined by

; the linker, and its value is the

; start address of section DT.

Y: .DATA.W 0x2222 ; The value of Y is determined by

; the linker, and its value is the

; start address of section DT, plus 2.

Definition by Assembler Directive: Symbols can be defined by using assembler directives to set an arbitrary value or a special meaning.

Example:

.SECTION	DT1,DATA,ALIGN=4		; DT1 is the section name.

; A section name is also a type of

; symbol, a symbol that expresses

; the start address of a section.

; However, the syntactic handling of

; address symbols and section names is

; different.

X: .EQU 100 ; The value of X is 100.

; X cannot be redefined.

Y: .ASSIGN 10 ; The value of Y is 10.

; Y can be redefined.

Z: .REG R1 ; Z becomes an alias of the general

; register R1.

; Z cannot be redefined.

3.4.1 Separate Assembly

Separate assembly refers to the technique of creating a source program in multiple separate source files, and finally creating a single load module by linking together those source files’ object modules (using the linkage editor).

The process of developing software often consists of repeatedly correcting and reassembling the program. In such cases, if the source program is partitioned, it will be only necessary to reassemble the source file that was changed. As a result, the time required to construct the complete program will be significantly reduced. Figure 3.5 demonstrates the potential reduction in time.

Figure 3.5 Source Program in a Single File Versus Partitioned into Several Files

The procedure involved in separate assembly consists of four steps:

Investigate methods for partitioning the program. Normally, programs are partitioned by function. Note that the memory reservation of the section must also be considered at this point.

Divide the source program into separate files and edit those files accordingly.

Assemble the individual files.

Link the individual object modules into a single load module.

3.4.2 Declaration of Export Symbols and Import Symbols

When a source program consists of multiple files, referencing a symbol defined in one file from another file is called external reference or import. When referencing a symbol externally (this declaration is called external definition or export), it is necessary to declare to the assembler that this symbol is shared between multiple files.

Export Symbol Declaration: This declaration is used to declare that the definition of the symbol is valid in other files. The .EXPORT or the .GLOBAL assembler directive is used to make this declaration.

Import Symbol Declaration: This declaration is used to declare that a symbol is defined in another file. The or the .GLOBAL assembler directive is used to make this declaration.

Declaration of Export Symbols and Import Symbols: The assembler does not support the use of .IMPORT, .EXPORT, or .GLOBAL for absolute symbols. Only relative symbols can be imported and exported. This restriction is due to limitations of the MS-COFF object format.

Example:

In this example, the symbol TABLE is defined in file A and referenced in file B.

File A:

.EXPORT  TABLE    	; Declares TABLE to be an export symbol

TABLE: .DATA.L 11,9,68 ; Defines TABLE

.DATA.L 3,17,72

File B:

.IMPORT  TABLE     	; Declares TABLE to be an import symbol

MOV #TABLE,R1 ; References TABLE (R1 = address of TABLE)

MOV.L @(8,R1),R2 ; Loads 3rd item from table (R2 = 68)

See section 5.5, Export and Import Assembler Directives.
