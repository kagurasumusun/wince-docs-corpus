Inline Assembly Language

The inline assembly language provides a capability for manually inserting SH3 assembly code in C/C++ routines, especially in situations where the compiler cannot generate equivalent code. The directives required to specify entry and exit points for a routine are not supported, so to write complete routines, the routine entry and exit generated by the C/C++ compiler must be used.

Terms

The following is a list of terms used in this document and their definitions.

__asm argument

One of the expressions (not including the statically initialized string) in an __asm

statement argument list.

__asm intrinsic

The __asm intrinsic as recognized by the C/C++ compiler as a result of inclusion

of the appropriate prototype definition.

__asm instruction stream

The list of assembler-level instructions generated as a result of processing an __asm string.

__asm label

A label defined within an __asm string.

__asm line record

A newline-terminated or zero-terminated segment in the __asm string.

__asm statement

A call to the __asm intrinsic in a C/C++ routine. The arguments passed to the intrinsic include a statically initialized string argument followed by zero or more C/C++ expressions.

__asm string

The statically initialized string argument in an __asm statement.

Learning and Using SH3 Assembly Language

This document is not intended to be a tutorial on how to program SH3 assembly code. Rather, it describes the syntax, semantics and restrictions for the inline assembly language. For a complete description of the stand-alone SH3 assembler, see the Hitachi COFF Assembler Manual.

Since it is not intended for extensive use, the inline assembly language contains a subset of the features available in the stand-alone assembler. For the features it does provide, the inline assembly language is compatible with the stand-alone assembler.

__asm Intrinsic Prototype

Inline assembly code is specified using the __asm statement, which is treated as an intrinsic call. Before an __asm call is invoked, it must first be declared as a function prototype. In C++ files, the compiler reports an error unless one of the following declarations is included before any __asm calls:

extern "C" {- void __asm(const char *, ...); }

extern "C" {- int __asm(const char *, ...); }

extern "C" {- unsigned int __asm(const char *, ...); }

For C files, the compiler does not recognize an __asm call as an intrinsic unless one of the following declarations is included before an __asm statement:

void __asm(const char *, ...);

int __asm(const char *, ...);

unsigned int __asm(const char *, ...);

Inline Assembly Language Syntax

The __asm statement is an intrinsic routine call that assembles one or more assembly-language instructions. Before using __asm, you should properly declare it as explained in the previous section.

A call to the __asm intrinsic uses the following syntax:

__asm(string[,expression]...);

In this syntax, string is a null-terminated string consisting of one or more __asm line records. Zero or more cases of expression may be included. The expressions are processed by the compiler in exactly the same way as if they were being passed to a standard routine call. The first four words that represent the expression list are stored in registers R4 through R7, and the remaining words are placed on the stack frame starting at a displacement of 16 bytes from the stack pointer.

An example of an __asm statement with a single line record is:

__asm("mov.l	@R4,R0",&var)

In the example above, the address of var is loaded into R4 by the compiler, and this register is available for use by the mov.l instruction listed in the string argument.

Note The default stack frame for a function with an inline __asm in it that has a function call is 16 bytes. This will allow for up to four arguments to be passed to the function. if you want to call one with more than four args, you must use __declspec(naked) and allocate your own arg build area.

The inline __asm function can also be used in a value context. For example:

int foo(intD) {-

return __asm(“swap.b r4, r0\n”

“swap.w r0, r4\n”

“swap.b r4, r0\n,

D)

}

This will generate the desired code and cause the value in R0 to be preserved.

Important You must pass in the value of D rather than implicitly using r4 wihtout passing it in.

Writing Multiple Assembly Instructions

Multiple assembly-language instructions may be listed in a single __asm statement by using embedded newline characters (\n) as separators within the string argument. A comment may be included on any line, and it starts with a semicolon. For example, a program that simply prints out “Hello” could be written as:

#include <stdio.h>

extern void __asm(const char *, ...);

main() {-

__asm(

"jsr @R5 ; Call printf\n"

"nop ; Don’t forget the delay slot"

,"Hello\n"

,printf

);

}

This format is recommended for readability and ease of editing. The C/C++ compiler concatentates the individual strings as long as there are no non-white separators between them.

The following is a more extensive example that shows how to access parameters from registers and local argument stack space according to the calling conventions given in [2]. Byte displacements must be specified in the index-plus-displacement addressing mode. These displacements are shifted according to the data size before being stored in the object code.

__asm(

"add R4,R5 ; add first two numbers\n"

"add R5,R6 ; add third number\n"

"add R6,R7 ; add fourth number\n"

"mov.l @(16,SP), R0 ; retrieve fifth number\n"

"add R0,R7 ; add fifth number\n"

"mov.l @(20,SP), R0 ; get address of result\n"

"mov.l R7,@R0 ; save results"

,num1

,num2

,num3

,1000

,0xFFFF

,&result

);

Although literal pool entries are not allowed in the __asm string, constants and labels may be included as __asm arguments. The compiler generates code to copy the corresponding values to parameter registers or the run-time stack (as in the case of 0xFFFF in the above example).

Branch Code in __asm Statements

The following example demonstrates how to use branch code within an __asm statement. A branch instruction may be given a fixed displacement, which is divided by 2 and inserted into the object code. Alternatively, a label may be the target of a branch. However, the label must be defined within an __asm string (not necessarily the one containing the label reference) in the current function. __asm labels are not visible outside of __asm strings. The distance from a label reference to its definition must fit within the displacement field of the corresponding branch instruction.

#include <stdio.h>

#ifdef __cplusplus

extern "C" {- void __asm(const char *, ...); }

#else

extern void __asm(const char *,...);

#endif

main() {-

// Branch example using displacements

__asm(

"sett ; set T bit\n"

"bf 6 ; branch to print FAIL if not set\n"

"jsr @R6 ; print PASS\n"

"nop ; delay slot\n"

"bra 4 ; branch using displacement\n"

"nop ; delay slot\n"

"jsr @R6 ; print PASS\n"

"nop ; delay slot\n"

,"PASS\n" // argument #1 (R4)

,"FAIL\n" // argument #2 (R5)

,printf // argument #3 (R6)

);

// Branch example using labels

__asm(

"sett ; set T bit\n"

"bf lab1 ; branch to print FAIL if not set\n"

"jsr @R5 ; print PASS\n"

"nop ; delay slot\n"

"bra lab2 ; branch using label\n"

"nop ; delay slot"

,"PASS\n"

,printf

);

__asm(

"lab1: ; isolate label"

);

__asm(

"jsr @R5 ; print FAIL\n"

"nop ; delay slot"

,"FAIL\n"

,printf

);

__asm(

"lab2:"

);

}

In the above example, the __asm label “lab1” must be isolated in its own __asm statement If the label definition is inserted at the start of the next __asm statement, the code inserted by the compiler to process arguments for that statement would not be executed.

Labels within __asm strings are treated as case-sensitive Reserved words such as register names and operation names are treated as case-insensitive.

Restrictions

· An __asm line record can be any valid assembly operation code (including operands) accepted by the stand-alone assembler In addition, an __asm line record may contain a label definition or a comment as described in the previous sections However, there are some coding restrictions:

· No directives (except for .prolog) are allowed in the __asm instruction stream The .prolog directive is only allowed if the enclosing function has the naked attribute In this case, the compiler does not generate prolog/epilog code If the prolog end is not at the function start, it must be marked within an __asm statement using this directive.

· No expansion of assembler instructions is performed Immediate values (after scaling) must fit in the associated object code field for the instruction.

· No assembler macro definitions or references are allowed.

· Literal pool entries are not allowed in the __asm instruction stream Therefore, using the PC-relative addressing mode for memory references is not recommended.

· No reference to a symbol defined outside of the __asm strings for a routine is allowed in an __asm instruction stream.

· Registers R0 through R3 are available as temporary registers Registers R4 through R7 hold __asm argument values according to the standard calling conventions on entry to an __asm statement Otherwise, they may be used as temporary registers Permanent registers R8 through R14 are not saved and restored by the compiler if they are modified in an __asm statement.

· The default stack frame for a function with an inline __asm in it that has a function call is 16 bytes. This will allow for up to four arguments to be passed to the function. if you want to call one with more than four args, you must use __declspec(naked) and allocate your own arg build area.

· Do not attempt to allow data to flow implicitly between inline __asm calls using SH-3 registers, because global register allocation is performed around the calls. Instead, return the values from the inline __asm and assign these to temps.

Example

This section provides a detailed example of how to use the inline assembly language to specify code for a naked routine The compiler does not generate any prolog or epilog code so this code must be specified within __asm statements Note the use of the .prolog directive to mark the end of the prolog code in case a stack traceback walks through this routine during debugging.

#include <stdio.h>

void __asm(const char *, ...);

_muls();

_adds();

// Compute (a * (X * X)) + (b * X) + c in single precision

// floating point and return the result

__declspec(naked) float quadratic(float X, float a, float b, float c) {-

__asm(

"sts.l PR,@-SP ; save return address on stack\n"

"mov.l R4,@(4,SP) ; save X on stack\n"

"mov.l R5,@(8,SP) ; save a on stack\n"

"mov.l R6,@(12,SP) ; save b on stack\n"

"mov.l R7,@(16,SP) ; save c on stack\n"

"add #-12,SP ; allocate local stack frame\n"

".prolog ; add a prolog marker\n"

);

__asm(

"mov.l R4,@(4,SP) ; save address of multiply routine\n"

"mov.l R5,@(8,SP) ; save address of add routine\n"

"mov R4,R5 ; set up call to multiply routine\n"

"mov.l @(16,SP),R4 ; get X\n"

"jsr @R5 ; compute a * X\n"

"mov.l @(20,SP),R5 ; delay slot - get a\n"

"mov R0,R4 ; get a * X\n"

"mov.l @(8,SP),R0 ; get address of add routine\n"

"jsr @R0 ; compute a * X + b\n"

"mov.l @(24,SP),R5 ; delay slot - get b\n"

"mov R0,R4 ; get a * X + b\n"

"mov.l @(4,SP),R0 ; get address of mult routine\n"

"jsr @R0 ; compute (a * X + b) * X\n"

"mov.l @(16,SP),R5 ; delay slot - get X\n"

"mov R0,R4 ; get (a * X + b) * X\n"

"mov.l @(8,SP),R0 ; get address of add routine\n"

"jsr @R0 ; compute ((a * X + b) * X) + c\n"

"mov.l @(28,SP),R5 ; delay slot - get c\n"

"mov.l R0,@(0,SP) ; save result on stack\n"

,_muls

,_adds

);

__asm(

"mov.l @(0,SP),R0 ; recover result\n"

"mov SP, R2 ; save SP\n"

"add #12, R2 ; R2 points to RSA base\n"

"lds.l @R2+,PR ; pop return address from stack\n"

"rts ; return\n"

"mov R2, SP ; delay slot - restore stack pointer"

);

}

In the example above, intrinsics _muls and _adds are used to perform single-precision floating-point multiply and add, respectively The compiler may use hidden intrinsics to generate code, especially in the case of floating point and 64-bit integer data types If references to such intrinsics are made within __asm statements, it is necessary to include prototype definitions for those intrinsics.
