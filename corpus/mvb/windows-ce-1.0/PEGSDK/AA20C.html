System Out of Memory Dialog

Even if all applications are hibernated, Windows CE may still run critically low on memory. If the system is very close to failing a memory allocation call, the operating system automatically puts up a critical low memory handler dialog box. This dialog box is a special, "system modal" dialog box which essentially freezes the rest of the system. This implies that socket connections may hang up, other threads will stop running, and so on.

The user is informed that memory is critically low on the device, and is forced to choose which applications should be shut down. The dialog box will look something like the following illustration.

After the dialog box is dismissed, each selected application is closed just as if the Close button was pressed. The handler gives the applications eight seconds to close. If more memory is requested after four seconds have passed, but memory is still critically low, the dialog box will reappear (see the System Low Memory Handler topic).

The important thing to keep in mind is that the success of this scheme depends on the ability of applications to shut down in response to a WM_CLOSE message without needing to allocate very much additional memory. You should make every attempt to ensure that your application does its best to make this happen. One possible approach is to cache the memory needed for a graceful shutdown. For example, a Do you want to save your document dialog box could be hidden and then simply made visible when you need to close.
