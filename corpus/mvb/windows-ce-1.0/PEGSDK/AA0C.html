Memory Management

Introduction

Although Windows provides developers with a rich set of tools for producing complex graphically oriented applications, the applications often require substantial amounts of RAM. A Handheld PC (HPC) will have much less memory available than a normal desktop PC, and will probably require some changes in how you program in order to write successful applications.

An HPC must have at least 2 MB of RAM available, although some manufacturers may choose to provide more (probably not more than 4 MB total). Not only is this much less memory than most desktop PCs, it must serve a wider range of purposes.

A significant portion of this memory will be taken up by the operating system kernel and related RAM-resident applications. In addition, an HPC has no mass storage device. While bundled applications such as Pocket Word will reside in ROM when not in use, all other applications as well as all data must be stored in RAM.

Your application must be able to run in what memory is not being used for these purposes. Unless you are willing to restrict your potential market to those devices with more memory than the minimum, you should design your application to fit into the 2 MB limit. One problem you will face is that the actual amount of memory you will have to work with will depend not only on the Windows CE operating system and the amount of RAM on the device, but also on what programs and data your user decides to install at any given time.

In general, there are a number of things you can do to use the available memory efficiently. Often, you can reduce memory requirements by accepting lower speed. Since most users will not be expecting a PDA to be as fast as their desktop computer, this may represent an acceptable compromise. You may also be able to use storage more efficiently than is commonly done with desktop PC programs.

This chapter describes the various memory management options available to applications written for Windows CE, and explains the tradeoffs involved in using each of them. It explains mechanisms in the Windows CE operating system that handle low memory conditions. It also includes a set of hints and tips for writing memory-efficient applications.
