RegisterDebugZones

Register debug zones for a module.

BOOL RegisterDebugZones(// dbgapi.h
HANDLE hMod,
LPDBGPARAM lpdbgParam
);
Parameters
hMod
This is NULL if the caller is registering zones for the current process, and an hInstance if the caller is a DLL registering zones.
lpdbgParam
Pointer to a DBGPARAM structure that contains the zone definitions to be registered. For the DEBUGZONE macro to work correctly, the name of this structure in the caller address space should always be dpCurSettings.
Return Values
FALSE if an invalid module handle is specified.
Remarks
The structure pointer is stored in either the module database or the process structure, depending on whether hMod is NULL. If it's a module, there is some complexity because the DLL could be loaded in multiple process' address spaces. We store a zero-based unmapped pointer, and if there is an initializer, we go through all the process contexts in which it is loaded and map the pointer into each to initialize it correctly. We also make use of the fact that kernel's loaded copy of the DLL is used to initialize all future copies if any new process decides to load the DLL—so our initialization still holds good. Uses the registry functions exported by ppfs. This is one of the few uses of ppfs at run time.
Remarks
In general use the DEBUGREGISTER macro to call this function. This function will also look in the registry on the host PC to find an initializer for the zone mask if any is specified. All initializers must be under the key \HKEY_CURRENT_USER\Windows CE\Zones. The entry name should be the same as the name specified in the DBGPARAM structure. The value should be a DWORD that is assigned to the ulZoneMask member of the structure.
