The Mail Transport Service

Transport Service/Mail Architecture

The purpose of a transport service DLL is to provide support functions for a mail client application, such as Inbox. Using Inbox, for example, a transport service can be connected as represented in the following figure.

The Inbox Client

The Inbox application is a client that provides connections to internet mail services, using Simple Mail Transport Protocol (SMTP) and Post Office Protocol 3 (POP3). As shown in the above figure, transport service layers can be written to allow connections to various services, using Inbox.

Inbox is a mail client that communicates with Internet Mail via a transport service that exports a defined set of Transport functions (for a list of these functions, see “The Transport Service Interface Functions” later in this chapter). Inbox calls these service functions to perform standard mail operations such connecting to, sending mail to, receiving mail from, and deleting mail from the mail service.

Inbox provides a method of maintaining a unified inbox and outbox containing messages that are stored in the message store database. Inbox interfaces with the message store via a set of exposed APIs.

Transport Service Interface

A mail transport service is a DLL that exports a set of transport service functions to a client mail application, such as Inbox. Inbox calls these services to handle the sending and receiving of messages between Inbox and a service application, using SMTP protocol (to send messages) and POP3 protocol (to receive messages). For example, Inbox uses the transport service Smtp.dll to handle messages for the SMTP/POP3 service.

Mail Message Store Interface

Inbox interfaces with the message store (part of the object store) to store and retrieve messages. The message store API is exposed through Msgstore.h (included with the SDK) and Msgstore.dll

If you chose not to use Inbox, a custom application could be written to interface directly with the message store. The application could dynamically load a transport service DLL and the message service DLL. In this scenario, the functions listed in the topic “The Transport Service Interface Functions” would not have to be implemented, since the custom application would define the required exports.

For more information about the message store interface, see the “Mail Interface” chapter.
