Driver Post Initialization Processing

After the Device Manager successfully loads a driver by calling RegisterDevice, it looks for the optional numeric value, Ioctl, in the driver's registry key. If it exists, then the Device Manager opens the newly created device and calls I/O control function using the value of Ioctl as the control code. The driver can do any post-initialization processing it needs to do, such as loading a module that uses the newly created driver. In addition, the Device Manager broadcasts a WM_DEVICECHANGE message for the new device and it signals the application notification system via the PegEventHasOccurred function, passing it the NOTIFICATION_EVENT_DEVICE_CHANGE event.
