The Device Manager Architecture

During operation, drivers interact with both the Device Manager and Card Services. Figure 1 illustrates the general relationship of a driver with respect to the Device Manager and Card Services.

The Device Manager loads the drivers and tracks the active drivers in the system. The Device Manager accesses the registry to retrieve and store the keys, subkeys, and entries it needs to identify and configure the drivers it loads and tracks.

Card Services establishes the interface between the PC Card hardware and the other software in the system. Card Services monitors the status of the PC Card and uses callback functions to notify the Device Manager and drivers of the card events.

For example, when a PC Card is installed in the system, Card Services uses a Device Manager callback function to notify it of the event. For this event, the Device Manager executes an ID and Loading routine to identify the PC card and load the proper Client driver. Similarly, when a PC Card is removed from the system, Card Services notifies the Device Manager of the removal event. The Device Manager then unloads the Client driver.
