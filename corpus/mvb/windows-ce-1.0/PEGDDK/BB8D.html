PC Card Callback Functions and Event Codes

PC Card drivers are notified of PC Card status changes through a callback function specified with the CardRegisterClient function. The PC Card event codes sent to the callback function have a “CE_” prefix and they defined in the “Event Codes” section.

The following hardware-initiated callback event codes are sent to all PC Card drivers:

Event CodeDescription
CE_BATTERY_DEADIndicates a dead battery on the PC Card.
CE_BATTERY_LOWIndicates a low battery charge on the PC Card.
CE_CARD_LOCKIndicates the mechanical card lock is closed.
CE_CARD_UNLOCKIndicates the mechanical card lock is open.
CE_CARD_READYIndicates the card has changed from a busy to ready state.
CE_CARD_INSERTIONIndicates a PC Card is inserted in the socket.
CE_CARD_REMOVALIndicates a PC Card is removed from the socket.
CE_WRITE_PROTECTIndicates a PC Card’s write-protect status has changed.
The following software-initiated callback event codes are sent to all PC Card drivers:
Event Code		Description
CE_EXCLUSIVE_REQUESTResults when a driver requests exclusive access to a PC Card with CardRequestExclusive.
CE_RESET_REQUESTResults when a driver resets a PC Card with CardResetFunction.
CE_RESET_PHYSICALIndicates a hardware reset is about to occur to a specific socket.
CE_CARD_RESETIndicates a hardware reset occurred in a specific socket.
CE_CARD_INSERTIONIndicates a PC Card is inserted in the socket.
CE_CARD_REMOVALIndicates a PC Card is removed from the socket.
The following software-initiated callback event codes are sent only to the requesting PC Card driver.
Event Code		Description
CE_EXCLUSIVE_COMPLETEIndicates the result from calling CardRequestExclusive.
CE_RESET_COMPLETEIndicates a hardware reset occurred from calling CardResetFunction.
CE_REGISTRATION_COMPLETESpecifies CardRegisterClient has finished registering the driver.
Some callbacks occur in multi-event sequences. For example, when a driver calls CardRegisterClient, the callback receives a CE_CARD_INSERTION callback event code for each function on the inserted card. After the callback receives the final CE_CARD_INSERTION callback event code, it receives a CE_REGISTRATION_COMPLETE callback event code.
When a driver calls CardRequestExclusive, it also geneates a multi-event sequence. In this case, the CE_EXCLUSIVE_REQUEST callback event code is sent to all PC Card drivers. If all drivers approve, then the CE_CARD_REMOVAL callback event code is sent to all drivers. Then the CE_CARD_INSERTION callback event code is sent to the requesting driver, followed by the CE_EXCLUSIVE_COMPLETE callback event code.
When a driver calls CardResetFunction, if there are no conflicts with socket ownership, then the reset is immediate. If another driver requested the configuration for this card or owns exclusive access, then CERR_IN_USE is returned.
