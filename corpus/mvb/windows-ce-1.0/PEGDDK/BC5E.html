About the Cardtest Source Files

The Cardtest.c source file contains the following important functions for working with the operating system:

· DllEntry—an entry-point function for the DLL

· DetectionFunction—a card detection function

· PTD_*—the stream interface entry-point functions (PTD is used as the prefix for the stream interface functions)

· StatusCallback—status callback function

The Cardtest.h header file contains definitions for three I/O control codes—memory, attribute, and tuple—that define the type of operation to perform on the inserted PC Card. This header file includes the Windows I/O control codes header file, Winioctl.h. The three I/O control codes in this header file are defined using the system-supplied CTL_CODE macro.

The Cardtest DllEntry DLL Entry Function

The Device Manager uses the DllEntry entry function to load and unload the driver DLL. When the driver is loaded, this function can initialize global variables. When the driver is unloaded, this function can call functions that enable a clean separation from the system.

The Cardtest StatusCallback Status Callback Function

The Cardtest StatusCallback test status callback function processes PC Card callback status events. These status callback events notify the Cardtest driver of changes in the status of the PC Card that Card Services detects. The PTD_Init function uses CardRegisterClient to register StatusCallBack.

The Cardtest PTD_Init Function

When you insert a PC Card, the Device Manager retrieves the Plug and Play ID of the card device and searches the registry. If the Device Manager does not find a match for the card’s Plug and Play ID in the registry, it next looks under the Drivers\PCMCIA\Detect key for a detection function. From information in the detection function, the Device Manager obtains the test device key, adds a new key for the test card under the Drivers\Active key, loads Cardtest.dll, and calls the PTD_Init function, passing it the address of a string containing the registry path of the added key. The PTD_Init function performs the following operations:

· Opens the passed key and gets the socket handle for the card. The socket handle is used when calling PC CARD card services functions.

· Allocates memory for a client context structure containing data members related to an instance of the inserted card. The critical section data member of this client context structure is initialized.

· Proceeds to register the status callback function by calling CardRegisterClient.

· Returns the client context handle which is the address of the client context structure.

The Cardtest PTD_Deinit Function

When you remove the test card, the operating system Device Manager calls the PTD_Deinit function. The argument passed in the PTD_Deinit function is the client context handle. This function de-registers with Card Services and frees the client context structure.

The Cardtest PTD_Open and PTD_Close Functions

The PTD_Open function uses the client context structure as the open context of the test card. Since the PTD_Close function does nothing, it always succeeds and returns a TRUE value.

The Cardtest PTD_IOControl Function

The PTD_IOControl function processes the I/O control code that a test application passes. The PTD_IOControl function processes the I/O control code by coding a switch statement. The switch statement test expression is the I/O control code type passed in the PTD_IOControl function. The label for each case of the switch statement is a constant I/O control code that defines the type of operation to perform on the inserted PC Card.

The Cardtest Detection Function

The detection function provides the Device Manager with the test card device key. This function detects any card inserted in the PC Card slot and returns the registry key under Drivers\PCMCIA holding the test client driver.

Unused Stream Interface Functions

The following functions are not used by the test installable driver:

· PDM_Read

· PDM_Write

· PDM_Seek

· PDM_PowerUp

· PDM_PowerDown
