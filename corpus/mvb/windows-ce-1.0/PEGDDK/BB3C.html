Calling the Stream Interface

The xxx_Init, xxx_Deinit, xxx_PowerDown, and xxx_PowerUp functions are called directly by the Device Manager—these functions are not normally called by the application requesting driver services. When the Device Manager loads a driver, it calls the xxx_Init function and when it unloads a driver, it calls the xxx_Deinit function. When the system powers down, the Device Manager calls the xxx_PowerDown function; and when the system powers up, the Device Manager calls the xxx_PowerUp function.

The xxx_Open, xxx_Close, xxx_Read, xxx_Write, xxx_Seek, and xxx_IOControl functions are indirectly called by an application. The application uses Win32 functions to make the indirect call to the driver. Directly calling these functions is not recommended—the design of the system is such that making direct calls to the driver does not improve application performance. The following table lists the stream interface functions indirectly called by an application and the Win32 function used by an application to make the call:

Device Driver Stream FunctionAssociated Win32 Function
xxx_OpenCreateFile
xxx_CloseCloseHandle
xxx_ReadReadFile
xxx_WriteWriteFile
xxx_SeekSetFilePointer
xxx_IOControlDeviceIoControl
The following example lists a short program that exercises all of the functions in the previous table with the exception of WriteFile. For information on the Win32 functions, see the Pegasus SDK and Win32 SDK.
#include <windows.h>
typedef wchar_t WTCHAR;
INT
WINAPI
WinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance, LPWSTR lpCmdLine, INT nCmdShow) {-
HANDLE hDevice;
WTCHAR wchByte[20];
DWORD dwBytesRead;
// Indirectly invokes RAM_Open
hDevice = CreateFile(TEXT("RAM1:"), GENERIC_READ, 0, NULL, OPEN_EXISTING, 0, NULL);
if (hDevice == INVALID_HANDLE_VALUE) {-
MessageBox(0,(TEXT("Error opening SRAM device.")),
(TEXT("Read Error")), MB_ICONERROR);
return 0;
}
DEBUGMSG(1, (TEXT("RAM device opened.")));
//DeviceIoControl and SetFilePointer used for demonstation only.
//The example code only prints debug messages for RAM_IOControl and
//RAM_Seek.
//Indirectly invokes RAM_IOControl
DeviceIoControl(hDevice, 0, NULL, 0, NULL, 0, &dwBytesRead, NULL);
//Indirectly invokes RAM_Seek
SetFilePointer(hDevice, 1, NULL, FILE_BEGIN);
// Indirectly invokes RAM_Read
ReadFile(hDevice,(PBYTE)wchByte,20*sizeof(wchar_t),&dwBytesRead,NULL);
MessageBox(0,wchByte, TEXT("SRAM Card Message"), MB_OK);
DEBUGMSG(1,(TEXT("Read Test: String returned = %s\r\n"),wchByte));
DEBUGMSG(1,(TEXT("Read Test: %d bytes read.\r\n"),dwBytesRead));
// Indirectly invokes RAM_Close
CloseHandle(hDevice);
return 1;
}
Note When calling CreateFile to open a physical device (as opposed to an actual file), the syntax for the device to open is xxx#:, where xxx is the prefix of the driver (as required by the stream type driver interface), and # is the index. Index values must be a single digit (that is, 0 through 9, inclusive). Finally, the device prefix and index must be followed by a colon.
