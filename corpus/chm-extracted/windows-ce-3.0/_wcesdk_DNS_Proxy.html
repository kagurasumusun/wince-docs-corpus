DNS Proxy

Name resolution is automated in Windows CE by having the DHCP server supply the addresses of DNS servers to DHCP clients during address assignment. This scheme fails for the home network, because the DNS server resides either with an ISP or on a corporate network, and the correct DNS server address does not become known until a connection is established. Moreover, a typical home network does not have a DHCP server configured.

To deal with these characteristics of the home network, the DHCP allocator on the gateway device can give the local-area address of the gateway as the DNS server address to DHCP clients. Once the Internet connection is established, the gateway device can forward address-resolution requests to the address of the Internet DNS server obtained for the connection. This DNS proxy makes name resolution transparent from the point of view of devices on the home network.

The DNS proxy relays DNS requests to the current public network DNS server for the proxy, and replies as a DNS resolver to the client device on the home network. The DNS proxy must also keep track of the state of the public DNS requests and try the next DNS server in the configuration if the previous DNS resolution fails.

When the home network already has a DNS server configured, the DNS proxy is still useful. The existing DNS server most likely would be configured to forward Internet name-resolution requests to a DNS server with a static Internet address. This static configuration can fail when the Internet address of the DNS server changes. With automatic name resolution, the existing DNS server can be configured to forward Internet DNS requests to the local-area address of the DNS proxy, and the DNS proxy can handle the task of dynamically finding the internet DNS server addresses when the internet connection is established.

The DNS proxy performs the following functions:

  • Receives DNS inquiries and forwards them to external DNS address on the Internet.
  • Initiates demand-dial when it receives DNS inquiry but has no Internet connection.

The DNS proxy does not require any specific protocol actions. When the DNS proxy receives a DNS question message, the proxy:

  1. Selects a unique new identifier.
  2. Records a tuple that contains the original 16-bit identifier of the message, the newly selected identifier, and the endpoint from which the message originated.
  3. Writes the new identifier in the request.
  4. Transmits the question to the configured DNS server for the proxy.

When the DNS proxy receives a DNS response message, the proxy:

  1. Searches for a tuple associated with the identifier in the response message.
  2. Writes the original identifier in the response message.
  3. Transmits the response to the endpoint from which the question originated.

To enable DNS proxy

  1. Enable the DHCP Allocator as described in DHCP Allocator.
  2. Set the HKEY_LOCAL_MACHINE\Comm\ConnectionSharing\EnableDNSProxy registry key equal to a non-zero value.
  3. Set the HKEY_LOCAL_MACHINE\Comm\ConnectionSharing\PrivateInterface registry key to a list of private interfaces that you want to enable the DNS proxy on.
