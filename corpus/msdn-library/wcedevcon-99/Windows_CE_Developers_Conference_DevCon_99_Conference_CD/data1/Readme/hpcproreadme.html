Important Notes for Microsoft Windows CE, Handheld PC Edition, Version 3.0 and Microsoft Windows CE, Handheld PC Professional Edition, Version 3.0

Known Issues

The information stored in the lParam of a WM_CREATE message may not match with the values that were initially specified in the call to CreateWindow( ... ). This is because the Window NT and Window CE window managers use style bits slightly differently.

Installation

If the platform SDK has been installed as part of the Visual Basic for Windows CE (VBCE) installation, a separate reinstallation will be required in order to use the platform SDK with Visual C++ for Windows CE (VCCE). The VBCE installation does not install the headers and libraries needed for VCCE.

The H/PC Pro SDK may not be compatible with the Handheld PC SDK or the Palm-size PC SDK. Therefore, you should uninstall the original Handheld PC SDK and Palm-size PC SDK prior to installing the H/PC Pro SDK. However, the H/PC Pro SDK is compatible with both the Handheld PC Service Pack SDK and the Palm-size PC Service Pack SDK. You do not need to remove either of these SDKs prior to installing the H/PC Pro SDK.

Known Emulator Issues

In order to use platform manager for H/PC Pro emulation it is necessary to install the TCP/IP protocol stack if you choose not to install CE Services

The Windows CE Security API's are not supported under Emulation.

This version of emulation does not support printing (or print-related APIs).

Windows CE emulation uses information from Windows NT in some situations. For example, the Fontcount property in Visual Basic for Windows CE will return the same value as the Fontcount property in Visual Basic for Windows - 32 bit edition.

The Desktop Size control panel applet allows developers to change the size of their Handheld PC Emulation desktop. This functionality is intended to help the developer test how her application would look on a Handheld PC of a size other than the default provided. To run this applet, launch the control panel and double-click the Desktop Size icon. Choose the desired new size of the desktop and press OK. For the new settings to take effect, suspend and re-launch emulation.

The Object Store control panel applet allows a developer to change which object store file emulation will use. It is useful if the developer wants to save off the object store in a known state and return to it later. Note that the object store contains all emulated files, directories, registry entries, and databases. Before using this applet, copy the object store you want to save to the hpcpro\windows\ directory with the extension ".obs" (e.g. hpcpro\windows\test.obs) when Handheld PC Emulation is not running. To switch to using this new copy of the object store, launch the Object Store applet from Emulation's control panel. Either type in the name of the new object store or select the Browse button to find it. Shut down and restart emulation for your change to take effect.

While possible, it is unadvised to rename the system folders in emulation, as doing so may cause problems for the emulator.

It is recommended that you exit all applications running under emulation before suspending (i.e., shutting off) the emulator.

Emulation does not allow you to modify hardware related settings like repeat rate and power savings settings.

The Windows CE task manager is not available under emulation. Because emulated CE applications are in reality NT processes, you must utilize the NT task manager for switching between emulated applications.

Running the emulator with the same screen resolution as the desktop resolution is sub-optimal. This situation can create conflicts between the emulation taskbar and the desktop taskbar.

While you cannot set the systemwide NT cursor, you can still use the cursor APIs in emulation.

APIs That Behave Differently Under Emulation

GlobalMemoryStatus: there is no distinction between CE memory and NT memory. Therefore, GlobalMemoryStatus returns info relevant to the system as a whole.

Because Handheld PC Pro emulation uses the NT gdi, the emulator does not support 2 bit per pixel (4 color) bitmaps. Therefore, the CreateDIBSection function will not succeed in emulation if the passed-in bitmap header information includes biBitCount of 2 or biClrUsed of 4. Use a larger palette for bitmaps in Handheld PC Pro emulation.

CeRunAppAtTime is not supported for emulation.
