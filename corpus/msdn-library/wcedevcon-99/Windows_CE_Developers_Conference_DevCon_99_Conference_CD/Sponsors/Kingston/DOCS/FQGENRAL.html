Frequently Asked Questions:

(NOTE: The following FAQs represent the most common issues for the given scenario, and may not work in each and every single situation. If you are unable to resolve an issue, please call Technical Support at 1-800-435-0640.)

QStart Installation Program:

Although QStart has a Windows-like graphical interface, it is strictly a DOS-based program and will only run properly in a DOS environment. Therefore, you should not attempt to run QStart from within a DOS shell or Windows environment. For instance, in Windows 95, you must shutdown your computer and restart it in MS-DOS mode, or press <F8> during bootup so that you can get to the command prompt only. In operating systems such as Windows NT or OS2, you must boot from a DOS diskette, or extract the drivers at a DOS machine.

Link LED Not Lit on the Network Adapter:

The link light, located on the mounting bracket of your network adapter, is supported by twisted-pair cabling only. It will light up solid green once it has established a valid link to another network device. If the LED is not on, here are some things you may want to try:

* Make sure that the network card is properly seated in the motherboard slot

* Check to make sure that the cable is not disconnected from the port

* Replace the cable to see if it is faulty or not

* If you are using a hub, make sure there is a power source to the hub

* Make sure that the cable meets minimum and maximum length specifications

* If you are using a cross-over cable, check for proper pin assignments

(NOTE: You will not get a green link LED light if you are using coaxial [BNC] cabling.)

 

Cross-over and Straight-through cabling:

Twisted-pair cabling (10BASE-T) can be wired one of two ways, depending on your network configuration. The easiest way to remember which wiring scheme is right for you is to keep in mind "like devices." In other words, if you are going to connect one workstation directly to another workstation, or cascade one hub to another hub, then you need to use the cross-over configuration. For workstations connected to a concentrator, or hub, use the straight-through configuration. The pin assignments are illustrated below.

"Loader Cannot Find Public Symbol" error on 4.x Netware Servers

Q: When loading the KTC40 LAN driver on my Netware (4.x) file server, I get the following error message: "Loader Cannot Find Public Symbol". What is this error caused by and what can I do to resolve it?

A: This error message usually occurs when attempting to load older versions of NLM files (spec. MSM.NLM and ETHERTSM.NLM) on the file server. To resolve this error, you need to make sure that the fore-mentioned NLMs provided with QSTART are present in the server startup directory (i.e. C:\NWSERVER.) Depending on the type of installation you are performing, there are two ways to accomplish this. Please consider the following scenarios:

When you extract the driver(s) from QSTART, by default, the files will be copied into a directory called \NWSERVER. During the server installation, Netware will also copy files into the same directory, over-writing duplicate NLM files with older versions. When this happens, you must run QSTART (after completing the server installation), and copy over the newer NLM files again.

If you extract the driver(s) from QSTART to a directory OTHER than \NWSERVER, you must specify the entire drive and path to the NLM file(s) in the AUTOEXEC.NCF startup file (i.e...

Load C:\Directory_Name\File_Name.NLM.)

(NOTE: If you are upgrading your Netware server to Kingston’s KNE40 PCI adapter, just copy the files from QSTART to the existing \NWSERVER directory.)

 

Windows 95 Workstation on a Novell Network (Ethernet)

Q: If my Primary Network Logon indicates "Client for Netware Networks" (specified in Control Panel, Network icon), why does my computer continue to boot up with the Microsoft Windows 95 Logon?

A: Based on whether or not your network is designed to support multiple Frame Types, you may need to change the Network Frame Type Value (located in the Advanced Properties section of IPX/SPX compatible protocol) from ‘Automatic’ to the specific Ethernet Frame Type of your Netware File Server. To do this, go into the Control Panel and double-click on the Network icon. Under the configuration tab, you will see a list of network components that are currently enabled or installed on your system. From the list, highlight the IPX/SPX compatible protocol option and click on the Properties button (located just below the list of components.) In here, you will find 3 tabs. Please select the Advanced Windows tab and highlight the Frame Type property. You are now able to change the value of your Frame Type, which is set to Automatic by default, to that of your File Server (i.e. Ethernet_802.2, Ethernet 802.3, etc.)

 

Windows 95 Peer-to-Peer Network (Ethernet)

Q: In Windows 95s ‘Network Neighborhood’, I cannot see my other workstation, even though Device Manager indicates that my Network Adapters are working properly. If my network boards pass both the ‘Basic’ test and the ‘Transmit / Receive’ test in QSTART, shouldn’t I be able to find them in the Network Neighborhood? Are there any additional steps I need to take?

A: Make sure that the resource settings in QSTART are in sync with those specified in Windows 95s Device Manager (Control Panel, System icon.) Even if there are no error messages upon boot-up, and Device Manager indicates that there are no conflicts, you still need to make sure that the IO and IRQ settings in QSTART match Device Manager (NOTE: To run QSTART successfully, make sure that you Shutdown Windows 95 and then Restart in MS-DOS mode.)

A: If you go into the Control Panel, Network icon, make sure that you have ‘File and Printer Sharing for Microsoft Networks’ installed in the list of network components. If you do not have this component listed, just click on the ‘Add’ button and choose ‘Service’. Under Microsoft you will find "File and Printer Sharing for Microsoft Networks"; since the option is highlighted by default, just click on the ‘OK’ button and restart you computer. The option should now appear in the network listbox.

 

KNE20xxLC Adapter in Windows 95

Q: As Windows 95 boots up, I get an error message that says my NE2000 compatible adapter is not working properly, and that I may need to set it up again. Even after changing the settings in Device Manager, I get the same message. What can I do to resolve this error?

A: This error usually indicates that the resource settings in QSTART are not in sync with those specified in Windows 95s Device Manager. This means that the IO and IRQ settings in QSTART (default IO=300, IRQ=03) need to be changed to match the values specified in Device Manager. Keep in mind that QSTART should only be run in DOS mode (i.e. you need to shutdown Windows 95 and restart your computer in MS-DOS mode.)

(NOTE: For models KNE20xx+, you will be using AUTOSET in place of QSTART.)

Windows 95 Network Neighborhood

Q: In Network Neighborhood, I am unable to browse the network. However, other workstations (on the network) are able to see my machine. I have checked the network identification for proper computer and workgroup names and everything looks fine. In fact, QStart passes the "Transmit and Receive" test successfully, so I know that the cable is good. Any suggestions?

A: It appears that all workstations, except for yours, have proper networking capabilities. This issue is very common among end-users who wish to be on the network without putting in a password. This is possible by leaving the password field blank; however, you must click on the OK button, and not the Cancel button. Otherwise, you are "canceling" the networking capabilities of your workstation.

 

NE2000 Compatible driver in Windows for Workgroups

Q: After setting up my network card in Windows for Workgroups, I have been unable to get into Windows. After typing WIN at the DOS prompt, I get the Windows logo, but then my machine locks up (it hangs at the logo.) Do you know what I can do to resolve this problem?

A: This type of problem usually occurs when using the NDIS3 driver in Network Setup. The easiest way to resolve this error is to change the driver type in Windows for Workgroups from "Real Mode and Enhanced" (NDIS3) to "Real Mode NDIS Driver" (NDIS2) in Network Setup. To do this, go into Network Setup, click on the ‘Drivers’ button, and select ‘Setup.’ At the bottom of the next window, you will see a section called Driver Type. Click on the down arrow to see the list of available options, and select the appropriate driver.

*** To start Windows without the network, you may type WIN /N at the DOS prompt.

(NOTE: If you are using the driver(s) from Kingston’s diskette(s), you will need to change the driver completely by removing the NDIS3 driver from Network Setup and replacing it with the NE2000 compatible driver.)

 

Driver IFSHLP.SYS not loaded

Q: After the NET START command executes in my autoexec.bat file, I receive an error message that indicates a problem with my network. It says that the IFSHLP.SYS driver was not loaded. Can you help?

A: This is actually a very simple problem to fix. It requires that you add the following line to your CONFIG.SYS file:

DEVICE=C:\WINDOWS\IFSHLP.SYS

(NOTE: You must reboot your computer for this change to take effect.)
