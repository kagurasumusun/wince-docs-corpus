Recommended Installation Procedure

To Build for Emulation Only:

To ensure proper functionality of emulation you need to run Windows NT 4.0. Emulation on Windows 95/98 is not supported.

Install Microsoft Visual C/C++ 6.0, another C/C++ compiler, or Visual Basic 6.0.

Install the Windows CE Platform SDK (P/PC Edition 1.2).

These installation instructions create an environment in which Palm-size PC samples can be built using NMAKE from the command line for Visual C++ 6.0. Projects are automatically built and run to emulation in Visual Basic 6.0 using the run command.

To Build for Both Emulation and the Device

To ensure proper functionality of emulation you need to run Windows NT 4.0. Emulation on Windows 95/98 is not supported.

Install Microsoft Visual C/C++ 6.0, another C/C++ compiler, or Visual Basic 6.0.

Install the Windows CE Toolkit for Visual C/C++ 6.0 or Visual Basic 6.0.

Install the Windows CE Platform SDK (P/PC Edition 1.2)

Install Windows CE Services 2.2

The Windows CE Platform SDK (P/PC Edition 1.2) is designed to provide tools for building applications for Palm-size PC devices. This release includes emulation support for the Palm-size PC. The Windows CE Platform SDK (P/PC Edition 1.2) does not include the cross-compilers needed for developing binaries that run on Palm-size PC devices. These compilers are included in the Windows CE Toolkit for Visual C/C++ 6.0 or Visual Basic 6.0 available from Microsoft, or in a C/C++ development environment that supports Windows CE.

The Windows CE Platform SDK allows you to uninstall the development kit. However, because the kit is delivered in updates, the uninstall will remove all the components present. Any component can be added back by reinstalling it.

Desktop Emulation Environment

The Windows CE emulation environment requires the following:

Microsoft VC/C++ 6.0 (or equivalent) compiler, linker, and related desktop build tools.

Windows NT 4.0 or greater.

Although you can install the Windows CE Toolkits on Windows 95/98, Windows CE emulation is not supported on Windows 95/98.

The Palm-size PC emulation environment allows you to build and test Windows CE applications on your Windows NT workstation as if you were running the applications on a Palm-size PC device. This facilitates application development. The environment consists of an emulated shell and object store. The object store is contained in a file on your hard disk called Palm_Size_PC.obs. The object store resides in \Windows CE Tools\WCE211\MS Palm Size PC\Emulation\Palm211. The SDK setup creates this directory for you. The object store is managed by FileSys.exe. The object store contains the registry, databases, and files. The tree structure is identical to the object store on a Palm-size PC device. All semantics are the same. For example, the root is \ and there is no concept of a current directory.

Palm-size PC emulation is a well-behaved Windows NT desktop application. It must have the ability to start and stop at the user's convenience. This conflicts with the nature of a well-behaved Palm-size PC application: Palm-size PC applications cannot be terminated by the user. Thus, some Palm-size PC applications may not respond appropriately to termination of the emulation environment. If an application fails to exit correctly, the emulation will display a dialog to that effect and provide the user with a means to forcibly exit the application.

For emulation, Palm-size PC utilizes Shell32.exe as the shell. This is accessible from the Start menu via Start\Programs\Windows CE Platform SDK (Palm-Size PC 1.2)\Emulation Environment for the Palm-size PC 1.2. The emulated shell and CoreDLL.dll create the look and feel of Palm-size PC devices. They contain most of the functionality of Palm-size PC devices. Running multiple emulation shells at the same time is not supported. FileSys.exe can be launched directly or indirectly. To launch it indirectly, launch the shell executable Shell32.exe. Shell32.exe will detect if FileSys.exe is running and, if not, start it for you. FileSys.exe runs as a background task, so it does not appear in a normal window. You may be able to view FileSys.exe in the Task Manager. If the registry debug value is set to console, FileSys.exe will show up in a debug console window. FileSys.exe will run until the last emulation application exits.

The emulated shell executable can also be started directly or indirectly. The emulated shell runs in a fixed window that cannot be moved or minimized. To start the emulated shell indirectly, launch an application built for emulation (see below for building for emulation). This includes any application that links to CoreDLL.lib(dll). CoreDLL.dll will detect if the shell is running and, if it is not, start it for you. FileSys.exe is started for you as needed. If you want to run your application without shell emulation, give the command line switch /noshell to your application. Shell APIs will not be available to emulation applications that are started without the shell.

Though every effort was made to emulate the Palm-size PC device, emulation relies on Windows NT and therefore certain minor differences are visible.

To switch between two active applications under Palm-size PC emulation, use the Task Manager.

The Windows CE header file and library which enable ICMP Echo Request/Reply functionality are included in this development kit. The header file and library are intended for use only on the device, and not under emulation. The files needed for this functionality are ICMPAPI.h, IPEXPORT.h, and ICMPLIB.lib.

This release of the Palm-size PC emulation environment does not support Windows CE Mobile Channels.

The World Clock application not supported under emulation because it would cause the desktop time and date to change.

To turn emulation off, use the Exit Apps command on the Start menu. Exit Apps closes all emulation applications, Shell32.exe, Device.exe, and FileSys.exe.

Building for Emulation

The include environment variable must be set to \Windows CE Tools\WCE211\MS Palm Size PC\Emulation\Palm211. The environment batch file PALM_SIZE_PCENV.bat sets up the build and run-time environment for emulation applications. This batch file can be run in a console window, or you may use the Start menu item Start\Programs\Windows CE Platform SDK (Palm-size PC 1.2)\Emulation Environment for the Palm-size PC 1.2. The lib environment variable must be \Windows CE Tools\WCE211\MS Palm Size PC\lib\x86em. The Platform SDK setup does this automatically. If you are using Visual C/C++, you will need to add the Visual C/C++ Library directory to the lib environment variable, or you can run the Visual C/C++ VCVARS32.bat before compiling and linking your application.

Your application must have _WIN32_WCE_EMULATION defined before including <windows.h>. This value can be defined in the makefile, as it is with the existing samples, or it can be defined in the source code.

All DLLs built for emulation need to have the entry point set to _DllMainCRTStartup@12. This is done by passing the -entry:_DllMainCRTStartup@12 switch to the linker. Additionally, if the DLL has a main function, it must be called DllMain.

All executables built for emulation need to have the entry point set to WinMainCRTStartup. This is done by passing the -entry:WinMainCRTStartup switch to the linker. The sample makefiles illustrate how to do this.

If your application contains an .exe and a .dll file, copy both to the object store and to the emulation directory. The Windows CE Toolkit for Visual C/C++ 6.0 does this for you.

To launch an application from the emulated shell, the application must reside in the object store.

To run for emulation, the batch file PALM_SIZE_PCENV.bat, must be run first. This file modifies the path. PALM_SIZE_PCENV.bat is run automatically when the user chooses the Start menu option Windows CE Platform SDK (Palm-size PC)>Emulation Environment for Palm-size PC. RESTENV.bat is also provided so that the previous path can be restored.

If you are using the Visual C/C++ development environment when building applications for emulation, you need to link with the following libraries:

Emulation Libraries: CoreLibc.lib, CoreDLL.lib, CommCtrl.lib

Additional Emulation Libraries (as necessary): OLE32M.lib, OLEAUTM.lib, UUID.lib, ASFORM.lib, MsgStore.lib, AddrStor.lib, HtmlView.lib, WinInetM.lib, ToolHelp.lib, ASFUUID.lib, CEShell.lib, AYGShell.lib, INKX.lib, Note_Prj.lib, RichInk.lib, WinsockM.lib, PegCards.lib

Library Notes

To Windows CE Toolkit for Visual C/C++ 6.0 Users: MSVCRTD.lib must be removed in many sample projects that ship with the Windows CE Toolkit for Visual C/C++ 6.0 to build that sample project.

RichInk.lib must be added to the Project\Settings\Link\Tab Library modules used for building for the device, and INKX.lib must be added for building for emulation. Without these two libraries, a linker error will be generated.

The libraries above that end with an M are emulation versions of the desktop libraries that have been renamed to avoid collisions with the desktop libraries.

Building Within the Windows CE Toolkit for Visual C/C++ 6.0

To build within the Windows CE Toolkit for Visual C/C++ 6.0

  1. Install Microsoft Visual C++ 6.0.
  2. Install the Windows CE Toolkit for Visual C/C++ 6.0 and the SDK for Windows CE, Handheld PC Professional Edition 3.0 if you want to build for H/PC Emulation. Windows CE Services 2.2 is highly recommended for Palm-size PC, and it works with Handheld PC and Palm-size PC devices.
  3. Install the Microsoft SDK for Windows CE, Palm-size PC Edition 1.2
  4. Start Devstudio.
  5. Create a new workspace.
  6. Select a WCE configuration:
  • Palm (only for Emulation, SH, and MIPS platform)
  1. Select Palm-size PC 1.2 from the WCE Configuration toolbar.
  2. Go to Project\Settings\Link Tab. In the edit box on the bottom, add /NODEFAULTLIB:"libc.lib".
  3. In the Objects/Library Modules box, enter all needed libraries including CoreDLL.lib, CommCtrl.lib, and CoreLibc.lib.
  • H/PC Version 2.00 (for any platform)
  1. Select H/PC ver 2.00 from the WCE Configuration toolbar.
  2. Go to Project\Settings\Link Tab and be sure the Ignore default Libraries option is unchecked.
  3. In the Objects/Library Modules box, enter all needed libraries including CoreDLL.lib and CommCtrl.lib.
  4. Insert your code files and compile or build.

NOTE: Switching between H/PC and Palm-size PC, you must repeat step 6. The setting under each OS will not automatically change or save.

Tools You Should Know About

WM_HIBER.exe is a tool included in the emulation object store for each platform. WM_HIBER allows the user to send WM_HIBERNATE messages to all applications or only chosen applications. The user can launch it from the Run dialog, by double-clicking its icon in Windows Explorer, or by calling CreateProcess(). Windows CE applications may respond to this message, which the system may send in low memory conditions. But in emulation, low memory conditions aren't encountered, and Windows NT does not send this message. WM_HIBER.exe allows you to see how your application behaves when it is sent a WM_HIBERNATE message.

Running WM_HIBER.exe places an icon in the Taskbar Tray. Double-clicking this icon brings up a dialog that allows the user to enter the window to which the WM_HIBERNATE message should be sent. Alternatively, the user can select to broadcast the message to all applications.

REGSVRCE.exe allows COM server DLLs to be registered. REGSVRCE has the following command line options:

REGSVRCE [/u] [/s] DLLName

/u - Unregister the server

/s - silent operation

WM_HIBER.exe is located in the object store. REGSVRCE.exe can be found in the <target install>\wce211\ms palm size pc\emulation\palm211\windows directory

CEREGEDIT from the menu or PREGEDIT.exe from the command line allow you to alter your device registry under emulation. This tool can be found on the menu. Press the ALT key and left click to exit CEREGEDIT.

Known Problems

The Palm-size PC's emulation environment does not support IR file transfers.

If you encounter difficulties with window ordering and navigating to your emulated application in the Palm-size PC or H/PC shell, use the buttons on the Windows NT Taskbar or ALT+TAB to navigate to the desired application.

If you exit an emulation shells and immediately attempt to restart it, the restart attempt will fail.

If the Microsoft Office Manager is running and you experience problems with emulation menus, set the Microsoft Office Manager's properties to Auto hide.

Running emulation applications from the Windows NT Explorer or FileManager is not directly supported. If you wish to do so, you must modify your system or user path environment variable from the System applet in the Control Panel. The path to the emulator window directory, typically C:\Windows CE Tools\wce211\ms palm size pc\emulation\palm211\windows, must be added to your path. Microsoft does not recommend this method due to potential conflict with other emulation environments. Use the Emulation Environment for the Palm-size PC menu item instead, and run the sample from the command line using the fully qualified name of the executable.

Because of the differences in architecture of emulation and the Palm-size PC, emulation needs to be restarted after setting a calendar entry for the reminder to be emitted.

The VK codes for Action and Exit status messages map to VK_F23 and VK_F24. Because these keys do not exist on the Windows NT keyboard, by default they do not exist under emulation. The Action and Exit keys map to ENTER and ESC. Because these are essential Palm-size PC keys, the corresponding keys should go in your code, protected by #ifdef _WIN32_WCE_EMULATION statements.

Under emulation, after a time is selected, the notebox is tapped, and the keyboard input panel is selected, a cursor fails to appear in the note area until an Windows NT click is placed in the window.

If the Microsoft Windows NT 4.0 Power Toys are installed, and Tweak UI is enabled, under emulation for the Palm-size PC 1.2, there is no way to terminate the Start menu once it is activated other than starting a program listed on the Start menu.

If the Microsoft Windows NT 4.0 Power Toys are installed, and Tweak UI is enabled, under emulation for the Palm-size PC1.2, the Start menu invokes itself when the input panel space bar is tapped.

In the Calendar, under File, New Appointment, there are no changes for the font setting after typing a string in the Edit window and changing the font settings using the Format menu.

Within the Home tab of the World Clock, an hourglass icon appears when the Cities combo box is opened with the input panel DOWN ARROW and when the combo box has the focus. The cursor cannot be moved to open the combo box to select a city because the cursor changes from a pointer to an hourglass as soon as it is over the open combo box. To avoid this, use the mouse to open the combo box. This also happens when accessing the World Clock from the Start menu.

Using the Windows NT keyboard instead of the input panel for backspacing causes the suggestion box not to work properly. The suggestion box helps alleviate typing with the input panel.

Focus may be lost in the Appointment dialog if you type a description edit control using default IM, go to the InputMethods list in an input panel button, choose the default Keyboard IM and continue to type at the same edit control or another edit control. This is caused by the differences between Windows NT and the Palm-size PC.

To rename Note Taker notes under emulation, the Properties, Rename function must be used.

When using the Note Taker application under emulation, the keyboard may not respond after you enter several characters. To avoid this, click on the Note Taker, and switch back to the keyboard and enter characters again.

When saving a file with Note Taker under emulation, always change the directory to My Documents.

When running applications under emulation, the active desktop button may become inactive. To avoid this, switch between emulation applications by using ALT+TAB.

Under emulation, the virtual keyboard may behave erratically. To avoid this, use the workstation keyboard.

When starting for the first time, the Palm size PC will display a window which prompts the user to Press Action to continue.... Under emulation, the user should press the ENTER key on the desktop keyboard.

Because the Palm-size PC does not support a mouse, the Palm-size PC does not support the functions such as SetCursorPos and GetCursorPos.

By default, the size of a Windows CE Visual Basic InputBox will exceed the size of the Palm-size PC desktop area.

Under low memory situations, you may not be able to access the input panel. To access the input panel you must free memory by closing applications on the desktop.

The input panel for the Japanese emulator exists to help design the user interface for an application. However, the input panel for the emulator may not support some characters. If you need to input characters not supported by the US keyboard input method, use the hardware keyboard on your desktop computer.

Voice Recorder application's behavior depends on sound card drivers. It may not work with some drivers or cards.

The Emulation Object store is a key component for the emulator. However, Windows NT does not directly support the object store persistent storage mechanism. Therefore, the emulated object store may become corrupted. A corrupted object store has a variety of symptoms. You can restore the object store from a backup copy of the object store. The backup copy is located in the emulation windows directory, with the name palm_size_pc_bk.obs.

NOTE: Disk space required for Platform SDK installation in the setup program does not consider backup OBS, thus the displayed amount in the setup screen is 23 MB less than actual space requirement.

If the emulator should fail to load completely when launched, or any processes of the emulator fail to completely load or unload (such as aadesk, device, filesys, shell32, and welcome), they can be terminated with NT Task Manager.

When using the Japanese version of the Microsoft Windows CE Toolkit for Visual C++, if you add a Status Bar to a WCE MFC AppWizard project containing a Basic CommandBar, a CommandBar with toolbar buttons, or an Internet Explorer ReBar, the application fails at runtime with the message "Failed to create empty document". For the Japanese Toolkit Wizard generated code to run properly, you must create a definition for the string ID_INDICATOR_CAPS.

To create a definition for the string ID_INDICATOR_CAPS

  • Insert the following code into the .rc file:

    ID_INDICATOR_CAPS    "CAP"
END

When designing a label on a form for Visual Basic, setting AutoStyle to True and BorderStyle to Fixed Single causes Windows CE to not fully display the text on the label.

When attempting to run the Generic or other sample applications under emulation, Windows CE may present a dialog stating that an old executable exists. You may not be able to run the compile samples application. To avoid this, close down and restart the emulator. The rebuild and execute the sample. This error occurs on the first run of the emulation environment only.

Under certain conditions, the WCE MFC App Wizard (DLL) generates code for your new project that is not correct. If you create a new DLL App Wizard project, the following error may show when building for the Palm-size PC 1.2:

To use Visual Basic forms in Palm-size PC 1.2 emulation, you must install the Palm-size PC 1.2 SDK after you install the Windows CE toolkit for Visual Basic 6.0. If you install the Windows CE toolkit for Visual Basic 6.0 after you install the Palm-size PC 1.2 SDK, you must uninstall and reinstall the Palm-size PC 1.2 SDK.

When running a debug build MFC application in emulation on the Japanese version of Windows NT, an assertion error in Wincore.cpp can occur if you try to change character modes by clicking on the NT host computer's IME window. You can ignore the assertion error. To avoid the assertion error, use the function keys instead of the mouse to change character modes.

Emulation Debugging Information

The Windows CE Platform SDK for the Palm-size PC 1.2 now provides a debugging window that can be turned on or off with a registry setting.

The registry key is as follows :

[HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows CE Platform SDK\Debug]

"OutputWindow"="None"

After you install the Platform SDK, OutputWindow is set to the default None. If you decide to obtain debug information, this value should be changed to Debugger or Console. Debugger directs all debug information to the active debugger—IDE debugger or WinDBG. Console directs all debug information to each individual console window of applications (including filesys, device, explorem) currently running under the emulation.

To print debugging information to this window, NKDbgPrintfW() must be called. NKDbgPrintfW() is prototyped in DBGAPI.h.

PC-Link

Windows CE Services supports one Windows CE connection at a time, either emulation or a device. If the emulation or the device is engaged in a successful PC-Link session, and a second PC-Link session is attempted from the device or emulation, then the second PC-Link session fails. A dialog is shown that states: Cannot start communications with the desktop computer. The computer is not available or busy and currently cannot accept connections. If the currently connected session is terminated and the failed connection is reattempted, it will succeed.

APIs That Behave Differently Under Emulation

Windows CE Emulation relies on underlying Windows NT functionality. Therefore applications may be able to do more in emulation than on a Windows CE device. If you use an API parameter that is not defined in Windows CE, the result may be different on the device. The following section discusses all known emulation differences.

GetOpenFileName: On the device, the hwndOwner member of the OpenFileName parameter passed to GetOpenFileName can be NULL. In emulation, however, the hwndOwner member must be set to a valid window before calling GetOpenFileName, as in the following example:

    ofn.hwndOwner=hwndMain;
    GetOpenFileName(&ofn);

When passed an invalid handle, the following Windows CE GDI functions will set the error state returned by GetLastError() to ERROR_SHARING_VIOLATION rather than the proper error state of ERROR_INVALID_HANDLE.

  • SetBkMode()
  • GetBkMode()
  • SetBkColor()
  • GetBkColor()
  • CreateBitMap()

Applications running under emulation cannot change Windows NT settings via the Get* or Set* APIs.

When using CreateBitmap() to create bitmaps with 2, 4 or 8 bits per pixel, a monochrome bitmap will always be returned.

When running in emulation, 2-bits-per-pixel bitmaps are not supported.

The coordinates from the following functions are treated differently in emulation than when running on a Windows CE device:

  • ClientToScreen()
  • ScreenToClient()
  • MoveWindow()

CreateDIBSection() cannot be used to create 2-bits-per-pixel bitmaps when running in emulation.

If the size of a buffer containing region data is smaller than required, GetRegionData indicates a failure by returning 0 instead of the number of bytes needed.

The information stored in the lParam of a WM_CREATE message may not match the values that were specified in the call to the CreateWindow function. This is because the Windows NT and Windows CE window managers use style bits differently.

If you set the display on the host machine to 65,536 colors, the dividers for menu sections and the column heading buttons may display different colors than expected.

Because emulation is based on the underlying Win32 APIs running on Windows NT, the bmWidthBytes structure used by the CreateDIBSection function may return values that are consistent with Windows NT and inconsistent with Windows CE.

The CreateDIBPatternBrushPt function may return the incorrect brush style and color.

The GetTextMetrics function may return the incorrect font height.

When programming in Visual Basic for Windows CE, a form window or input panel can disappear behind the Active Desktop. To cause the form window to reappear, press ALT+TAB. To cause the input panel to reappear, press ALT+TAB or select the keyboard icon on the task bar.

When running Visual Basic for Windows CE, a form window clicking the keyboard icon on the emulator task bar will bring the input panel back.

Debugging Control Applets in Windows CE

Control panel applets are dynamic-link libraries. To debug these files on Windows CE, you must create an .exe file that loads a particular .cpl or .dll. In the Debug function on the Project, Settings menu, the Executable for debug session and Remote executable path and file name edit boxes should contain the name of the .exe file. The Additional DLLs box should specify the .cpl or .dll.
