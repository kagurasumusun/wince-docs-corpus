Object Identifiers

Each object—whether a directory, file, database, database on a mounted file system, or database record—is associated with a unique Windows CE object identifier (CEOID). Each CEOID is unique within its own mounted database volume, but not across multiple database volumes. The system generates a CEOID for each object when it is created. CEOIDs are commonly used to access databases and their records. The following table shows where to obtain the system-generated CEOIDs for the various file system object types.

Object type
Where to obtain the CEOID
Directory or file The dwOID member of WIN32_FIND_DATAW returned by FindFirstFile or FindNextFile

The dwOID member of BY_HANDLE_FILE_INFORMATION returned by GetFileInformationByHandle
Database For any Windows CE version later than 2.0, the return value of CeCreateDatabaseEx or CeFindNextDatabaseEx.

For any Windows CE version earlier than 2.0, the return value of CeCreateDatabase or CeFindNextDatabase
Database record The return value of CeSeekDatabase, CeReadRecordPropsEx, or CeWriteRecordProps
Mounted database volume CeMountDBVolume and CeEnumDBVolume return the Windows CE Globally Unique Identifier (CEGUID) of the mounted database volume. This can then be used in conjunction with a CEOID to uniquely reference a database or record when more than one database volume is mounted.

Another use of a CEOID is to obtain information about an object.

    To obtain information about a CEOID

  1. Call the CeOidGetInfoEx function.
  2. Pass the CEOID in the CeOidGetInfoEx function’s CEOID parameter.

    The CeOidGetInfoEx function returns object data in a CEOIDINFO structure. This structure’s wObjType member contains a flag indicating the object type. The data structure that is returned depends on the object type. For example, if the object is a database record, the CEOIDINFO structure’s wObjType member contains the flag OBJTYPE_RECORD, indicating that the data for the object consists of a CERECORDINFO structure. If there is no valid object for the CEOID, the return value of CeOidGetInfoEx is FALSE.

The following code example shows how to retrieve information about an object in the object store or a mounted database volume.

CEOID        CeOid;            // Object identifier
PCEGUID        pceguid;            // GUID of the mounted volume
CEOIDINFO    CeObjectInfo;    // Structure into which to retrieve
                            //    object information 
TCHAR        szMsg[200];        // String to display with object information

// Assign to pceguid the GUID of the mounted volume
// on which the object resides.
// ...

// Assign to CeOid the OID of the object about which 
// you want to get information.
// ...

if (CeOidGetInfoEx(pceguid, CeOid, &CeObjectInfo)) 
{ 
    switch (CeObjectInfo.wObjType) 
    {
        case OBJTYPE_FILE:
            wsprintf(szMsg, TEXT("Object is a file: %s"), 
                    CeObjectInfo.infFile.szFileName); 
            break;

        case OBJTYPE_DIRECTORY: 
            wsprintf(szMsg, TEXT("Object is a directory: %s"), 
                    CeObjectInfo.infDirectory.szDirName); 
            break;

        case OBJTYPE_DATABASE: 
            wsprintf(szMsg, TEXT("Object is a database: %s"), 
                    CeObjectInfo.infDatabase.szDbaseName); 
            break;

        case OBJTYPE_RECORD:
            wsprintf(szMsg, TEXT("Object is a record"));
            break;

        case OBJTYPE_INVALID: 
            wsprintf(szMsg, TEXT("The object store does not contain a \
                    \valid object that has this object identifier."));
            break;

        default:
            wsprintf(szMsg,TEXT(“Object is of unknown OBJTYPE”));
            break;
    }
}
else
{
    // error handling...

    if (GetLastError () == ERROR_INVALID_HANDLE)
        wsprintf(szMsg, TEXT("Invalid Object ID"));
    else
        wsprintf(szMsg, TEXT("Unknown error"));
}
