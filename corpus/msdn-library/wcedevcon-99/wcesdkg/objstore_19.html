Opening and Creating Databases

Windows CE provides several functions for creating, opening, reading, and deleting databases.

    To access records or properties in a database

  1. Call the CeOpenDatabaseEx function.
  2. Pass either the database name or its CEOID to the CeOpenDatabaseEx function.

    The CeOpenDatabaseEx function returns a handle to the database.

  3. Use the handle in subsequent calls to read or modify database properties or records.
  4. Call the CloseHandle function with the database handle when you have completed the previous steps.

Use the CEDB_AUTOINCREMENT flag when calling CeOpenDatabaseEx to increase performance when reading many properties. This flag directs the system to increment the seek pointer automatically every time you access a database property with the CeReadRecordPropsEx function. The seek pointer marks the record that will be read by the next read operation.

When calling CeOpenDatabaseEx, you can specify the identifier of a property to use as the sort order for the database. The system uses the sort order to increment the seek pointer after each subsequent call to CeReadRecordPropsEx, if the CEDB_AUTOINCREMENT flag is specified. The sort order also determines the property that the CeSeekDatabase function uses to traverse the database.

To create a new database, use CeCreateDatabaseEx.

    To create a new database

  1. Call the CeCreateDatabaseEx function.
  2. Pass the CEGUID of the mounted volume on which to create the database in the CEGUID parameter.
  3. Pass the other parameters in the function’s CEDBASEINFO parameter.
  4. Specify the database name in the CEDBASEINFO structure.
  5. Optionally, specify a database type identifier in the CEDBASEINFO structure.
  6. Optionally, specify any sort order specifications in the CEDBASEINFO structure.
  7. Optionally, specify the CEDB_NOCOMPRESS flag in the CEDBASEINFO structure.

    By default, the database will be created as a compressed database. If you do not want it to be compressed, you must set this flag.

Note When you create a database on a PC Card storage device, it is usually preferable to make it noncompressed. This is because the access speed to read and write from a storage card is slower than when reading and writing in RAM, and compressing and decompressing data slows your application further. Create your database as a noncompressed database, unless you expext it to be larger than the storage card can contain if left noncompressed.

If the database grows to fill the storage card, you can call CeSetDatabaseInfoEx with CEDB_VALIDDBFLAGS and the HIWORD set to zero, and the database will compress itself. Compression can take a long time to complete, especially on large databases. 

The database type identifier is an optional, application-defined value that allows you to differentiate individual databases. For example, you can have a different type of database for an address book than for a to-do list. The type identifier allows you to group related databases for searching, record management, and enumeration of databases.

To delete a database, the application passes the database’s CEOID to CeDeleteDatabaseEx, which removes the database from its database volume.

The following code example attempts to open a database of addresses by calling the CeOpenDatabaseEx function. If the database does not exist, the code example calls the CeCreateDatabaseEx function to create a new address database with three different sort orders. After creating the database, try again to open the database. 

HANDLE OpenDatabase (
            HWND hwndNotify,        // Handle to the window to which
                                // notification messages are posted 
            PCEGUID pceguid,        // Pointer to the mounted database
                                //     volume where the database to
                                //     be opened resides
            CEOID CeOid)            // Object identifier of the database
                                //     to be opened 
{
    int index;
    DWORD dwError;                // Return value from GetLastError
    HANDLE hDataBase;            // Open handle to the address database
    CENOTIFYREQUEST *pRequest;    // CENOTIFYREQUEST structure
    CEDBASEINFO CEDBInfo;        // Structure containing 
                                //     database information 
    TCHAR szError[100];            // String to display with error message
    
    // Allocate memory for pRequest.
    pRequest = (CENOTIFYREQUEST *) LocalAlloc (LPTR, 
                                        sizeof (CENOTIFYREQUEST));

    pRequest->dwSize = sizeof (CENOTIFYREQUEST);
    pRequest->hwnd = hwndNotify;
    pRequest->hHeap = NULL;        // Let system allocate memory properly.
    pRequest->dwFlags = 0;        // Notifications are handled as they
                                //     were in Windows CE 1.0.

    hDataBase = CeOpenDatabaseEx( 
            pceguid,                // Pointer to the mounted volume
            &CeOid,                // Location for the database identifier
            TEXT("MyDBase"),        // Database name
            0,                    // Sort order; 0 indicates to ignore
            CEDB_AUTOINCREMENT,    // Automatically increase seek pointer
            pRequest);            // Pointer to a CENOTIFYREQUEST
                                //     structure
                
    if (hDataBase == INVALID_HANDLE_VALUE) 
    { 
        dwError = GetLastError();
    
        if (dwError == ERROR_NOT_ENOUGH_MEMORY)
        {
            wsprintf(szError, TEXT("Not enough memory"));
        }
        else
        {
            // Possibility of non-existing database. Create it.
        
            // Initialize structure CEDBInfo
            memset (&CEDBInfo, 0, sizeof(CEDBInfo));

            // Create the database with the following specified flags.
            // Create the database as uncompressed.
            // You can use CeSetDataBaseInfoEx to compress the Database.
            CEDBInfo.dwFlags = 
                    CEDB_VALIDNAME           // szDbaseName is valid
                    | CEDB_VALIDTYPE           // dwDbaseType is valid
                    | CEDB_VALIDDBFLAGS       // HIWORD of dwFlag is valid
                    | CEDB_VALIDSORTSPEC       // rgSortSpecs is valid
                    | CEDB_NOCOMPRESS;       // The database is
                                           //    not compressed.

            // Assign the database name as MyDBase.
            wcscpy (CEDBInfo.szDbaseName, TEXT("MyDBase"));

            // Assign the database type.
            CEDBInfo.dwDbaseType = 0;

            // Set the number of active sort orders to 4.
            // This is the maximum number allowed.
            CEDBInfo.wNumSortOrder = 4;        

            // Initialize the array of sort order descriptions.
            for (index = 0; index < CEDBInfo.wNumSortOrder; ++index)
            {
                // Sort in descending order.
                CEDBInfo.rgSortSpecs[index].dwFlags = 
                                            CEDB_SORT_DESCENDING; 

                // Assign the identifier of the properties to sort by:
                // CEDBInfo.rgSortSpecs[index].propid = ...;    
            }

            // Create database "MyDBase".
            CeOid = CeCreateDatabaseEx (pceguid, &CEDBInfo);

            if (CeOid == NULL)
            {
                wsprintf(szError, 
                        TEXT("ERROR: CeCreateDatabaseEx failed (%ld)"),
                        GetLastError());
            }
            else    // Succeeded in creating the database. Open it.
            {
                hDataBase = CeOpenDatabaseEx(pceguid, &CeOid, 
                                TEXT("MyDBase"), 0, 0, pRequest);
            }
        }
    }

    // return the database handle.
    return hDataBase;
}

The CENOTIFICATION structure must be freed after the notification has been processed. To free the structure, you must call CeFreeNotification.
