Providing Secure Communications

In addition to the capabilities provided through WinInet and Winsock for creating a secure socket connection, Windows CE supports the Microsoft Cryptographic API (CryptoAPI) and Security Support Provider Interface (SSPI) for secure communications. The following illustration shows the relationship between these elements and your applications.

Security components

The cryptographic base functions supported in Windows CE already exist as an integral part of CryptoAPI. The services provided by these functions enable you to add cryptography to your Windows CE applications without requiring extensive knowledge of cryptographic processes.

The algorithms and standards used by the CryptoAPI are implemented through cryptographic service providers (CSPs). One CSP, the Microsoft Base Cryptographic Provider 1.0, is included with Windows CE through the rsabase.dll module. The CryptoAPI functions are available through the Coredll.dll module.

SSPI provides a common interface between transport-level applications and security providers. It provides a mechanism by which a transport application can call one of several security providers and obtain an authenticated connection without knowing the details of the security protocol. Two security providers are included with Windows CE: The NT LAN Manager (NTLM) and SSL2.0, SSL3.0, and PCT 1.0 that are provided through the Schannel security service. The Schannel security service is accessed through Winsock. The SSPI functions are available through the Secur32.dll module.

For more information about the CryptoAPI and Security SPI features available for Windows CE, see Cryptography and Security Support Provider Interface.
