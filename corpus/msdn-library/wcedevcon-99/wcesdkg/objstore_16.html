Working with Windows CE Databases

A Windows CE database is a general-purpose, flexible, and structured collection of data. A Windows CE database consists of records, where each record consists of one or more properties. A property refers to a data item that consists of a property identifier, a data type identifier, and the data value. For example, an application could use a database of address records, where the properties of each record include a name, street address, city, state, zip code, and telephone number. The following table shows the database properties supported in Windows CE:

Database property
Description
CEVT_BLOB A CEBLOB structure
CEVT_FILETIME A FILETIME structure
CEVT_I2 A 16-bit signed integer
CEVT_I4 A 32-bit signed integer
CEVT_LPWSTR A null-terminated string
CEVT_UI2 A 16-bit unsigned integer
CEVT_UI4 A 32-bit unsigned integer
CEVT_BOOL A 16-bit unsigned integer introduced in Windows CE 2.1.
CEVT_R8 A 64-bit signed double value introduced in Windows CE 2.1.

Devices that run Windows CE usually ship with several installed databases and allow users and applications to create additional databases. For example, a Handheld PC (H/PC) comes with calendar and task list applications that have databases for user data.

Windows CE databases allow only one level of hierarchy. Records cannot contain other records and they cannot be shared by databases. Each record is unique, has a unique CEOID, and is present in only one database. The maximum size of a record in bytes is given by CEDB_MAXRECORDSIZE. The maximum size of a property is given by CEDB_MAXPROPDATASIZE. Both of these constants are defined in Rapi.h and Windbase.h.

Opening and closing a Windows CE database does not imply that any transactions have occurred. The database is not updated at closing, but rather is updated after each individual call.

It is not possible to lock a Windows CE database to restrict access. Thus, several applications can have open handles to the same database concurrently. However, Windows CE supports several notification messages that tell an application when another application creates, modifies, or deletes database records. The messages are sent to the specified window when you call CeOpenDatabaseEx and supply a non-null window handle.

The following table shows the notification messages that Windows CE supports.

Notification nessage
Description
DB_CEOID_CHANGED Another thread modified an object in the object store. The message supplies the CEOID.
DB_CEOID_CREATED Another thread created an object in the object store. The message supplies the CEOID.
DB_CEOID_RECORD_DELETED Another thread deleted a record. The message supplies the record’s CEOID.

Each database includes information about the database as a whole, such as its name, an optional database type identifier that you can use to group similar databases, and up to four sort keys that describe how the records in the database will be sorted.
