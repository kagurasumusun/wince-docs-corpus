Aiding the Recognition Process

HwxALCValid and HwxALCPriority enable the recognition engine to identify a correct character match more rapidly and with a greater accuracy by establishing a prerequisite set of recognition parameters. Use HwxALCValid if you know what the user-entered values for a specified input field will be. For example, if your input field is part of a mailing address, such as numbers only for a United States ZIP code, you can use HwxALCValid with its alc parameter set to ALC_NUMERIC so that only number values are compared by the recognition engine to match the user input.

If the user-entered values for a given field will not be limited to any one predictable set of alphabet codes (ALC), you can use HwxALCPriority. For the type of input expected, you can use HwxALCPriority to provide the recognition engine with a prioritized list of ALCs to use for comparison to user ink input.

When implemented in your application, multithreaded processing improves the recognition engine’s ability to communicate with the input thread, and thus, speeds up the recognition process. This is because the recognition of a single character can take several seconds when using an order-independent process. In multi-threaded processing, the thread that gathers ink input can control the thread used for recognition. Optimally, this enables the recognition engine to produce partial results for display while the user writes on the writing pad.
