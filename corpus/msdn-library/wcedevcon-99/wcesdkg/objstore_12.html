FSD Manager

The FSD Manager (FSDMGR), which is contained in Fsdmgr.dll, manages all OS interaction with installable FSDs. It creates file handles, registers volumes, installs necessary APIs, and maps application calls to the installed APIs. FSDMGR invokes these API functions when an application accesses folders and files on mounted volumes using the file system APIs.

The name of the DLL and the names of the functions it exports start with the name of the associated installable file system. For example, if the name of the file system is MyFSD, then its DLL is Myfsd.dll. Exported functions are prefaced with MyFSD_*.

Note You can name your FSD anything you want. This section uses a hypothetical FSD named MyFSD. You can use this name or choose another.

Applications accessing an installable file system use file system API functions. For example, when an application creates a directory on a device, it calls CreateDirectory. FSDMGR then invokes the function supplied in the FSD for the device.

As a basis for developing an FSD, Windows CE provides the following functions, which are called the FSDMGR services.These functions isolate the FSD from both the OS and the device drivers.

FSDMGR_RegisterVolume FSDMGR_WriteDisk
FSDMGR_GetDiskInfo FSDMGR_CreateFileHandle
FSDMGR_GetVolumeName FSDMGR_ReadDiskEx
FSDMGR_ReadDisk FSDMGR_CreateSearchHandle
FSDMGR_DeregisterVolume FSDMGR_WriteDiskEx

In addition to providing services to an FSD for accessing a disk and for registering and deregistering volumes, Fsdmgr.dll also provides entry points to create the handles to be passed back to an application’s CreateFile and FindFirstFile requests. These services are prototyped in Fsdmgr.h.
