Working with the File System

The Windows CE file system supports files stored in RAM and ROM. The file system functions available to Windows CE-based applications are those supported by the Windows CE API and the standard runtime library. This section highlights specific points concerning the Windows CE file system functions.

The following table shows some of the file-related tasks that you can perform and their associated function calls.

Task
Function
Copy an existing file to a new file CopyFile
Create a new directory CreateDirectory
Open an existing file or create a new file CreateFile
Write a file in the equivalent of append mode CreateFile
Overwrite the contents of a file CreateFile with the TRUNCATE_EXISTING flag set
Truncate or extend files SetEndOfFile
Read data from a file ReadFile
Write data to a file WriteFile

Note Windows CE does not support simultaneous read/write operations. ReadFile does not support asynchronous read operations nor does it support read operations through a socket. WriteFile does not support asynchronous write operations. Files cannot be created with the overlapped attribute set.

A ROM file is a file stored on a device as read-only memory. A device manufacturer can use ROM files to store system data and programs. The GetFileAttributes function has additional return values for files stored in ROM. The FILE_ATTRIBUTE_INROM value identifies the file as located in ROM. The FILE_ATTRIBUTE_ROMMODULE value indicates that the file is designed to be executed in place, without first being copied to RAM. The CreateFile function cannot be used to access executable ROM modules. Use the LoadLibrary and CreateProcess functions instead.
