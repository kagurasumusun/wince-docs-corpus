IOCTL_DISK_GET_STORAGEID

Important:

This code returns the current STORAGE_IDENTIFICATION for a particular storage device. Block device drivers implement this code.

Parameters

hDevice
Handle to the block device storage volume, which can be obtained by opening the FAT volume by its file system entry. For example, a PC Card storage volume could be opened using this call: 
hVolume = CreateFile(TEXT("\Storage Card\Vol:"), GENERIC_READ|GENERIC_WRITE, 0, NULL, OPEN_EXISTING, 0, NULL);
dwIoControlCode
Specifies this code.
lpInBuf
NULL.
nInBufSize
Zero.
lpOutBuf
This should be set to the address of an allocated STORAGE_IDENTIFICATION structure. The storage ID data will be placed in this buffer when the IoControl call returns.
nOutBufSize
This should be set to the size of the STORAGE_IDENTIFICATION structure plus additional memory for the IDs themselves. For ATA disk devices, the IDs consist of 20 bytes for a manufacturer ID string, plus 10 bytes for the disk's serial number.
lpBytesReturned
A pointer to a DWORD that will be set to the number of bytes written to lpOutBuf.

Remarks

If an OEM or IHV provides support in a block device driver for IOCTL_DISK_GET_STORAGEID, then the driver should return TRUE is returned on a successful operation, and FALSE if this code is not supported. If FALSE is returned then callers should call GetLastError for details. An error of ERROR_INSUFFICIENT_BUFFER indicates that lpOutBuf is too small to store all the information. The caller must allocate enough memory for the structure and the IDs. If buffer is not large enough to hold the data then the call will fail and dwSize will be set to the size of the required buffer. Whether a block device driver supports this code depends on the implementation and whether the hardware contains storage ID information.
