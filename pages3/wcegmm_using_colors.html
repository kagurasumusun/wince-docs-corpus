Using Colors

The color range available to a display device is determined primarily by the pixel depth it supports. A depth of 1 bit per pixel (bpp) allows only two values — black and white. In general, the maximum number of possible colors is equal to 2 to the power of the pixel depth. To determine the number of colors a device supports, use the GetDeviceCaps function, and specify the NUMCOLORS value.

The primary and back buffer DirectDraw surfaces have a pixel depth of 16 bpp. Texture and off-screen surfaces have a pixel depth of either 4 bpp or 8 bpp. Therefore, the primary and back buffer surfaces can hold up to 65,536 colors.

Windows CE applications pass and store colors, using parameters and variables of the COLORREF data type. Use the GetRValue, GetGValue, and GetBValue macros to extract the individual RGB components of a color value. Use the RGB macro to create a color value from individual red, green, and blue components.

If you request a color that the display device cannot generate, Windows CE approximates it with the closest color that the device can generate.

Note   If you want your application to enable dithering, it must pass the D3DRENDERSTATE_DITHERENABLE enumerated value as the first parameter to IDirect3DDevice3::SetRenderState. It must set the second parameter to TRUE to enable dithering, and FALSE to disable it. You can apply dithering to the entire scene or to none of it. You cannot dither a portion of a scene.

DIBs retain color information, either as RGB values or color palette indexes. If RGB values are used, the colors may be approximated.

No color translation is necessary for off-screen DIBs because they are already in screen format (16 bpp and 5-6-5 RGB). For other DIBs, you must perform a bit block transfer (blit) to translate the color.
