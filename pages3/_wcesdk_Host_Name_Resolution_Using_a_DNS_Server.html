Host Name Resolution Using a DNS Server

To make host name resolution scaleable and centrally manageable, IP address mappings for fully-qualified domain names (FQDNs) are stored on DNS servers. Windows CE does not support hosting a DNS server running on Windows CE. However, Windows CE queries a DNS server for name resolution if a server exists on the network. The following process outlines what happens when the DNS resolver component on a host sends a DNS query to a DNS server.

  1. The DNS resolver component formats a DNS Name Query containing the FQDN and sends it to the configured DNS server. For Windows NT, the DNS resolver forms a FQDN by appending the value of the HKEY_LOCAL_MACHINE\Comm\interface\TCPIP\Parms\DNSDomain registry entry to the name passed to the gethostbyname function. Unlike Windows NT, Windows CE first checks that the name is a valid DNS name; for example, Windows CE checks that the name is not too long and is in the form name.something. If the name is valid, Windows CE then checks the DNS server for the name that was passed to gethostbyname. If this procedure fails, Windows CE next uses the following formula to decide whether or not to append the value of the DNSDomain registry entry to the name before querying the DNS server again. 
    N > C/2

    N equals the current number of efforts to resolve the DNS name, C equals the number of retries specified in the HKEY_LOCAL_MACHINE\Comm\interface\TCPIP\Parms\ResolverRetryCount registry entry. If the above formula is true, Windows CE appends the value of the DNSDomain registry key to the name.

  2. The DNS server checks the FQDN in the DNS Name Query against locally-stored address records. If a record is found, the IP address corresponding to the requested FQDN is sent back to the client.
  3. If the FQDN is not found, the DNS server forwards the request to a DNS server that is authoritative for the FQDN.
  4. The authoritative DNS server returns the reply, containing the resolved IP address, back to the original DNS server.

    The original DNS server sends the IP address mapping information to the client.

Windows Sockets applications generally use the gethostbyname function to resolve a host name to an IP address. When looking up a name, gethostbyname performs the following operations by default:

  1. Checks the registry for a name that matches the value of the HKEY_LOCAL_MACHINE\Comm\Tcpip\Hosts\host name entry.
  2. Checks the name cache, which is stored in memory for Windows CE 3.0, unless HKEY_LOCAL_MACHINE\Comm\Afd\ResolverCheckCacheFirst is equal to zero.

    If a DNS Server is configured and the name matches the definition of a DNS name, gethostbyname queries the DNS server as outlined above. The gethostbyname function tries both the primary DNS Name Server (DNS1) and the secondary DNS Name Server (DNS2).

    If gethostbyname does not find a match and the name matches the definition of a WINS name, gethostbyname tries the NetBIOS Name Server. The gethostbyname function tries both the primary NetBIOS Name Server (WINS1) and the secondary NETBIOS Name Server (WINS2).

  3. Tries the IP subnet broadcast, if gethostbyname did not find a match in the earlier steps.
  4. Tries the name cache, if gethostbyname did not find a match in the earlier steps and if the ResolverCheckCacheFirst registry entry is equal to 0.
    Note   The gethostbyname function determines whether the name that you want to look up matches the definition of a DNS name or the definition of a WINS name. The gethostbyname function then queries only the appropriate servers, based on the type of name matched.

Some applications use the gethostbyaddr function to resolve an IP address to a host name. The gethostbyaddr function performs the following operations by default:

  1. Checks the registry for a matching name entry
  2. Queries a Domain Name Server, if one is configured
  3. Sends a NetBIOS unicast message to the device, if gethostbyaddr did not find a match in the earlier steps
    Note   Windows CE does not support dynamic DNS at this time.
    Windows NT support for host name resolution using a DNS server is slightly different. For more information on host name resolution on Windows NT, see the Windows NT documentation.
