Administering MSMQ

Windows CE implements an independent client that is not part of any domain, and all relevant administration information is stored on the device itself. Administration functions are carried out locally using the MSMQADM utility, a console-based utility that configures MSMQ. MSMQADM is script-driven, so that routine tasks can be automated.

Tasks administered through MSMQADM include:

  • Browsing local queues.
  • Purging messages.
  • Deleting individual messages.
  • Stopping and starting MSMQ service.
  • Connecting and disconnecting from the network.

MSMQADM takes its operating parameters from the command line. For example, to run MSMQADM in manual mode, type:

Msmqadm man

The following examples show three different ways to set up and start MSMQ on a new device.

Example 1

\> msmqadm register
\> msmqadm start

Example 2

\> msmqadm man
>register
>start
>exit
\>

Example 3

\> echo register > start.txt
\> echo start >> start.txt
\> echo exit >> start.txt
\> msmqadm man start.txt

The following table describes some additional MSMQADM arguments. To obtain a list of arguments while running MSMQADM, type: 

Msmqadm help
Argument Description
Console Brings up the MSMQ console (debug version).
Debug {ON, OFF} {All, API, Queue, Session, Packets, Cursors, Order, IO, File, Init, Warn, Fatal} Turns on or off specified debug zones1, 2.
Debug output {ON, OFF} {All, Console, Log, Debugger} Turns on or off specified debug output channels1, 2.
Empty queue Purges the queue.
Exit Exits manual mode.
Enum queues Displays a list of queues present on a device.
Enum messages <queue number> Enumerates messages in a specified queue.
Delete queue <queue number> Deletes a queue.
-f <filename> Output goes to specified file and cannot be used with scripting.
Logsize <number> Sets the size of MSMQ log file1.
Man<filename> Executes a script from a file.
Purge queue <queue number> Purges a queue and deletes all messages.
Start Starts the MSMQ service.
Stop Stops the MSMQ service.
Register {GUID, <QM GUID>, DIR <base directory>, FRS <name of Out-FRS server>, REGNET} Creates the MSMQ configuration in the registry.

The optional GUID specifies the GUID of the queue manager.

DIR specifies the MSMQ store directory.

FRS specifies the name of the Out-FRS server.
Register change {PORT <new port>, PINGPORT <new port>, QUOTA <new quota>, NETRETRY <timeout in seconds>, CONNECTRETRY <space-separated list of timeout in seconds>, DIR <new directory>, FRS <new Out-FRS name>} Changes the MSMQ configuration parameters in the registry1.

PORT and PINGPORT change default communication port numbers from MSMQ. Changing these values will disable the MSMQ ability to connect to other computers.

QUOTA changes default queue quota and quotas for outgoing queues.

NETRETRY sets the period for probing whether the network interface has become available.

CONNECTRETRY sets the connection schedule as discussed above.

DIR sets a new MSMQ store directory; use carefully, because this can disable certain transactional queues if the contents of the previous store are not available in the new directory.

FRS changes the name of the Out-FRS server.
Register cleanup Deletes the MSMQ registry key and store directory. All messages are lost.
Register install [NETREG] Installs MSMQ and optionally NETREG as device drivers.
Register uninstall Uninstalls the MSMQ and NETREG drivers, but does not affect the MSMQ store or registry key. The NETREG registry key is removed.
-s Silent; no output is produced. Cannot be used with scripting.
Status Provides the status of the queue manager.
Net connect Forces all queues to connect to the network.
Net disconnect Abandons all network connections.
Tidy Forces the system to perform an internal data compaction.
1 Setting takes place after MSMQ has been stopped and restarted.
2 Debug-only version.

Web-Based Utility

A Web-based application provides a user-friendly interface for MSMQ administration that uses the Web services and enables you to remotely configure MSMQ. This utility is included in the Maxall configuration; otherwise, you must have the MSMQ modules, including the msmqadm component, and the server modules, including httpd and msmqadmext components. Depending on the Web server configuration, authentication may be required to load the administration utility program. For more information about setting access permissions to the web server utility application, see Authentication in Windows CE Web Server.

This interface allows you to perform all the administration functions that are available in MSMQAdm.exe. To call the application, type http://<yourMachineName>/msmqadmin or http://<IPAddress>/msmqadmin in the browser window.

You can find the source code for this sample application in the folder %WINCEROOT%public/servers/sdk/samples/http/msmqextn. This is a sample application that you can modify to suit your needs.
